## 已修复缺陷

所有生产修复和对应回归测试均在提交 `a74f2cd`（`fix: harden AI inputs and export workflows`）中。

| 缺陷 | 根因 | 修复 |
| --- | --- | --- |
| 无路径浏览器附件无法读取 | 本地附件无条件进入旧磁盘读取分支 | 仅存在真实 `attachment.path` 时使用旧读取器，否则读取 `File.arrayBuffer()` |
| 图片 MIME 可被扩展名绕过 | 扩展名回退优先于不支持的声明图片 MIME | 对声明为 `image/*` 的不支持类型先拒绝 |
| Office 压缩包可能高倍率展开 | 只限制压缩输入大小，没有解析前展开预检 | 增加条目数和声明解压总量上限，并在三类 Office 读取前执行 |
| JSON/HTML 导出可能损坏 | 对最终字符串执行通用字节截断 | 改为结构化缩减后重新渲染，保留语法和闭合结构 |
| UI 只能导出 Markdown | 两个父组件硬编码 `md` | 新增共享下拉按钮并提供 Markdown、HTML、JSON |
| AI E2E 偶发操作错误终端/配置 | 定位器选择旧标签，语言用例依赖外部状态 | 锁定 `.session-current`，为用例创建隔离配置和本地终端 |
| ExcelJS 传递依赖包含旧版本 | ExcelJS 固定旧 `uuid`/`unzipper`，minimatch 依赖旧维护线 | 使用窄范围 overrides，并加入普通/流式 XLSX 兼容回归 |
| 本地打包冒烟提示错误 | `npm run b` 只准备运行时，不生成 `dist/win-unpacked` | 新增 `npm run package:win:dir`，并让缺失产物提示指向该命令 |

## 剩余风险与后续建议

- npm 审计仍按 `brace-expansion <=5.0.7` 的版本范围将 ExcelJS 的传递路径计为 8 个 high。当前安装的 1.1.18 和 2.1.4 源码含长度上限回补，且 ExcelJS 普通/流式读写通过，但 npm 元数据尚未识别维护分支回补；发布说明应透明保留该差异，后续优先升级到 ExcelJS 官方兼容的新依赖线。
- 严格在线字节校验没有通过，因为本轮按边界不创建“已批准发布资产”，也不把未发布的新二进制与线上旧 0.4.22 伪装为一致。正式发布时应生成 NSIS 安装包、写入批准清单、准备更新资产、执行本地校验，上传两条源后再运行 `npm run release:update-sources:verify`。
- 构建仍提示少数压缩后超过 500 kB 的分块；这不是本轮功能回归，但后续可对 AI 聊天、语言目录和主包做按路由动态加载，以降低冷启动和更新体积风险。
- 真实外部 MCP 服务、不同供应商模型和弱网/代理组合没有在本轮产生写操作式实测；现有契约和隔离测试通过，发布前可按目标用户环境补充只读兼容矩阵。
