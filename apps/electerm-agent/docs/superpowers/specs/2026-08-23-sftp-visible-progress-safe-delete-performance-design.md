# SFTP 可见进度与安全删除性能优化设计

日期：2026-08-23
状态：已获用户确认
方案：稳健定向优化

## 1. 背景与实测结论

ShellPilot v0.4.42 已具备 SFTP 上传、下载、进度坞、安全删除、快速删除、恢复记录和虚拟列表。基于真实 Electron 界面、本地 SSH/SFTP 测试服务器、32 MiB 文件和 1000 项目录的复测，日常交互响应健康，但仍有两个高影响问题：

- 上传时进度坞 DOM 在约 460.5 ms 内出现，但其边界为 `top=1073, bottom=1123`，测试窗口高度为 1098，主体信息被视口底部裁切。
- 32 MiB 安全删除准备耗时约 10.76–13.99 秒，确认后列表更新耗时约 7.47–8.98 秒。准备和执行路径会重复读取完整文件摘要，完成路径还固定等待 500 ms 后才刷新列表。

代码链路确认了上述根因：

1. `.sftp-transfer-progress-dock` 使用绝对定位，锚定在带固定高度的 `.sftp-wrap` 底部；当包装容器的顶部偏移与固定高度之和超过窗口高度时，进度坞随容器一起落到视口之外。
2. 安全删除准备阶段依次描述原文件、复制快照、描述暂存快照、再次验证最终快照，并在提交恢复清单后立即重新加载和验证快照。
3. 用户确认后，执行前再次验证恢复清单、快照和原文件；删除后又重新验证恢复清单与结果。
4. 删除完成后 `delFiles` 无条件执行 `wait(500)`，再请求远程列表。

## 2. 目标

1. 上传和下载进度坞在任意支持的窗口高度、标签栏高度和面板布局下均完整进入可见视口。
2. 保持安全删除“快照完整验证后才能确认、确认前原文件不得变化、删除后仍可恢复”的边界。
3. 在同一次确认周期内复用已经验证且绑定到当前事务的结果，消除可证明重复的完整摘要读取。
4. 安全删除等待期间持续显示当前阶段；能够取得可靠总量时显示已处理字节和百分比。
5. 删除成功后立即更新当前列表，再异步刷新远端状态，不再增加固定 500 ms 等待。
6. 保持快速删除、AI/MCP 删除策略、恢复中心和其他 SFTP 操作语义不变。

## 3. 非目标与安全边界

本轮不做以下变更：

- 不跳过快照完整性验证，不允许先删除再补快照。
- 不把安全删除改成快速删除，也不改变键盘 Delete、AI 或 MCP 的默认安全路径。
- 不信任仅由文件名或大小构成的快照；完整文件仍必须使用现有 `SHELLPILOT-SHA-256-CHAIN-V1` 摘要验证。
- 不重写 WebSocket SFTP 协议，不引入新的远端守护进程或 Shell 命令摘要实现。
- 不为了本轮优化重构全局安全事务框架、传输中心或远程列表组件。
- 不使用固定位置常量假设标签栏高度，也不以隐藏进度坞换取布局稳定。

任何缓存只在单次事务确认周期内有效，并同时绑定操作 ID、恢复绑定、快照路径和已验证描述符。操作取消、重试、连接更换、端点不匹配、清单变化或元数据变化都会使缓存失效。

## 4. 方案比较与选择

### 4.1 采用：稳健定向优化

采用视口安全锚定、确认周期验证缓存、阶段/字节进度和乐观列表更新。该方案直接覆盖实测问题，同时沿用现有 SFTP 安全事务与恢复记录。

### 4.2 未采用：仅做 CSS 和等待时间修补

只调整容器高度并移除 `wait(500)` 的改动最小，但固定高度仍会受到标签栏、缩放和窗口布局变化影响，而且无法降低安全删除中的重复完整摘要成本。

### 4.3 未采用：重写服务端复制与摘要协议

在主进程复制流中同时计算摘要并新增实时进度事件，长期可进一步减少读取次数，但需要修改 WebSocket 请求/事件协议、主进程 SFTP 复制实现和渲染进程订阅模型。本轮收益不足以覆盖其回归面，留作后续独立项目。

## 5. 进度坞设计

### 5.1 视口安全锚定

进度坞保持在当前 SFTP 工作区底部，但定位基准从可能超出窗口的容器底部改为可见视口：

- 进度组件读取所属 `.sftp-wrap` 的 `getBoundingClientRect()`。
- 水平方向使用包装容器在视口内的可见左右边界，并保留现有 10 px 内边距。
- 垂直方向以 `window.innerHeight` 为上限；当包装容器底部超出视口时，进度坞使用 8 px 视口底部间距。
- 使用 `position: fixed`，避免祖先固定高度、`overflow: hidden` 和顶部偏移再次裁切。
- 监听窗口 resize、包装容器 ResizeObserver 和当前 SFTP 面板布局变化；计算结果限制为非负有限值。
- 组件卸载时移除监听器和 observer，不保留全局副作用。

几何计算抽取为纯函数，输入容器边界、视口宽高和间距，输出 `left/right/bottom/maxWidth`。上传、下载和窄窗口共享同一计算逻辑。

### 5.2 布局与交互

- 进度坞继续显示当前文件、方向、百分比、字节、速度、任务数、展开详情和终态关闭按钮。
- `.sftp-section` 只在进度坞存在时保留底部空间，避免列表最后一行被固定浮层遮挡。
- 当工作区宽度不足时沿用现有窄窗口隐藏次要指标规则，方向、百分比和操作按钮仍保持可见。
- `role="progressbar"`、未知总量不声明 `aria-valuenow`、终态 `aria-live` 等语义保持不变。

## 6. 安全删除验证与性能设计

### 6.1 准备阶段

每个目标仍执行以下必要步骤：

1. 完整描述原文件或目录，生成包含摘要的原始描述符。
2. 复制恢复快照到事务暂存路径。
3. 完整描述暂存快照，并与原始描述符严格比较。
4. 原子重命名暂存快照到最终快照路径。
5. 读取最终快照的轻量元数据，确认路径、类型、大小、mode、uid/gid 与刚刚验证的暂存快照一致。
6. 原子提交恢复清单，并进行结构、端点、操作 ID、恢复绑定和产物路径验证。

准备函数不再在同一调用栈中对刚刚验证并原子重命名的快照执行两次额外完整摘要。成功结果写入确认周期验证缓存，并在对话框进入 `ready` 前确认缓存与恢复绑定一致。

### 6.2 执行前与执行后

用户确认后：

- 重新加载并验证恢复清单结构与恢复绑定。
- 对最终快照执行一次完整摘要验证。
- 对原文件执行一次完整描述，确认自准备阶段后未发生变化。
- 只有两项均通过才允许执行删除。

执行完成后：

- 验证原路径确实不存在。
- 读取最终快照轻量元数据并与执行前完整验证结果比较。
- 将执行前的已验证快照结果传递给同一执行调用中的验证阶段，不再立即重复完整读取同一快照。
- 后续真正执行恢复时仍沿用现有完整快照验证，缓存不能跨确认周期替代恢复前校验。

这样保留关键的完整摘要边界：准备时验证复制内容，执行前验证恢复资产与原文件，恢复前再次验证恢复资产；仅移除同一连续调用中没有中间可观察修改点的重复读取。

### 6.3 失效与失败关闭

以下任一条件出现时，验证缓存立即失效并重新完整验证或停止操作：

- 操作 ID、effectKey、endpointKey 或 recoveryBinding 不一致。
- 清单、快照路径或描述符结构变化。
- 快照轻量元数据与缓存不一致。
- 连接重建、外部取消、重试或安全删除对话框重新创建。
- 任一摘要、复制、重命名、删除或远程状态查询失败。

失败时确认按钮保持禁用，已创建的事务产物仍由现有取消/清理逻辑处理，不降级为直接删除。

## 7. 安全删除阶段与字节进度

安全删除对话框状态扩展为：

- `source-scan`：读取并摘要原文件。
- `snapshot-copy`：复制恢复快照。
- `snapshot-verify`：读取并验证快照。
- `ready`：恢复快照已验证，等待用户确认。
- `deleting`：执行删除。
- `result-verify`：确认原路径消失并绑定恢复记录。
- `failed`：显示经过清理的失败原因并允许重试。

进度数据使用 `{ phase, completedBytes, totalBytes, targetIndex, targetCount }`：

- 客户端摘要读取已有分块边界，直接按实际读取字节报告。
- 快照复制阶段在事务暂存路径存在后，以有限频率读取其大小；最多每 250 ms 一次，复制结束或取消后立即停止。
- 目录或无法取得可靠总量的阶段显示不确定进度，不伪造百分比。
- 多目标操作显示当前目标序号与总数；聚合百分比只在全部目标总量可靠时计算。
- 进度更新最多每 100 ms 发布一次，但阶段变化、失败、取消和 ready 状态立即发布。
- 对话框关闭或信号取消后不再执行轮询、状态更新或远端请求。

## 8. 列表刷新与响应

安全删除成功后不再执行固定 `wait(500)`：

1. 根据已确认成功的绝对远程路径，从当前远程列表中立即移除对应目标并清空无效选择。
2. 立即向用户显示安全删除成功与恢复可用状态。
3. 后台调用一次 `remoteList()` 校准服务端真实状态。
4. 后台刷新失败时保留乐观结果，但显示“状态校准失败，请手动刷新”的单条提示；不得重新插入未经服务器确认的数据。

快速删除保持现有独立刷新策略，不共享安全事务验证缓存。

## 9. 组件与数据流

预计修改边界：

- `src/client/components/sftp/sftp-transfer-progress-dock.jsx`：测量所属工作区并应用视口安全位置。
- `src/client/components/sftp/sftp-transfer-dock-layout.js`：纯几何计算与边界钳制。
- `src/client/components/sftp/sftp.styl`：固定进度坞、底部空间和窄窗口样式。
- `src/client/components/sftp/sftp-delete-dialog.jsx`：阶段、字节、目标序号和执行中状态。
- `src/client/components/sftp/sftp-delete-dialog-model.js`：安全删除进度归一化与文案模型。
- `src/client/components/sftp/sftp-entry.jsx`：连接对话框进度、乐观移除和后台校准。
- `src/client/components/sftp/sftp-transaction-adapter.js`：验证结果缓存、摘要进度、快照复制轮询和重复验证消除。
- `src/client/common/shellpilot-i18n-overrides.js`：新增中英文阶段与刷新失败文案。

数据流保持单向：

```text
真实 SFTP 摘要/复制/事务阶段
  -> 受限进度回调
  -> 安全删除对话框展示模型
  -> 阶段文字、字节和确定/不确定进度

文件传输真实状态
  -> 现有 fileTransfers / transferHistory
  -> 现有进度聚合模型
  -> 视口安全进度坞
```

界面不根据计时器伪造完成状态，也不把安全删除进度写入上传/下载传输历史。

## 10. 错误处理

- 容器尚未挂载或几何值无效：进度坞使用 8 px 视口底部和 10 px 水平安全边距，下一次布局测量自动修正。
- ResizeObserver 不可用：回退到窗口 resize 与首次布局测量。
- 摘要或复制失败：进入 `failed`，确认按钮保持禁用，允许用户重试或取消。
- 进度轮询中的临时 `ENOENT`：暂存文件尚未创建时忽略一次；其他错误停止轮询但不替代主复制结果。
- 执行前快照或原文件变化：停止删除并保留恢复产物，不使用缓存继续。
- 删除结果无法确认：不报告成功，沿用现有安全错误记录。
- 后台列表校准失败：只显示一次可操作提示，不撤销已经由事务确认的成功状态。

## 11. 测试策略

### 11.1 进度坞

- 纯函数验证容器完全可见、底部超出、左右裁切、窄窗口和无效几何输入。
- 组件契约验证 `position: fixed`、布局测量、resize/observer 清理和现有 ARIA 语义。
- Electron 自动化同时断言上传和下载状态下 `top >= 0`、`bottom <= viewportHeight`、`left >= 0`、`right <= viewportWidth`。
- 保留活动、暂停、部分完成、失败和完成终态测试。

### 11.2 安全删除

- 使用调用计数测试证明准备阶段每个文件只执行必要的原文件摘要和快照摘要。
- 验证缓存必须绑定操作、端点、恢复绑定、路径和描述符；任一变化都导致失效。
- 验证执行前仍完整检查快照和原文件，执行后确认原路径不存在。
- 验证取消、重试、断线、摘要失败、复制失败和元数据变化均失败关闭。
- 验证阶段顺序、字节单调递增、节流上限、未知总量和多目标序号。
- 验证确认前按钮禁用、ready 后启用、deleting 时防止重复提交。
- 验证删除成功后同步乐观移除且没有 `wait(500)`，后台只调用一次 `remoteList()`。

### 11.3 回归与性能

- 运行相关 `test/unit-ci` 安全事务、删除对话框、进度坞和刷新行为测试。
- 运行完整 `test-unit-ci`、lint、SSH/SFTP 本地 E2E 和核心质量流程。
- 使用 32 MiB 文件重复三次测量安全删除准备和确认后完成时间，并记录完整摘要次数。
- 使用 1956 × 1098 和一个更矮窗口复测上传/下载进度坞可见性。
- 使用 1000 项目录确认乐观移除和后台校准不破坏虚拟列表。

## 12. 验收标准

1. 上传与下载进度坞在测试窗口和更矮窗口中均完整可见，边界不超出视口。
2. 安全删除点击后 150 ms 内显示阶段反馈，长操作期间阶段和可用字节持续更新。
3. 快照完整验证完成前确认按钮始终禁用。
4. 同一确认周期内不再对刚验证、未发生可观察变化的快照重复执行完整摘要。
5. 32 MiB 安全删除准备和确认后等待相对 v0.4.42 基线均明显下降；测试记录同时证明摘要次数减少。
6. 删除成功后当前列表立即更新，不再存在固定 500 ms 等待；后台只校准一次。
7. 快速删除、AI/MCP 安全策略、恢复中心、上传下载传输语义和现有安全失败关闭行为保持不变。
8. 相关单元测试、完整单元测试、lint、本地 SSH/SFTP E2E 和可见性自动化全部通过。
