# ShellPilot 启动与聊天栏简化设计

## 目标

在不删除底层 SSH、MCP、CLI 能力的前提下，让 Windows 客户端更符合常规桌面工具的使用习惯：

1. 双击客户端顶部标题栏空白区域时，在最大化与还原之间切换。
2. 没有显式启动任务时，客户端进入未连接首页，不再自动创建本地终端。
3. AI 聊天栏暂时隐藏 MCP 与 CLI 引用入口。

## 窗口交互

在 `AIGShellTopBar` 的顶层标题栏处理双击事件，并调用现有的 `maximize` / `unmaximize` IPC。

- 仅标题栏空白区域和品牌信息区域响应。
- 按钮、链接、输入框、下拉菜单、窗口控制按钮及其他带 `no-drag` 语义的元素不响应。
- 最大化状态继续使用现有 `store.isMaximized`，不新增第二套窗口状态。
- 最小化、最大化、还原和关闭按钮的现有行为保持不变。

## 启动首页

修改默认设置，使 `initDefaultTabOnStart` 默认为 `false`。启动流程遵循以下优先级：

1. 命令行或协议链接明确要求打开连接时，照常打开。
2. 用户明确配置启动工作区或启动服务器时，照常恢复。
3. 崩溃恢复由用户现有的恢复入口处理，不静默建立新连接。
4. 没有上述显式意图时，保持零标签页并显示现有 `NoSessionPanel` 首页。

本次不删除“启动时打开默认终端”设置。用户主动开启后仍可恢复旧行为。

## AI 聊天栏

从聊天输入区的可见操作列表移除：

- 引用 MCP 配置
- 引用 CLI 能力

保留终端引用、选中内容、SFTP 文件引用和生成命令。MCP/CLI 的底层模块、配置数据和 Agent 能力不删除，后续成熟后可重新开放入口。

## 兼容边界

- 不修改 SSH、SFTP、终端输入、快捷命令和安全执行链路。
- 不清理用户已保存的终端、书签、MCP 或 CLI 配置。
- 不影响手动新建本地终端。
- 不改变用户明确配置的启动工作区和启动服务器。

## 验收

- Windows 自定义标题栏空白处双击可最大化，再次双击可还原。
- 双击顶部功能按钮不会切换窗口状态，也不会重复触发按钮。
- 清洁配置启动后 `tabs.length === 0`，显示未连接首页。
- 显式启动会话、命令行连接和手动新建终端仍正常。
- AI 聊天栏不显示 MCP/CLI 引用按钮，其他上下文按钮仍可见可用。
- 相关单元测试、关键 E2E、前端编译和本地打包冒烟测试通过。
