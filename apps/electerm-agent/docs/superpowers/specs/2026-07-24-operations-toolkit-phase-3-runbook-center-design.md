# 运维工具第三阶段：场景脚本中心设计

## 目标

在现有运维工具中把“我的工具”升级为“脚本中心”，提供面向故障场景的多步骤只读脚本。脚本复用现有 SSH 后台任务、实时输出、取消、历史记录和 AI 分析能力，不复制终端、SFTP、快捷命令或安全事务实现。

## 产品边界

- 快捷操作用于短小、单一目的的命令。
- 诊断脚本用于单项检查。
- 脚本中心用于按故障场景组织的多步骤排查流程。
- 安全维护负责修改服务器，并继续提供备份、确认、校验和回滚。
- 脚本中心首期只接纳 `read-only` 脚本，因此无需二次确认。
- 自定义脚本导入暂不开放，避免未经审查的命令绕过安全策略。

## 首批场景脚本

1. 服务器综合健康巡检
2. CPU 高负载现场采集
3. 内存、Swap 与 OOM 排查
4. 磁盘空间与 I/O 故障排查
5. Web 502/504 故障包
6. Docker/Podman 容器故障包
7. 网络间歇性故障排查
8. SSH 登录安全审计
9. 指定服务故障排查
10. 国产 Linux 兼容性与基础环境报告

已有 UDP 综合检测继续保留在“诊断脚本”，避免在脚本中心重复。

## 数据与执行

脚本采用现有运维工具定义模型，每个步骤都有稳定 ID、中文名称、超时和安全构建函数。参数必须经过现有主机、端口、服务名和路径校验器处理。

执行时先自动发现系统、工具、网卡和服务，再通过独立 SSH 任务逐步运行。任何步骤失败时停止后续步骤并保留已完成输出；用户可随时取消。每个步骤输出继续受行数和持久化大小限制，完成记录保存在现有任务历史中，并可交给 AI 分析。

## 系统兼容性

兼容 Ubuntu、Debian、CentOS、Rocky、AlmaLinux、Anolis、Alibaba Cloud Linux、OpenCloudOS、TencentOS、Kylin、UOS 和 openEuler。脚本不直接安装依赖；缺少工具时输出明确的“不支持/未安装”信息，并继续采集可用信息。

## 界面

“脚本中心”沿用诊断脚本的双栏布局：

- 左侧提供搜索、分类和场景脚本列表。
- 右侧展示用途、适用场景、自动发现的服务器、参数表单和步骤清单。
- 主按钮使用“运行脚本”，旁边明确标注“只读，无需确认”。
- 执行区继续显示步骤进度、实时输出、停止按钮和 AI 分析入口。

## 验证

- 单元测试校验脚本数量、唯一 ID、只读安全边界、参数转义和国产系统兼容性。
- E2E 验证脚本中心入口、分类、参数表单、未连接状态和运行按钮。
- 回归运维诊断、安全维护、SSH、SFTP、AI、历史记录和 Windows 打包。
