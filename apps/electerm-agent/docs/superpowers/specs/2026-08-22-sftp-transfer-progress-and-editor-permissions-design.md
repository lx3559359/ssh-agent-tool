# ShellPilot SFTP 传输进度与远程编辑权限设计

## 1. 背景与问题

ShellPilot 已经具备上传、下载进度事件和逐任务进度条，但详细传输界面只绑定在左侧 SFTP 按钮的右键菜单中。用户启动传输后看不到稳定、直接的反馈，容易误判任务没有开始或已经卡住。

远程文本编辑器使用带快照、校验和原子置换的 SFTP 安全事务。保存时会在目标文件父目录下创建 `.shellpilot-transactions`，复制原文件快照，保留 ownership/mode，写入临时文件并原子替换目标。当前元数据复制和编辑暂存阶段会无条件调用 `chown`。部分 SFTP 服务会拒绝普通用户发起的 `chown`，即使目标文件已经具有正确的 uid/gid，因此正常可写文件也可能返回 `Permission denied`。

终端 Shell 与 SFTP 虽复用同一条 SSH 连接，但权限上下文不同。用户在交互式终端中执行 `su` 或 `sudo` 只改变该 PTY Shell 的进程身份，不会改变已经认证的 SFTP 子系统身份。界面目前没有在保存失败时解释这一区别。

## 2. 已验证事实

本设计仅依据本地代码和隔离测试验证，不连接用户服务器：

1. SFTP 客户端通过现有 SSH 连接的 `conn.sftp()` 创建，身份固定为连接配置中的认证用户。
2. 终端内后续执行 `su`、`sudo -i` 或其他提权命令不会重新认证 SFTP。
3. 正常编辑事务会经过快照、ownership/mode 保留、暂存写入和原子置换。
4. ownership 变更被拒时，现有事务按安全策略失败关闭，不修改原文件。
5. 上传和下载传输层已经上报 `transferred`、`total`、速度和预计剩余时间；缺口主要是可见性。
6. 本地相关测试共执行 19 项，正常编辑、ownership 拒绝、上传、下载及进度事件均通过。

## 3. 目标

1. SFTP 上传或下载开始后，在当前 SFTP 文件管理器中立即显示进度条。
2. 同时支持整体进度和逐文件详情，不要求用户知道右键入口。
3. 修复 ownership 已经一致时仍执行 `chown` 导致的误报权限失败。
4. ownership 确实不一致时继续严格保留元数据，不以降级方式破坏文件属主。
5. 保存失败时明确说明当前 SFTP 身份、失败阶段和可执行的处理方式。
6. 保存失败后保留编辑器内容，允许用户修复权限或重新连接后重试。
7. 新增进度展示不得显著增加输入延迟或全局重渲染频率。

## 4. 非目标

本次不包含：

- 连接或探测截图中的服务器。
- 自动执行 `sudo`、猜测 sudo 密码或复用终端中的 root Shell。
- 把命令注入当前交互式 PTY 来绕过 SFTP 权限。
- 绕过远端 ACL、immutable 属性、只读文件系统或 SFTP 子系统策略。
- 改变上传、下载的重试、暂停、恢复和安全事务语义。
- 重写全局操作中心或传输历史。

## 5. 方案选择

### 5.1 采用方案

采用“固定进度坞 + 条件元数据写入 + 身份感知错误”方案：

- 在 SFTP 文件管理器底部增加紧凑传输进度坞，当前标签页有活动传输时自动出现。
- 默认显示整体进度、当前文件、任务数和速度；点击后展开已有逐任务进度与控制。
- 在复制快照和编辑暂存文件时先读取实际 uid/gid/mode，只对不一致的字段调用 `chown`/`chmod`。
- 真实 ownership 不一致且服务端拒绝变更时继续失败关闭，并显示可理解的权限说明。

该方案不改变服务器权限，也不引入自动提权，能修复不必要 `chown` 造成的兼容问题，并让真正的权限不足清晰可诊断。

### 5.2 未采用方案

仅自动打开现有右键弹层：改动较小，但弹层接近全屏，会遮挡文件操作，而且完成后容易打断用户。

自动使用 `sudo` 保存：可覆盖部分 root-owned 文件，但需要新的特权事务、远端临时文件、sudo 能力验证和审计边界。它无法可靠复用交互终端中的 root 状态，也与项目现有“不猜测密码、不自动提权”原则冲突。

向当前终端注入保存命令：依赖提示符和 Shell 状态，可能与用户输入竞争，无法形成可靠的原子事务，因此明确排除。

## 6. 传输进度设计

### 6.1 展示位置与状态

进度坞固定在当前 SFTP 文件管理器底部，只展示 `tabId` 与当前标签页一致的上传、下载和跨端传输。没有活动任务时不占用空间。

折叠状态显示：

- 方向图标和当前文件名。
- 按已知字节加权的整体百分比。
- `已传输 / 总大小`、合计速度和活动任务数。
- 暂停、失败和重试状态的明确颜色与文字。

展开状态复用现有逐任务传输行，保留文件来源、目标、进度条、速度、剩余时间、暂停/继续和取消控制。原有右键传输中心继续保留，作为跨标签页的全局入口。

### 6.2 聚合规则

- 已知总大小的文件按字节聚合，百分比限制在 0–100。
- 总大小未知或目录扫描尚未完成时显示活动态进度，不伪造精确百分比。
- 已完成字节不得因重试回退产生负数；重新开始的任务使用已有 retry 状态文字。
- 失败和暂停任务仍留在展开列表中，直到现有传输生命周期清理它们。
- 当前文件优先选择正在传输的第一项，其次为暂停或等待项。

### 6.3 性能与可访问性

底层传输继续保存精确字节数，视觉更新合并到最多每 100ms 一次；开始、暂停、失败、完成和取消立即刷新。聚合逻辑放在纯函数中，避免每次渲染重复深遍历全局任务。

进度条提供可访问名称、最小值、最大值和已知时的当前值。未知总量时不声明虚假的 `aria-valuenow`。展开按钮支持键盘操作，并通过 `aria-expanded` 表达状态。

## 7. 远程编辑权限设计

### 7.1 条件 ownership/mode 写入

快照复制后的元数据处理顺序调整为：

```text
读取暂存项元数据
  -> uid/gid 与预期不同：调用 chown
  -> mode 与预期不同：调用 chmod
  -> 再次读取并严格验证 uid/gid/mode
```

编辑器写入 `*.execute` 临时文件后采用相同规则。若新文件天然由当前 SFTP 用户创建且 uid/gid 已经正确，则跳过冗余 `chown`。如果原文件属于其他用户，暂存文件 ownership 与预期不一致，仍必须调用 `chown`；调用失败时事务停止，原文件保持不变。

不得因为 `chown` 不可用而忽略 ownership 差异，也不得仅凭连接用户名推断远端 uid。

### 7.2 失败阶段与错误说明

保存事务为权限错误附加有限阶段信息：

- 创建事务目录。
- 创建或验证快照。
- 写入暂存文件。
- 保留 ownership/mode。
- 原子替换目标。

面向用户的错误不展示内部随机事务路径，但显示目标路径、当前连接配置中的 SFTP 用户和阶段。

非 root SFTP 身份的权限提示说明：终端中的 `su/sudo` 不会改变 SFTP 身份；需要使用具备目标父目录写入和元数据保留权限的账号重新连接，或由服务器管理员调整目标 ownership/ACL。

连接配置用户名为 root 时，不直接断言 root 必然有权限；提示检查只读挂载、ACL、immutable 属性、chroot 或 SFTP 服务端限制。

### 7.3 编辑器状态

保存失败后：

- 编辑器保持打开。
- 文本内容、光标和搜索状态不清空。
- 保存按钮退出 loading 状态，可再次提交。
- 原始错误继续进入现有安全诊断记录，但通知只显示经过清理的可操作信息。

保存成功后继续沿用现有摘要校验、成功通知和安全中心回滚记录。

## 8. 组件与代码边界

预计新增或修改：

- `src/client/components/sftp/sftp-transfer-progress-model.js`：按标签过滤、聚合已知/未知进度和选择当前任务的纯函数。
- `src/client/components/sftp/sftp-transfer-progress-dock.jsx`：折叠/展开进度坞及可访问交互。
- `src/client/components/sftp/sftp.styl`：底部进度坞布局、状态色和窄窗口行为。
- `src/client/components/sftp/sftp-entry.jsx`：在当前文件管理器挂载进度坞，并传入当前标签页身份。
- `src/client/components/sidebar/transport-ui.jsx`：抽取或复用逐任务进度内容，避免两套显示逻辑分叉。
- `src/app/server/session-sftp.js`：条件应用 ownership/mode，最终验证保持严格。
- `src/client/components/sftp/sftp-transaction-adapter.js`：编辑暂存文件采用相同的条件元数据逻辑，并标记失败阶段。
- `src/client/components/sftp/sftp-editor-permission-error.js`：将权限错误映射为身份感知、可测试的用户提示。
- `src/client/components/sftp/file-item.jsx`：保存失败时保留编辑状态并显示规范化权限信息。

实现时可根据现有组件边界合并小型辅助函数，但聚合计算和权限错误格式化必须保持为可独立测试的纯逻辑。

## 9. 错误处理与安全边界

- 已知权限拒绝：显示阶段、SFTP 身份和处理建议，保持编辑内容。
- ownership 不一致：不得跳过 `chown`；失败时保留原文件和可回滚快照。
- 事务目录不可写：在创建阶段停止，不尝试直接覆盖目标。
- 暂存写入失败：清理仅由当前事务确认拥有的临时项。
- 原子替换失败：沿用现有事务恢复逻辑，不删除无法确认归属的文件。
- 连接中断：保留现有 interrupted/rollbackable 状态。
- 未知错误：继续使用现有安全错误 ID，不暴露凭据或完整内部路径。
- 任何分支都不自动执行 sudo，不读取或保存 sudo 密码。

## 10. 测试策略

### 10.1 传输进度

- 上传与下载均产生递增的字节和百分比。
- 当前标签页只聚合自己的任务，不泄漏其他会话的文件名。
- 多文件按字节加权，百分比正确钳制。
- 未知总量显示活动态，不显示虚假百分比。
- 暂停、继续、重试、失败、完成和取消状态正确。
- 折叠/展开、键盘操作和 ARIA 属性完整。
- 高频进度事件下视觉提交频率不超过设计上限，终态立即可见。

### 10.2 编辑权限

- uid/gid 已匹配时，即使 mock `chown` 会拒绝，保存仍成功且不调用 `chown`。
- uid/gid 不匹配时必须调用 `chown`；拒绝后原文件不变。
- mode 已匹配时可跳过 `chmod`，不匹配时必须修改并复验。
- root-owned 目标由普通 SFTP 用户保存时失败关闭。
- 非 root 和 root 身份生成不同且准确的权限提示。
- 保存失败后编辑器文本和打开状态保留，loading 正常复位。
- 快照、原子替换、摘要校验和回滚测试不回归。

### 10.3 本地集成与回归

- 使用仓库内本地 SSH/SFTP 服务完成大文件上传、下载，并观察进度坞从开始到完成。
- 使用权限 mock 复现冗余 chown 拒绝和真实 ownership 不匹配，不连接外部服务器。
- 运行相关单元测试、完整 `test-unit-ci`、lint、SFTP 本地 E2E 和客户端交互性能回归。

## 11. 验收标准

1. 上传或下载开始后，无需右键即可在 SFTP 页面底部看到进度条。
2. 进度坞显示当前文件、百分比、字节、速度和任务数，且可展开逐文件控制。
3. 已匹配 ownership 的普通用户文件不会因冗余 `chown` 返回 `Permission denied`。
4. ownership 确实不同且无权限时仍不会破坏原文件或偷偷降低安全要求。
5. 保存失败提示明确区分 SFTP 身份和终端 Shell 提权，并保留未保存文本。
6. 不连接用户服务器，不自动 sudo，不注入当前终端。
7. 相关单元测试、本地 SFTP 集成测试、lint 和性能回归通过。
