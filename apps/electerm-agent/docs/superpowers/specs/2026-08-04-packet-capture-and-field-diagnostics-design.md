# ShellPilot 独立抓包与现场排查脚本设计

## 1. 背景与问题

ShellPilot 旧版快捷命令包含 `builtin-server-packet-capture` 独立抓包脚本。运维工具迁移时，该 ID 被加入隐藏集合，并映射到 `network.udp-comprehensive-check`。因此旧定义仍在仓库中，但新版运维工具不再显示独立抓包入口。

UDP 综合检测只在固定 UDP 目标上附带短时 `tcpdump` 观察，不能替代支持 TCP、UDP、ICMP、主机和端口组合过滤的通用抓包。迁移行为导致了功能降级。

当前运维目录已经覆盖系统概览、CPU、内存、磁盘容量、基础网络、服务、日志、Web 和容器等常见场景，但对异常进程、文件描述符、远程挂载、块设备健康和时间同步等现场深挖场景覆盖不足。

## 2. 目标

本次采用“完整恢复 + 小批量扩展”方案：

1. 在新版运维工具中恢复独立、可配置、有限额的网络抓包。
2. 保留旧抓包 ID、收藏、历史记录和深链兼容性。
3. 新增五项与现有目录不重复的只读现场排查工具。
4. 所有新增命令采用类型化参数、固定命令模板、执行限时和输出限额。
5. 缺少可选依赖时只报告能力缺失和安装建议，不自动安装软件。

## 3. 非目标

本次不包含：

- 任意自由输入的 BPF 或 Shell 表达式。
- 持续、循环或后台抓包。
- 自动上传、自动下载或自动提交 pcap 内容给 AI。
- 自动修复磁盘、文件系统、NTP、进程或挂载故障。
- 新增服务停止、文件删除、日志清理等不可逆维护动作。
- 替换现有 UDP 综合检测；UDP 工具继续保留其专用报文观察步骤。

## 4. 方案概述

### 4.1 独立抓包工具

新增稳定工具 ID：

```text
network.packet-capture
```

显示名称为“网络抓包与报文采样”，位于运维工具的网络诊断分类。旧 ID `builtin-server-packet-capture` 改为映射到该工具，而不是映射到 UDP 综合检测。旧快捷命令定义继续保留一个兼容周期，但不在新版目录重复展示。

抓包属于资源敏感诊断：它不会修改系统配置，但会读取网络流量并在远端创建 pcap 文件。风险模型新增 `resource-sensitive`，不能伪装成普通只读工具。

执行流程为：

```text
参数校验
  -> 显示抓包范围、上限和保存路径
  -> 用户确认
  -> 依赖、权限、网卡、目录和目标文件预检
  -> 有界抓包
  -> 原子落盘
  -> 输出文件信息和有限文本摘要
```

### 4.2 首批现场排查工具

新增以下只读诊断：

| 工具 ID | 显示名称 | 主要输出 |
| --- | --- | --- |
| `process.abnormal-state` | 异常进程与阻塞状态排查 | 僵尸进程、D 状态、线程、资源占用、等待点，可选 PID 深挖 |
| `system.file-descriptor-pressure` | 文件描述符与 Socket 压力 | 系统 file-nr/file-max、进程 FD 排名、Socket 摘要、当前限制 |
| `storage.mount-filesystem-health` | 挂载点与远程文件系统健康 | findmnt、只读挂载、NFS/CIFS 状态、mountstats 和相关内核告警 |
| `storage.block-device-health` | 磁盘、SMART 与 RAID 健康 | lsblk、内核块设备告警、mdraid 状态和有限 SMART 健康摘要 |
| `system.time-synchronization` | 系统时间与同步状态 | 本地时间、时区、timedatectl、Chrony、NTP 和 timesyncd 状态 |

这些工具只采集状态，不发送信号、不重新挂载、不执行 fsck、不调整时间，也不修改服务配置。

## 5. 抓包参数与命令构建

### 5.1 参数

| 参数 | 类型与默认值 | 约束 |
| --- | --- | --- |
| 网卡 | 能力发现下拉框，默认 `any` | 必须来自当前服务器探测结果，另允许 `any` |
| 协议 | 枚举，默认 `tcp` | `any`、`tcp`、`udp`、`icmp`、`icmp6` |
| 主机 | 可选 host | 通过现有主机校验器，不允许控制字符或命令语法 |
| 端口 | 可选 port | 仅 `tcp`、`udp` 可用，范围 1–65535 |
| 包数 | 数字，默认 100 | 1–1000 |
| 最长时长 | 数字，默认 30 秒 | 1–300 秒 |
| 保存路径 | 绝对路径，默认 `/tmp/shellpilot-capture.pcap` | 必须以 `.pcap` 结尾，父目录已存在，拒绝已有文件和符号链接目标 |

过滤表达式只由协议、主机和端口三个经过校验的字段组合生成。例如：

```text
tcp and host 10.0.0.8 and port 443
```

界面不提供自定义 BPF 输入框，避免把用户文本直接放入 Shell 命令。

### 5.2 远端执行安全

- 使用 `tcpdump -nn`，避免 DNS 和服务名解析带来的额外流量与延迟。
- 同时使用包数和时间双重上限；达到任一上限即停止。
- 使用 `timeout --signal=INT`，让 tcpdump 有机会完整刷新 pcap 头和缓冲区。
- 默认 `umask 077`，抓包文件仅对创建用户可读写。
- 先在目标父目录创建随机临时文件，成功后使用 `ln -- "$TEMP" "$TARGET"` 创建同目录硬链接，再移除临时文件名。`ln` 在目标已存在时失败，从而原子地保证“不覆盖”。
- 最终路径已存在时立即失败，不覆盖、不追加。
- 失败或正常取消时清理当前任务拥有的临时文件；无法确认所有权时保留并报告路径，不盲目删除。
- 非 root 用户仅尝试无交互的 `sudo -n`。没有免密权限时给出明确提示，不让任务停在密码输入上。
- `tcpdump` 不存在时提示适用发行版的安装命令，但不自动安装。
- 文本摘要最多读取前 100 个报文，只显示 pcap 路径、大小、时间和有限报文头，不读取载荷全文。

## 6. 风险模型与确认

`operationsRiskTypes` 新增：

```text
resourceSensitive: resource-sensitive
```

任务执行器继续默认只接受 `read-only`。执行 `resource-sensitive` 工具必须同时满足：

1. 工具定义声明需要确认。
2. 工作区先展示工具名称、目标主机、网卡、过滤范围、包数、时长和保存路径。
3. 用户在本次运行中明确确认。
4. Store 将工具 ID、端点键和规范化参数摘要绑定到一次性确认记录，再传给任务执行器。

任务执行器拒绝无确认的资源敏感任务。单台服务器同时只允许一个资源敏感任务，普通只读任务继续沿用现有并发上限。

确认不会持久化，也不能应用到下一次抓包。取消、超时、SSH 断线和部分完成状态继续写入现有运维历史。

## 7. 现场排查工具边界

### 7.1 异常进程与阻塞状态

默认输出系统范围内有限数量的高 CPU、高内存、僵尸和 D 状态进程。可选 PID 模式读取 `/proc/<pid>/status`、线程列表、等待点、限制和 FD 数量。

不读取 `/proc/<pid>/environ`，不完整输出命令行参数，避免泄露令牌、密码和业务参数；进程不存在或权限不足时返回明确的降级结果。

### 7.2 文件描述符与 Socket 压力

读取 `/proc/sys/fs/file-nr`、`file-max`、当前 shell 限制、Socket 汇总，并对可访问的 `/proc/<pid>/fd` 做有界排名。存在 `lsof` 时可补充摘要，不存在时使用 `/proc` 降级。

扫描设置进程数和输出行数上限，不能因主机进程过多造成长时间阻塞。

### 7.3 挂载点与远程文件系统健康

读取 `findmnt`、`df`、`/proc/self/mountstats`、`nfsstat -m` 和相关内核日志。只识别 NFS/CIFS 和只读异常，不主动访问每个挂载点，避免故障远程存储将诊断任务卡入不可中断状态。

### 7.4 磁盘、SMART 与 RAID 健康

读取 `lsblk`、`/proc/mdstat`、mdadm 扫描摘要和内核 I/O 告警。存在 `smartctl` 时最多检查八个探测到的本地块设备，每个设备单独限时；权限不足时标记“未确认”，不把缺少权限误判为磁盘健康。

不运行长测、短测、修复、重建、写缓存调整或文件系统检查。

### 7.5 系统时间与同步状态

读取 `date`、`timedatectl`、Chrony、ntpq 和 systemd-timesyncd 可用信息。只报告同步源、偏移、层级、闰秒和服务状态，不主动校时，也不访问用户未指定的外部时间服务器。

## 8. 目录与组件变更

新增或修改的核心边界：

- `catalog/diagnostics/packet-capture.js`：参数规范化、过滤器构建、预检、抓包和摘要步骤。
- `catalog/diagnostics/advanced-system.js`：五项只读现场排查工具。
- `catalog/index.js`：注册新增工具组。
- `catalog/migrations.js`：把旧抓包 ID 映射到 `network.packet-capture`。
- `shared/definition.js`：增加资源敏感风险类型和定义校验。
- `shared/validation.js`：增加抓包协议、可选主机、可选端口和 pcap 路径校验。
- `runtime/task-runner.js`：确认门禁、资源敏感任务单并发和现有取消状态复用。
- `workspace/operations-workspace.jsx`：抓包运行前确认摘要。
- `workspace/parameter-form.jsx`：复用现有字段，按协议控制端口可用性；不增加自由 Shell 输入。
- 用户指南：恢复独立抓包说明，并列出新增现场排查工具及依赖降级行为。

五项普通排查工具不引入新的运行通道，继续使用现有专用 SSH 任务通道、输出缓冲、历史记录和事故候选采集。

## 9. 错误处理与降级

- 参数错误：执行前阻止运行，并指出具体字段。
- 工具缺失：对应步骤显示 `unsupported` 和安装建议，其余可用步骤继续。
- 权限不足：显示所需权限；抓包不进入交互式 sudo，SMART 不声称健康。
- 任务通道超时：标记 `timed-out`。抓包命令内部达到用户设置的采样时长属于正常结束，命令负责刷新并发布有效 pcap，不把它上报为任务通道超时。
- 用户取消：标记 `cancelled`，清理本任务确认拥有的临时文件。
- SSH 断线：标记 `disconnected`，历史记录保留已完成步骤和最终路径状态。
- 输出过大：沿用现有输出缓冲截断，并显示“内容已截断”。
- pcap 路径冲突：拒绝覆盖，提示更换文件名。

## 10. AI 与隐私边界

普通排查结果继续沿用现有脱敏和长度限制进入“交给 AI 分析”。抓包任务默认只向 AI 提供：

- 工具名称和目标服务器标识。
- 用户选择的结构化过滤范围。
- 抓包开始/结束状态、报文数量、文件大小和远端路径。
- 最多 100 行不含载荷全文的 tcpdump 头部摘要。

pcap 二进制内容不自动读取、不自动上传，也不加入事故归档附件。用户后续明确选择文件时再走既有文件上下文和隐私确认流程。

## 11. 测试策略

### 11.1 迁移与目录

- 旧抓包 ID 解析为 `network.packet-capture`。
- 新工具在诊断目录中可发现，旧快捷动作仍保留在注册表但不重复展示。
- 新增工具 ID、步骤 ID、分类和风险类型唯一且稳定。

### 11.2 参数与命令安全

- 协议枚举、端口适用性、网卡来源、包数、时长和绝对 pcap 路径边界。
- 主机、路径和所有文本字段的换行、NUL、引号、命令替换、重定向和管道注入用例。
- 已存在目标、符号链接目标、错误后缀和不存在父目录的拒绝行为。
- 生成命令包含包数和时长双重限制，不包含 `eval`、动态 `source` 或自由表达式拼接。

### 11.3 确认与运行时

- 未确认的资源敏感工具被任务执行器拒绝。
- 已确认抓包可以执行，确认只对当前运行有效。
- 同端点第二个抓包任务被拒绝，普通只读任务行为不回归。
- 成功、包数结束、时间结束、取消、超时、命令失败和 SSH 断线状态正确。

### 11.4 排查脚本

- 每个工具在主要工具存在时生成预期的有界只读命令。
- 可选依赖缺失、非 systemd、非 mdraid、无 SMART 权限等场景有明确降级输出。
- 不出现服务修改、信号发送、重新挂载、校时、磁盘测试或修复命令。

### 11.5 回归

- 运维工具目录、迁移、参数表单、任务执行器、历史记录、AI 上下文和事故采集单元测试。
- 快捷命令注册表及服务器维护命令安全测试。
- lint、完整 `test-unit-ci`，以及运维工具相关 E2E。

## 12. 验收标准

1. 用户能在“运维工具 → 诊断脚本/网络”中找到独立抓包工具。
2. TCP、UDP、ICMP 和不限协议抓包均可通过结构化表单配置。
3. 抓包没有确认不能执行，且单次最多 1000 包、300 秒。
4. 目标文件不会被覆盖，临时文件权限受限，取消和失败行为可解释。
5. 旧抓包收藏、历史或深链能定位到新工具。
6. 五项新增排查工具可在缺少可选依赖时安全降级。
7. 所有新增命令只执行设计允许的读取或有限抓包动作。
8. 相关单元测试、完整单元测试、lint 和运维工具 E2E 通过。
