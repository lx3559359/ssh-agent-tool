# ShellPilot 半自动故障档案设计

## 目标

将现有“完全手工创建故障档案”调整为“自动发现、人工确认建档、后续过程自动归档”：

1. 服务器状态异常、只读诊断失败和安全操作失败先生成待确认事件。
2. 待确认事件只保存脱敏、限长的只读上下文，不自动成为正式故障档案。
3. 用户确认后创建正式档案，并把原始事件写入时间线。
4. 正式档案可以继续关联诊断、命令、备份、修改、回滚、验证和成果物。
5. 普通 SSH/SFTP 使用不增加后台探测，不修改终端核心链路。

## 产品边界

### 自动执行

- 根据状态中心快照识别异常服务、连接失败和资源异常。
- 根据运维任务最终状态识别失败、超时、断线和部分完成。
- 根据安全操作中心事件识别失败、可回滚、已回滚和验证结果。
- 对同一服务器、来源和异常指纹进行去重。
- 对采集内容做敏感字段过滤、文本截断和数组限长。

### 必须人工确认

- 将待确认事件转换为正式故障档案。
- 执行任何修改、删除、重启、停止、网络或防火墙变更。
- 将普通 SSH 会话纳入故障过程记录。

### 不自动执行

- 不自动运行新的 SSH 命令来补充证据。
- 不自动创建大量低价值档案。
- 不把密码、私钥、API Key、Token、Cookie 或 Authorization 写入档案。
- 不把成果物与故障档案合并为同一个数据库对象。

## 信息架构

故障档案工作区增加“待确认事件”视图，与正式档案列表并列。

待确认事件支持：

- 查看来源、服务器、严重程度、首次/最近发现时间和证据摘要。
- 确认建档。
- 忽略事件。
- 对已忽略事件重新打开。

正式档案详情增加统一时间线：

- 状态变化。
- 人工备注。
- 自动采集事件。
- 运维任务结果。
- 安全操作、备份、回滚和验证。
- 关联成果物。

## 数据模型

### incident_candidates

- `id`
- `fingerprint`
- `source`
- `source_ref`
- `endpoint_ref`
- `title`
- `severity`
- `summary`
- `evidence_json`
- `status`: `pending`、`dismissed`、`converted`
- `incident_id`
- `first_seen_at`
- `last_seen_at`
- `occurrence_count`
- `created_at`
- `updated_at`

唯一约束为 `fingerprint`。相同异常再次出现时更新最近发现时间和次数，不重复创建。

### incident_timeline_events

- `id`
- `incident_id`
- `kind`
- `source`
- `source_ref`
- `title`
- `body`
- `metadata_json`
- `created_at`

`incident_id + source + source_ref + kind` 建唯一索引，避免完成回调重复写入。

### 关联成果物

成果物仍由成果物中心负责版本、预览和导出。故障档案时间线只保存：

- `artifactId`
- 成果物标题、类型和版本摘要
- 创建时间

删除成果物不删除故障档案；删除故障档案也不删除成果物。

## 事件来源

### 服务器状态中心

仅在以下情况创建候选事件：

- SSH 连接采集失败。
- 整体状态为异常。
- 服务状态为 failed、inactive、dead、crashed、unhealthy、degraded 或 error。
- 资源状态超过状态中心已经判定的告警阈值。

事件指纹由服务器标识、异常类型和异常对象组成。

### 运维工具

任务状态为 failed、timed-out、disconnected 或 partially-completed 时生成候选事件。

任务完成后，如果当前服务器存在已打开的正式故障档案，则将任务摘要写入时间线；否则只对异常任务创建候选事件。

### 安全操作中心

失败操作生成候选事件。已经关联正式故障档案的操作会把准备、执行、备份、回滚和验证结果写入时间线。

## 确认建档流程

1. 用户在待确认事件中选择“确认建档”。
2. 系统预填标题、服务器、严重程度、摘要、服务标签和来源标签。
3. 用户可修改后确认。
4. 后端在单个事务中创建正式档案、写入首条时间线并把候选事件标记为已转换。
5. 工作区自动打开新档案。

## 安全与性能

- 单条证据 JSON 最大 64 KiB。
- 摘要最大 20,000 字符，时间线正文最大 20,000 字符。
- 候选事件列表分页，每页最多 100 条。
- 自动事件只接收白名单字段并递归拒绝敏感键。
- 所有写入由 SQLite 事务完成。
- 失败的自动采集不得阻断原始状态刷新、运维任务或安全操作。
- 不监听终端原始字符流，不影响 SSH 输入、Ctrl+C、SFTP 和终端启动。

## 成果物协作

正式档案提供“生成复盘报告”入口，生成 `incident-review` 类型成果物草稿。报告是档案在生成时刻的结构化快照，可继续在成果物中心编辑、导出 MD/DOCX/PDF/HTML。

故障档案负责过程事实和审计，成果物负责表达、版本和交付；两者通过 ID 关联。

## 验收标准

- 相同异常重复采集只增加次数，不创建重复候选。
- 候选事件不会未经确认成为正式档案。
- 确认建档后候选状态与正式档案在同一事务中更新。
- 正式档案能够展示自动事件、任务、备份、回滚、验证和成果物时间线。
- 任何敏感字段均被拒绝或脱敏。
- 自动归档失败不影响 SSH、状态中心、运维任务和安全操作本身。
- 现有故障档案数据库可无损迁移，备份与恢复仍可使用。
