# ShellPilot 运维工具 1.0 设计

**日期：** 2026-07-24  
**适用版本：** 0.4.10 之后的本地开发版本  
**状态：** 总体方案已确认，待实施计划  

## 1. 背景

ShellPilot 已具备成熟 SSH/SFTP 终端、快捷命令、安全操作中心、备份回滚、AI 助手和服务器状态能力。现有“快捷命令”适合单个、短时、目标明确的操作，但不适合承载多步骤诊断、持续输出、条件分支、结果汇总和安全维护流程。

本设计将顶部“快捷命令”升级为“运维工具”，同时保留既有底层命令定义、安全事务和历史数据。新增脚本不是另一个独立客户端，也不在服务器安装常驻 Agent，而是通过当前服务器的 SSH 凭据建立专用后台执行通道，在客户端任务面板中展示进度与结果。

## 2. 目标

1. 将原“快捷命令”入口升级为统一的“运维工具”工作区。
2. 明确区分快捷操作、诊断脚本和维护脚本，避免相同能力重复出现。
3. 提供不少于 50 项高频、实用的服务器诊断和安全维护能力。
4. 普通只读操作直接执行，不增加二次确认。
5. 所有受支持的修改操作必须先预检、备份并准备回滚，再允许执行。
6. 后台脚本执行不得阻塞当前交互式 SSH 终端。
7. 自动识别操作系统、包管理器、服务管理器、网卡、服务、容器和常见平台软件。
8. 支持 Ubuntu、Debian、CentOS、RHEL、Rocky Linux、AlmaLinux 及主要国产服务器系统。
9. 任务支持实时输出、取消、超时、断线状态、历史记录和结果交给 AI 分析。
10. 不降低普通 SSH 首次可用时间，不为未使用运维工具的用户增加服务器开销。

## 3. 非目标

1. 不重写 Electerm SSH、终端、SFTP 和标签页核心。
2. 不安装服务器常驻 Agent、守护进程或监控探针。
3. 不自动安装 `tcpdump`、`sysstat`、数据库客户端等缺失依赖。
4. 不承诺任意用户脚本、任意数据库写入、磁盘格式化或软件升级可自动回滚。
5. 首期不实现多服务器并行修改，仅允许多服务器只读巡检。
6. 不让 AI 直接生成自由 Shell 后绕过脚本注册、安全分类和用户确认。
7. 不在首期提供完整作业编排、定时任务平台或远程配置管理系统。

## 4. 产品信息架构

顶部主入口由“快捷命令”改为“运维工具”。工作区内部固定为五个页签：

| 页签 | 职责 | 典型内容 |
| --- | --- | --- |
| 快捷操作 | 单步骤、短时、原子操作 | 查看端口、查询服务、重启单个服务、复制路径 |
| 诊断脚本 | 多步骤、只读、产生综合结论 | UDP 综合检测、Nginx 故障诊断、磁盘 I/O 分析 |
| 维护脚本 | 会修改状态的受控工作流 | 修改网络、调整防火墙、日志轮转、服务开机策略 |
| 我的工具 | 用户保存的参数预设和经审核自定义工具 | 常用业务域名检测、固定服务组巡检 |
| 执行记录 | 统一显示当前任务和历史任务 | 进度、输出、报告、备份和回滚入口 |

### 4.1 单一主入口规则

每项能力只能有一个主要入口：

- 只执行一条短命令且无需汇总时，保留为“快捷操作”。
- 需要两个及以上步骤、环境识别、条件分支或结果汇总时，归入“诊断脚本”。
- 会修改文件、系统状态、服务、网络、防火墙或计划任务时，归入“维护脚本”。
- 被迁移为脚本的旧快捷命令从目录中隐藏，但保留原 ID、收藏和历史记录兼容映射。
- AI、服务器状态和安全中心可以深链到同一工具定义，不复制实现。

### 4.2 工作区布局

运维工具打开后占用终端下方的可拉伸区域，右侧 AI 助手保持原位置：

- 顶部：页签、搜索、分类、风险筛选、当前服务器和关闭按钮。
- 左侧：工具目录或当前任务步骤。
- 右侧：参数表单、实时输出、结构化结果或执行报告。
- 任务运行时显示“取消任务”“查看实际命令”“复制到终端”“在终端继续”。
- 1366×768 使用两栏紧凑布局和纵向滚动，不依赖横向滚动。
- 1920×1080 可加宽结果区，但不改变操作顺序。
- 日间、夜间主题均使用现有 ShellPilot 设计令牌，不新建独立配色体系。

## 5. 架构设计

### 5.1 复用现有能力

运维工具必须复用以下现有层，不建立平行实现：

- 快捷命令领域模块与稳定命令 ID。
- `shared/definition.js` 的定义规范。
- `shared/validation.js` 的参数校验。
- `shared/command-builders.js` 的安全命令构建。
- `shared/safety-metadata.js` 的风险、备份、验证和回滚元数据。
- `quick-command` store 的任务和历史能力。
- 安全操作中心的事务记录、立即回滚和保留修改能力。
- 现有 SSH 连接、凭据、安全存储、日志和端点匹配机制。

新增代码只负责脚本目录、步骤编排、能力探测、后台执行适配、结果解析和工作区界面。

### 5.2 模块边界

```text
src/client/components/operations-toolkit/

```

各模块职责：

- `catalog`：只声明工具元数据、步骤、参数、兼容条件和结果结构。
- `forms`：根据定义生成中文表单，自动填充已识别资源。
- `task-controller`：管理前端状态、取消、重试和任务恢复提示。
- `ssh-task-channel`：使用当前端点凭据建立独立 SSH 执行通道。
- `task-runner`：顺序执行步骤、处理超时、条件分支和安全事务。
- `capability-discovery`：识别系统、工具、服务、网卡、容器和平台。
- `task-records`：保存脱敏的任务、步骤、结果、备份和回滚关联。

所有工具使用注册定义，不允许界面直接拼接任意 Shell：

定义加载时必须校验 ID 唯一、参数已声明、风险分类完整、修改工具具有恢复提供器、输出解析器存在且旧 ID 不冲突。

## 6. 执行模型

### 6.1 专用后台 SSH 通道

脚本默认不写入当前交互终端，而是：

1. 读取当前标签页端点和已解锁凭据。
2. 建立独立 SSH exec 通道。
3. 运行能力探测和脚本步骤。
4. 将 stdout、stderr 和结构化事件实时回传任务面板。
5. 完成后关闭通道并清理临时文件。

这保证脚本运行时用户仍可操作主终端。需要密码输入、确认提示、全屏 TUI 或持续交互的步骤不在后台执行，改为“复制到终端”或“在终端继续”。

### 6.2 临时脚本

- 简短步骤直接通过受控命令构建器执行。
- 多步骤流程写入 `~/.shellpilot/tasks/<task-id>/run.sh`，权限为 `700`。
- 任务清单、参数和结果文件权限为 `600`。
- 只读任务结束后立即清理远端临时目录。
- 维护任务的恢复点移入现有安全事务目录，临时运行文件清理，备份按安全中心策略保留。
- 不使用 `/tmp` 保存长期恢复点，避免重启或系统清理后丢失。

### 6.3 状态机

```text
created
  -> discovering
  -> ready
  -> awaiting-confirmation
  -> running
  -> verifying
  -> completed

任意执行状态
  -> cancelling -> cancelled
  -> timed-out
  -> failed
  -> disconnected
  -> partially-completed
```

只读脚本从 `ready` 直接进入 `running`。维护脚本必须经过 `awaiting-confirmation`。任务进入终态后必须立即释放并发占用，不能继续在安全中心显示“执行中”。

### 6.4 并发、超时和输出

- 同一服务器最多同时运行 2 个只读任务。
- 同一服务器最多运行 1 个修改任务；修改任务与其他修改操作互斥。
- 默认诊断超时 60 秒，网络采样类 90 秒，维护任务 300 秒；定义可缩短但不得无限等待。
- 取消时先发送终止信号并关闭 exec 通道，2 秒后仍未结束则强制关闭通道。
- 界面使用虚拟滚动，最多保留 5000 行可见输出。
- 每步骤保存最多 256 KB 脱敏摘要；完整本地任务日志最多 20 MB，按工具日志策略轮转。
- 单任务达到限制时停止追加原始输出，但继续保存退出码、结论和截断标记。

## 7. 能力与平台识别

### 7.1 基础识别

每个端点在首次打开运维工具或用户点击“重新检测”时识别：

- `/etc/os-release`、内核、架构、虚拟化和容器环境。
- `systemd`、OpenRC、SysV init。
- `apt`、dnf、yum、zypper。
- `ip`、ss、netstat、lsof、tcpdump、ncat、dig、nslookup、curl、openssl。
- 活动网卡、地址、路由、DNS 和 MTU。
- systemd 服务、容器、监听端口和进程。
- Nginx、Apache、Docker、Podman、数据库和语言运行时。

探测结果以端点为单位缓存 5 分钟；涉及服务、网卡和容器选择的表单允许立即重新检测。

### 7.2 发行版兼容

| 系列 | 发行版 | 首选适配 |
| --- | --- | --- |
| Debian | Ubuntu、Debian、UOS Server | apt、systemd、`/var/log/auth.log` |
| RHEL | CentOS、RHEL、Rocky、AlmaLinux | dnf/yum、systemd、`/var/log/secure` |
| openEuler | openEuler、EulerOS | dnf/yum、systemd、firewalld |
| Anolis | Anolis OS、Alibaba Cloud Linux | dnf/yum、systemd、firewalld |
| 国产桌面/服务器 | KylinOS Advanced Server | 根据 `/etc/os-release` 映射 Debian 或 RHEL 兼容层 |
| 云厂商 | TencentOS Server | yum/dnf、systemd、firewalld |

兼容等级：

- A：已有自动化测试和真实只读回归。
- B：使用已验证的兼容族命令，结果中显示“兼容模式”。
- C：仅提供 POSIX 降级步骤，并明确列出不可用能力。

工具缺失时优先使用安全降级命令；无可靠替代时显示缺失原因和手动安装建议，不自动安装。

### 7.3 平台软件识别

环境探测识别但不修改以下平台：

- 宝塔面板、1Panel。
- Docker Compose 项目。
- Java/JVM、PHP-FPM、Node.js/PM2、Python/Gunicorn/Uvicorn。
- MySQL/MariaDB、PostgreSQL、Redis、MongoDB。
- Nginx、Apache、HAProxy。

识别来源包括服务名、进程、监听端口、已知配置目录和容器标签。结果必须标明“确定”“推测”或“无权限确认”，不得只凭端口断言已安装。

## 8. 安全模型

### 8.1 风险分级

| 级别 | 说明 | 交互 |
| --- | --- | --- |
| 只读 | 不改变系统、文件或服务状态 | 直接执行，不确认 |
| 可恢复修改 | 有明确目标、可创建并验证恢复点 | 展示变更和恢复点后确认一次 |
| 高风险修改 | 可能断开 SSH、影响访问或业务 | 恢复点验证后进行醒目的二次确认 |
| 不可自动恢复 | 无可靠恢复提供器或目标不唯一 | 默认禁止自动执行，只允许复制命令并显示风险 |

读取文件、查询、搜索、切换目录、查看日志、服务状态和端口状态均不得被误判为修改操作。

### 8.2 维护事务

维护脚本固定执行：

```text
环境预检
  -> 参数校验
  -> 展示实际变更
  -> 检查磁盘和权限
  -> 创建并验证恢复点
  -> 用户确认
  -> 执行修改
  -> 健康验证
  -> 等待“保留修改”或“立即回滚”
```

恢复点创建或验证失败时不得执行修改。网络、SSH、防火墙和服务停止操作必须保留额外控制台回退提示。安全中心使用现有按钮式“立即回滚”，不要求用户复制回滚命令。

### 8.3 参数安全

- IP、CIDR、端口、服务名、容器名、域名、路径和时间表达式分别使用类型化校验器。
- Shell 参数必须由命令构建器引用，禁止把未验证输入插入模板。
- 工具定义不得使用 `eval`、隐式 `source`、未约束通配符或动态下载执行。
- 日志默认脱敏密码、私钥、API Key、Token、Cookie 和认证 Header。
- AI 只能收到用户选定的脱敏结果和必要上下文。

## 9. 工具目录

首轮目录共 52 项脚本能力，另保留现有原子快捷操作。分阶段交付可以控制风险，但最终目录和稳定 ID 在首轮设计中一次确定。

## 10. UDP 综合检测设计

UDP 检测是脚本化能力的基准案例，参数表单包含：

- 检测方向：本机监听、远程目标、双向验证。
- 目标 IP 或域名。
- UDP 端口。
- 网卡：自动识别后下拉选择，默认活动路由网卡。
- 超时和尝试次数。
- 抓包开关、抓包数量和保存路径。
- 可选源 IP、目标 IP 和端口过滤。

执行步骤：

1. 检查目标格式、网卡和必要权限。
2. 使用 `ss` 或 `netstat` 检查本机监听。
3. 读取 firewalld、ufw、iptables 或 nftables 相关规则。
4. 使用可用的 `ncat`、`nc` 或受控报文方式进行远程探测。
5. 可选使用 `tcpdump` 验证是否实际收到报文。
6. 汇总为“已确认可达”“已确认阻断”“收到但应用未响应”“无响应，无法仅凭 UDP 判定”“工具缺失”。

UDP 无响应不得直接显示为“端口关闭”。抓包文件默认保存在用户指定目录或 `~/.shellpilot/captures/`，界面提供 SFTP 定位和下载入口。

## 11. AI 协同

- 任务完成后提供“交给 AI 分析”，发送结构化结论、失败步骤和用户选定输出。
- AI 可以推荐已注册工具，但不能直接执行未注册自由脚本。
- AI 推荐只读工具时可由用户点击后直接执行，不再二次确认。
- AI 推荐维护工具时必须打开对应表单并走安全事务流程。
- 输出进入模型前按总字符、单步骤和附件大小限制截断，并保留“内容已截断”说明。
- AI 生成的建议与实际工具结果分开显示，避免将推测标记成服务器事实。

## 13. 错误与降级

- 未连接服务器：禁用执行，保留工具浏览和参数预设。
- 凭据不可用：提示重新解锁或连接，不降级到主终端注入。
- 能力探测失败：显示失败步骤和原始错误摘要，允许重试。
- 工具缺失：使用可靠降级方案；否则显示安装建议，不自动安装。
- 权限不足：停止对应步骤，说明所需权限，不猜测 sudo 密码。
- SSH 中断：任务进入 `disconnected` 或 `partially-completed`，立即释放运行槽位。
- 取消失败：强制关闭专用通道并标记实际状态，不显示为完成。
- 维护验证失败：保留恢复点，并在安全中心突出“建议立即回滚”。
- 模块按需加载失败：显示“重新加载运维工具模块”，不得导致客户端白屏。
- 错误界面只显示错误编号和可复制诊断摘要，不展示本地绝对路径、密钥或完整堆栈。

## 14. 性能约束

- 运维工具目录和工作区按需加载，不进入终端首屏主包。
- 未打开运维工具时不执行远端探测、不建立额外 SSH 通道。
- 单次能力发现目标在 3 秒内返回首批结果，慢项异步补充。
- 普通终端首个可用时间相对当前基线回退不超过 100 毫秒。
- 客户端空闲内存不因运维工具增加超过 20 MB。
- 任务面板长输出使用虚拟滚动，持续运行 30 分钟不产生无界内存增长。

- 专用通道执行不污染主终端输入和 Ctrl+C。

### 15.4 真实服务器回归

真实服务器默认仅执行只读诊断：

- AI 分析只发送脱敏结果。
- 修改工具只验证参数、命令预览、备份预检和回滚脚本生成，不在生产服务器执行网络、SSH、防火墙和删除类变更。

修改和回滚完整链路在隔离虚拟机或容器测试环境执行。

## 17. 验收标准

1. 顶部显示“运维工具”，内部五个页签可用。
2. 相同能力在目录中只出现一次，旧收藏和历史仍可打开。
3. 只读脚本不弹出确认，修改脚本不能绕过恢复点和确认。
4. 脚本运行时主 SSH 终端可继续输入和使用 Ctrl+C。
5. 任务可取消、可超时，结束后立即允许下一任务执行。
6. UDP 检测不会把无响应错误地判定为端口关闭。
7. 服务、网卡、容器和平台软件可自动识别并供用户选择。
8. 受支持修改在安全中心具有可用的“立即回滚”按钮。
9. 国产系统至少进入明确的 A、B 或 C 兼容模式，不静默执行错误命令。
10. 1366×768 和 1920×1080 下无文字挤压、遮挡或依赖横向滚动的问题。
11. 运维工具模块失败不会造成客户端白屏。
12. 普通 SSH、SFTP、AI、更新和现有安全中心回归无退化。
13. 代码、日志、报告和测试资产不包含服务器密码、私钥或模型 API Key。
14. 本地打包版本与源码版本一致，未经确认不发布在线更新。
