# ShellPilot 任务可靠性与统一恢复中心设计

**日期：** 2026-07-28  
**目标版本：** 0.4.18 本地候选  
**状态：** 已确认采用方案 B，待实施

## 1. 目标

在不改变 SSH 终端核心输入、连接和快捷键行为的前提下，为以下能力建立统一、可恢复、可观察的运行基础：

1. SFTP 上传、下载、目录及批量任务显示准确进度，并支持暂停、继续、重试和跨客户端重启续传。
2. SSH 隧道显示实时健康状态，保存有限的断线与重连记录。
3. AI 修改多个远程文件时，在执行前提供统一差异审查和逐文件选择。
4. 安全中心集中展示快捷命令、AI 文件修改、SFTP 备份和手动备份，并提供快捷回滚。

本轮不在服务器安装常驻 Agent，不改变现有 SSH/SFTP 协议，不把终端核心拆分为按需模块。

## 2. 设计原则

- **终端优先：** 普通 SSH 会话不创建传输或安全任务时，不产生额外轮询。
- **失败可见：** 不把失败、部分完成或未知结果显示为成功。
- **恢复前校验：** 续传和回滚都必须验证服务器身份、目标路径和内容指纹。
- **原子提交：** 上传和下载先写临时文件，完成校验后再替换最终文件。
- **数据有界：** 进度事件、隧道历史、任务记录和审计输出均设置数量及体积上限。
- **模块隔离：** SFTP、隧道、AI 审查和安全中心通过统一记录接口协作，不直接互相调用 UI。

## 3. 架构

新增一个轻量的客户端任务记录层，统一保存任务元数据和状态变化。实际执行仍由现有模块负责：

- `TransferTaskAdapter`：连接现有 SFTP 传输组件和服务端流。
- `TunnelHealthAdapter`：连接现有 SSH 隧道运行时。
- `AiFileChangeReviewAdapter`：聚合现有单文件差异和恢复事务。
- `SafetyRecordAdapter`：将现有安全事务及历史备份映射到统一视图。

统一记录层只保存可序列化信息，不保存流、Socket、SFTP 客户端、React 实例或函数，避免对象克隆和状态恢复错误。

### 3.1 统一任务记录

每个任务至少包含：

```js
{
  schemaVersion: 1,
  id: 'stable-task-id',
  type: 'sftp-upload',
  status: 'paused',
  endpoint: {
    host: 'example.com',
    port: 22,
    username: 'root',
    bookmarkId: 'bookmark-id'
  },
  source: {
    path: 'C:\\logs\\app.log',
    size: 1048576,
    modifiedAt: 1785000000000,
    fingerprint: 'sha256:...'
  },
  target: {
    path: '/var/tmp/app.log',
    temporaryPath: '/var/tmp/.app.log.shellpilot-part-...'
  },
  progress: {
    transferredBytes: 524288,
    totalBytes: 1048576,
    bytesPerSecond: 262144,
    estimatedSecondsRemaining: 2
  },
  retry: {
    attempt: 1,
    maxAttempts: 3
  },
  createdAt: '2026-07-28T00:00:00.000Z',
  updatedAt: '2026-07-28T00:00:02.000Z'
}
```

禁止把密码、私钥正文、API Key、文件正文和完整终端输出写入任务记录。

## 4. SFTP 传输

### 4.1 进度显示

传输面板对单文件、文件夹和批量任务统一显示：

- 文件名和方向。
- 已传大小与总大小。
- 百分比进度条。
- 当前速度。
- 预计剩余时间。
- 当前状态：等待、校验、传输中、暂停中、已暂停、重试中、已完成、失败、已取消。
- 暂停、继续、取消和重试按钮。

文件夹任务同时显示总文件数、已完成文件数、失败文件数和当前文件。批量任务提供汇总进度，但每个子任务仍保留独立状态。

进度事件最多每 200 毫秒更新一次 UI；持久化最多每 2 秒或每增加 4 MiB 写入一次，避免频繁写数据库。

### 4.2 会话内暂停与继续

暂停分为两步：

1. 标记任务为 `pausing`，停止读取新的数据块。
2. 当前写入操作稳定后保存偏移量，状态变为 `paused`。

继续时从已确认的偏移量恢复。任务还未真正暂停时，按钮显示“暂停中”，不允许重复操作。

### 4.3 跨重启续传

客户端启动后，将未完成任务恢复为 `interrupted`，不会自动连接服务器或自动发送数据。用户点击“继续”后：

1. 找到原服务器书签或相同的主机、端口和账号。
2. 建立新的 SSH/SFTP 会话。
3. 校验源文件大小、修改时间和首尾分块 SHA-256。
4. 校验临时目标文件大小不超过源文件，且已上传或下载部分的边界指纹一致。
5. 校验通过后从临时文件长度继续；校验失败时保留临时文件并提示“重新开始”或“另存为”。

上传临时文件位于目标文件同目录，名称带 ShellPilot 任务标识。下载临时文件位于最终文件同目录，扩展名为 `.shellpilot-part`。完成后先校验大小和最终指纹，再原子重命名。

FTP 或不支持可靠偏移写入的服务端只支持会话内暂停；界面明确显示“不支持跨重启续传”。

### 4.4 取消与清理

- 取消不会默认删除临时文件，用户可选择“保留以便继续”或“删除临时文件”。
- 已完成任务清除临时文件和续传元数据。
- 超过 7 天的中断任务进入“待清理”，用户确认后删除临时文件。
- 清理失败会保留任务记录和错误信息，不显示为已清理。

## 5. SSH 隧道健康状态

### 5.1 状态模型

隧道状态包括：

- `starting`
- `healthy`
- `reconnecting`
- `port-conflict`
- `session-lost`
- `stopped`
- `failed`

健康状态由以下信息确定：

- SSH 会话是否存活。
- 本地监听端口是否仍由当前隧道占用。
- 隧道控制器是否仍存在。
- 最近一次连接或转发错误。

不通过主动访问远端业务端口进行健康探测，避免产生业务流量。

### 5.2 断线与重连记录

每个隧道保存最近 50 条事件：

```js
{
  type: 'reconnect-failed',
  timestamp: '2026-07-28T00:00:00.000Z',
  attempt: 2,
  reason: 'SSH session closed'
}
```

界面显示运行时长、重连次数、最近断线时间、最近错误和监听地址。提供“立即重连”“停止”“复制诊断信息”操作。

自动重连采用有界退避：1 秒、3 秒、10 秒，最多 3 次。超过次数后进入 `failed`，必须由用户手动重连。

## 6. AI 多文件差异审查

### 6.1 审查模型

AI 准备创建、修改或删除多个远程文件时，先生成只读变更集：

```js
{
  id: 'change-set-id',
  endpoint: {},
  files: [
    {
      path: '/etc/nginx/nginx.conf',
      action: 'modify',
      selected: true,
      beforeFingerprint: 'sha256:...',
      afterFingerprint: 'sha256:...',
      preview: {}
    }
  ]
}
```

变更集不包含密码或无限制文件正文。单文件预览沿用现有有界读取和差异算法。

### 6.2 用户界面

- 左侧按目录显示文件列表和新增、修改、删除标识。
- 右侧显示当前文件的逐行差异、大小变化和截断提示。
- 用户可逐文件勾选，默认不勾选无法预览或指纹变化的文件。
- 执行按钮显示将修改、创建和删除的文件数量。
- 删除文件使用独立高风险颜色和二次确认。

### 6.3 执行与恢复

执行前为所有选中文件创建一个安全事务和逐文件恢复点。执行时再次校验原文件指纹：

- 全部成功：记录为 `rollbackAvailable`。
- 部分成功：停止后续操作，保留已成功文件的恢复点，记录为 `partiallyCompleted`。
- 校验冲突：不写入冲突文件，要求重新生成差异。

安全中心提供“恢复全部”和“选择文件恢复”。恢复前同样检查当前内容，防止覆盖用户后续修改。

## 7. 统一安全中心

### 7.1 数据来源

安全中心统一读取：

- 现代安全事务记录。
- 旧版快捷命令回滚记录。
- SFTP 备份和删除恢复记录。
- AI 多文件变更事务。
- 用户手动创建的 SFTP 文件或文件夹备份。

旧记录只做兼容映射，不修改或删除原始数据。

### 7.2 页面结构

页面分为：

1. **执行中：** 当前诊断、修改、传输和回滚任务。
2. **可恢复：** 恢复点完整且校验通过的操作。
3. **历史记录：** 已恢复、已保留、已完成和失败操作。
4. **旧版记录：** 无法完整验证的兼容记录。

每条记录显示服务器、操作类型、目标对象、备份位置、创建时间、最后状态、验证结果和操作链路编号。

快捷操作包括：

- 回滚。
- 选择文件回滚。
- 保留新版本并撤销自动回滚。
- 打开本地目录或在 SFTP 中定位远程目录。
- 复制脱敏诊断信息。

回滚按钮只有在恢复点结构、服务器身份和内容校验均通过后才可用。

## 8. 错误处理

- 客户端异常退出后，运行中的传输变为 `interrupted`，不会显示为失败或完成。
- SSH 断线不会删除传输或隧道历史。
- 数据库写入失败时，当前传输可以继续，但界面明确提示“无法保存续传状态”。
- 任务记录损坏时隔离该记录，其他任务仍可正常加载。
- 跨重启续传发生源文件变化时，禁止继续原任务。
- 安全中心恢复点校验失败时禁用回滚，并保留可复制的错误编号。
- 所有用户可见错误使用中文，日志保存脱敏后的技术原因和操作链路编号。

## 9. 性能与容量

- 默认最多并发 3 个实际传输任务。
- 单个目录任务默认最多记录 10,000 个子文件结果，超出时汇总显示。
- 最多保留 200 条传输历史、200 条安全记录和每个隧道 50 条事件。
- 任务记录按需加载；未打开传输或安全中心时不渲染明细。
- 进度条只更新变化的任务行，不重绘完整列表。

## 10. 兼容与迁移

- 保留现有 `fileTransfers`、安全事务和旧版 SFTP 恢复记录读取能力。
- 新字段缺失时使用安全默认值，不要求用户清理旧配置。
- 0.4.17 任务没有续传信息时显示“可重新开始”，不尝试猜测偏移量。
- 更新或回退客户端版本时不自动删除临时文件和恢复记录。

## 11. 实施阶段

### 阶段一：SFTP 任务可靠性

完成进度、会话内暂停、跨重启续传、任务持久化和真实服务器传输测试。

### 阶段二：隧道健康状态

完成状态模型、断线事件、有界重连和界面展示。

### 阶段三：AI 多文件审查

完成变更集、逐文件差异、批量恢复点和部分失败处理。

### 阶段四：统一安全中心

完成所有记录来源整合、筛选、快捷回滚和审计信息。

每个阶段都必须可独立构建、测试和回退，不允许依赖后续阶段才能正常使用。

## 12. 验收标准

### SFTP

- 传输 1 GiB 文件时进度单调递增，速度和剩余时间不出现负数或 `NaN`。
- 上传和下载暂停后 2 秒内进入已暂停状态。
- 关闭客户端并重新打开后，任务显示为已中断；重新连接后可以从正确偏移继续。
- 修改源文件后继续任务会被阻止，不覆盖目标文件。
- 文件夹和批量任务能显示成功、失败和当前文件数量。

### SSH 隧道

- SSH 会话关闭后隧道在界面显示断开，并产生断线记录。
- 自动重连不超过 3 次，端口冲突不会反复重试。
- 手动重连成功后状态恢复为健康。

### AI 多文件修改

- 至少 20 个文件的变更集可以流畅浏览和选择。
- 未选文件不会被修改。
- 原文件在审查后发生变化时执行被阻止。
- 部分失败后能恢复已经修改成功的文件。

### 安全中心

- 快捷命令、AI 修改、SFTP 备份和手动备份均可检索。
- 可恢复项显示有效回滚按钮，完整性失败项禁止回滚。
- 回滚后状态、审计日志和服务器实际内容一致。

### 回归

- SSH 终端输入、Ctrl+C、标签页、SFTP 基本操作和在线更新现有测试全部通过。
- Windows 1366×768、1920×1080、125% 和 150% 缩放下按钮及文字不重叠。
- 日间和夜间主题下进度、告警和禁用状态均清晰可读。
