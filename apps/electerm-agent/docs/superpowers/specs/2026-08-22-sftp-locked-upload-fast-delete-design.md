# SFTP 锁定文件上传与快速删除设计

## 背景与根因

ShellPilot v0.4.40 在 Windows 用户目录上传文件时，可能收到 `EBUSY: resource busy or locked, open ...`。已在 Windows 上复现：`NTUSER.DAT`、`ntuser.dat.LOG1` 等系统文件被操作系统独占锁定，Node.js 普通只读打开同样返回 `EBUSY`。错误发生在本地上传源摘要扫描或实际读取阶段，不是远端目录权限问题。

现有远程删除默认走安全事务。删除前会逐项创建、校验恢复快照，再显示确认并执行删除。该流程适合可恢复操作，但对明确不需要恢复的临时文件或大目录响应过慢。

## 目标

- Windows 本地文件因 `EBUSY`、`EACCES` 或 `EPERM` 无法读取时，跳过该文件并继续上传其余可读内容。
- 单文件、多选文件和目录上传采用一致的跳过规则。
- 上传完成后只显示一条汇总，列出成功、跳过和失败数量，并允许查看跳过项。
- 远程文件右键菜单新增“快速删除（不可恢复）”，一次确认后直接执行，不创建快照或恢复记录。
- 批量快速删除限制并发、只刷新一次，并准确报告部分失败。
- 保留现有安全删除、恢复中心和键盘 Delete 行为。

## 非目标

- 不使用卷影复制、备份权限或管理员提升读取 Windows 独占锁定文件。
- 不把网络错误、远端权限错误、摘要变化、符号链接、特殊文件或扫描预算超限降级为跳过。
- 不把快速删除设为默认删除方式，不改变 AI/MCP 安全删除策略。
- 不允许快速删除 ShellPilot 的事务恢复目录。

## 方案选择

采用“受控跳过 + 独立快速删除”方案。

相比只修改错误提示，该方案可以让包含系统锁定文件的批量或目录上传继续完成。相比 Windows 卷影复制，该方案不需要管理员权限或平台专用服务。快速删除与安全事务完全分流，既保留现有可恢复路径，也为明确接受不可恢复风险的用户提供低延迟路径。

## 上传架构

### 本地源计划

在主进程文件系统层增加可序列化的本地源计划接口。输入为上传根路径，输出为：

```js
{
  descriptor: {},
  skipped: [
    {
      path: 'C:\\Users\\example\\NTUSER.DAT',
      relativePath: 'NTUSER.DAT',
      code: 'EBUSY',
      reason: 'locked'
    }
  ]
}
```

`descriptor` 继续使用现有摘要、大小、类型和有序目录树格式，但只包含本次允许上传的条目。`skipped` 只记录本地展示所需信息，不进入远程安全事务的内容摘要。

扫描规则：

- 文件读取或目录枚举返回 `EBUSY`、`EACCES`、`EPERM` 时，将该文件或目录子树记录为跳过。
- 顶层源本身不可读时，`descriptor` 为 `null`，该传输不创建远程目标。
- 子项不可读时，从描述树中排除该项，继续扫描同级内容。
- 符号链接、特殊文件、摘要期间发生变化、节点/深度/总字节/清单大小超限仍然失败关闭。
- 路径对比在 Windows 上按规范化绝对路径处理，展示时使用相对路径，错误通知不泄露无关的完整路径。

### 传输约束

渲染进程把源计划绑定到传输项。目录递归上传不再把实时目录列表当作无条件输入，而是以已验证的 `descriptor` 目录树作为允许列表：

- 只传输描述树中存在的文件和目录。
- 跳过项中途解锁也不会未经本次摘要校验加入上传。
- 传输完成后的源验证使用同一跳过集合重新扫描允许项；描述发生变化时仍按现有安全失败处理。
- 顶层跳过任务以 `skipped` 终态结束，不启动远程上传、不创建 `.part` 文件、不准备恢复事务。
- 目录中部分跳过不影响可读文件的远程安全事务；事务预期描述只绑定实际上传内容。

### 汇总与历史

每个传输记录增加受限的跳过结果：相对路径、错误代码和原因。批次完成后聚合显示一条提示：

> 上传完成：成功 28 项，跳过 2 个被占用文件。

跳过项可在传输详情或历史中展开查看。相同错误不再同时通过传输错误和全局错误产生重复通知。若同一批次还存在真正失败，则提示“部分完成”，并分别展示跳过与失败数量。

## 快速删除架构

### 菜单与确认

远程真实文件或目录的右键菜单保留“安全删除（可恢复）”，并在其附近新增危险项“快速删除（不可恢复）”。多选时显示数量。

点击快速删除后立即显示一次红色确认框，明确说明：

- 删除后无法从安全操作中心恢复；
- 不创建备份或恢复快照；
- 当前将永久删除的文件/目录数量。

取消确认时不执行任何远端操作。键盘 Delete、现有“删除”入口及 AI/MCP 删除继续走安全删除。

### 执行与性能

快速删除使用独立的 `quickDeleteRemoteFiles` 路径，不调用 `prepareSftpSafetyOperation`、`sftpSafetyRunner` 或恢复记录存储。

- 普通文件直接调用 SFTP `rm`/`unlink`。
- 目录调用现有经过参数转义的 `rmdir` 快速路径；远端不支持命令执行时沿用纯 SFTP 递归回退。
- 多选目标最多并发 4 项，防止压垮单个 SSH/SFTP 会话。
- 使用 `Promise.allSettled` 保留逐项结果；一个失败不会停止其余已确认项。
- 删除结束后取消选择并只刷新一次远程列表，不保留现有固定 500ms 延迟。
- 全部成功显示一次成功消息；部分失败显示成功/失败数量及失败项；全部失败显示一次错误消息。

### 保护规则

快速删除在确认前验证全部目标。下列目标拒绝执行：

- `/` 根目录；
- `..` 父目录项、空白占位项或非远程项；
- 任意路径段为 `.shellpilot-transactions` 的 ShellPilot 恢复存储；
- 规范化后逃逸或无法确定为绝对远程路径的目标。

验证失败时整批不执行，避免用户确认内容与实际删除集合不一致。

## 错误处理

- 可跳过本地错误仅限 `EBUSY`、`EACCES`、`EPERM`，并保留原始错误代码用于详情。
- 上传网络断开、目标权限失败、远程空间不足及安全校验失败仍进入现有失败和重试流程。
- 快速删除出现部分失败时不伪造回滚；成功项保持已删除，失败项经单次刷新重新显示。
- 组件卸载或会话取消时，不再启动新的删除项；已进入的原子 SFTP/远端命令等待返回并纳入结果。
- 所有面向用户的新增文案提供中文与英文覆盖。

## 测试策略

### 单元与集成测试

- 本地源计划跳过顶层及嵌套的 `EBUSY`、`EACCES`、`EPERM` 项。
- 不可跳过错误、符号链接和预算超限继续失败。
- 描述树不包含跳过项，目录传输只消费描述树允许项。
- 跳过项中途解锁不会进入当前传输；允许项变化会触发完整性失败。
- 顶层跳过不会准备安全事务或创建远端目标。
- 批次汇总只产生一次通知，并区分成功、跳过和失败。
- 菜单同时显示安全删除和快速删除，快速删除标记为危险且支持多选数量。
- 快速删除只确认一次、不调用安全事务、并发上限为 4、仅刷新一次。
- 部分失败保留逐项结果；受保护路径在任何删除调用前被拒绝。

### Electron 回归

- 使用 Windows 锁定文件测试替身和普通文件组成上传批次，确认普通文件成功、锁定文件被跳过、进度坞正常结束且只有一条汇总。
- 使用本地 SSH/SFTP fixture 验证单文件、目录和多选快速删除。
- 验证原有安全删除仍创建可恢复记录，并可从安全操作中心恢复。
- 验证键盘 Delete 仍进入安全删除确认。

## 验收标准

- 截图场景中的锁定文件不再产生重复 `EBUSY` 错误通知，其余选中内容继续上传。
- 目录上传包含锁定项时不会把未摘要校验内容上传到远端。
- 右键菜单能明显区分“安全删除（可恢复）”与“快速删除（不可恢复）”。
- 快速删除在确认前不做远程快照，确认后直接执行，批量操作只刷新一次。
- 现有上传完整性、传输进度、安全删除和恢复测试保持通过。
