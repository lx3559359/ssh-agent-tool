# 运维工具第二阶段：安全维护设计

## 目标

在现有“运维工具”工作区中加入可直接使用的安全维护入口，同时复用已经过验证的快捷命令事务执行器、安全操作中心和服务器端回滚脚本，不复制 SSH、SFTP 或命令执行核心。

## 范围

- “安全维护”只展示会修改服务器且具备完整安全契约的内置动作。
- 每个动作必须同时具备表单化参数、明确确认、回滚定义、安全元数据和执行后校验。
- 修改操作继续走现有事务执行器，生成安全操作记录并可从安全中心一键回滚。
- 只读诊断继续由独立后台任务运行，不增加确认。
- 本阶段不开放任意自定义脚本，不改变普通终端命令的交互方式。

## 首批维护动作

- 修改服务器 IP
- 放行或收回防火墙端口
- 服务启停、重启、重载和开机策略
- Docker 容器启停与重启
- 文件权限和归属
- 主机名、时区、Swap、hosts、Cron

## 安全边界

安全维护目录通过统一筛选器建立白名单。缺少以下任一能力的动作都不会出现在页面：

1. `mutatesServer`
2. `editBeforeRun`
3. `confirmRequired`
4. `rollback`
5. `safetyMetadata`
6. 至少一个执行后校验命令

网络等高风险操作继续使用原有自动回滚保护。安全中心仍是唯一的恢复记录入口，避免产生两套状态。

## 界面

“安全维护”页顶部展示三项固定保障：修改前保护、执行后校验、安全中心回滚。下方沿用成熟的表单和命令预览组件，但只展示通过安全契约校验的维护动作。

## 验证

- 单元测试验证目录不会接纳缺少安全能力的动作。
- E2E 验证未连接状态可浏览、维护动作数量正确、安全中心入口可用。
- 回归现有运维工具、快捷命令、安全事务、SSH 和 SFTP 测试。
