## 发现并修复的问题

### R2-01：设置、弹窗和抽屉的背景仍可能进入读屏/键盘路径

- 根因：嵌套 portal 与多层弹窗关闭时的隔离恢复没有统一按前景层级计算。
- 修复：按实际前景 workspace/portal 维护背景隔离，稳定 Drawer/Modal 回调引用，并在关闭后恢复触发按钮焦点。
- 验证：设置、主题、服务器状态、AI 配置反复打开关闭回归通过；背景节点不可交互，前景对话框保持可访问。

### R2-02：快速连接、设置搜索和服务器状态的焦点路径不完整

- 根因：快速连接打开后依赖浏览器默认焦点；设置搜索的 Escape 事件与抽屉关闭事件存在竞争；服务器状态关闭后没有稳定恢复入口焦点。
- 修复：快速连接显式聚焦主机输入；搜索框优先消费首次 Escape；服务器状态和通用弹窗恢复触发按钮焦点。
- 验证：专项单元测试、质量 E2E 和 14 状态用户旅程均通过。

### R2-03：SFTP 键盘选择与前景快捷键委派不一致

- 根因：文件选择逻辑分散在行组件，键盘路径没有完全复用鼠标路径；全局快捷键可能委派到非前景工作区。
- 修复：抽取统一选择状态机，补齐方向键、范围选择和前景工作区判断；本地 SFTP 夹具补充目录长名称场景。
- 验证：SFTP 选择单元测试、连接态 SFTP 键盘证据和质量 E2E 通过。

### R2-04：英语短窗口 AI 配置和工具中心卡片横向溢出

- 根因：供应商名称、标签和工具元信息的 flex 子项缺少 `min-width: 0`、换行和容器约束。
- 修复：名称、标签、描述和元信息允许安全换行；卡片主区域限制最大宽度；列表阻止非预期横向滚动。
- 验证：AI 配置在 590×400、150% 下 `scrollWidth === clientWidth`；工具卡片在 1100 和 1600 宽度下均无越界元素或被截断标题。

### R2-05：Vite 开发态因 CommonJS 默认导出不匹配而白屏

- 首次实机证据：主文档空白，DevTools 报错 `parse-quick-connect.js does not provide an export named 'default'`。
- 根因：Node 单元测试会自动提供 CommonJS 默认互操作，但 Vite 开发服务器把应用源码作为原生 ESM 提供，不会合成该默认导出。
- 修复：规范解析器继续保持单一 CommonJS 实现，同时提供短生命周期浏览器桥接；渲染器改为副作用导入并在取用后删除桥接。
- 回归：先增加会失败的适配器契约测试，再修复至 11/11 通过；Vite 实机刷新后 ShellPilot 主界面成功加载；`npm run compile` 通过。

## Windows 实机可访问性复核

- 使用当前工作树源码和 Vite 开发服务器启动，不使用已安装旧版本。
- UI Automation 树能识别主工具栏按钮的名称，包括“快连”“运维工具”“SSH 隧道”“模型 API”“安全中心”“检查更新”“设置”和“帮助”。
- 设置界面暴露为具名 `对话框 设置`，包含“设置中心”标题、具名搜索组合框、语言组合框和“关闭”按钮。
- 快速连接浮层暴露具名主机、端口、用户名、密码和连接名称输入，以及“保存为连接”和“连接”操作。
- 实机截图显示输入焦点环和对话框背景遮罩正确；Playwright DOM 断言进一步验证初始焦点、Tab 顺序、Escape 分层处理与关闭后的焦点恢复。
- Electron 在本机 UI Automation 中会把部分 HTML 输入的 `focused_element` 回报为 `RootWebArea`，因此没有把该字段单独作为通过依据，也没有声称完成真实 Narrator 音频播报测试；读屏验收依据为 UIA 名称/角色树、DOM 可访问性契约和键盘行为三者组合。
