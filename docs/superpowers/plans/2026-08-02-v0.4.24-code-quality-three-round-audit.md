# ShellPilot v0.4.24 代码质量三轮自检计划

> **执行要求：** 按 `executing-plans` 逐项实施；每个行为修复先按 `test-driven-development` 写失败测试，遇到异常按 `systematic-debugging` 查根因，结束前按 `verification-before-completion` 提供新鲜验证证据。

**目标：** 在上一轮功能与需求核验的修正候选上，再做三轮面向可维护性的使用者自检，识别“屎山”风险，修复已经证实的重复实现、静默失败和脆弱测试，同时保持 v0.4.24 现有行为与 166 项需求结论不回退。

**原则：** 代码行数只是线索，不是缺陷。数据表、翻译表和协议目录可以很长；只有重复逻辑、高复杂度编排、隐式全局耦合、资源生命周期不清、吞错或无法行为测试的代码才进入高优先级。不得为追求指标进行大爆改；没有失败测试或明确行为收益的热点只登记债务和建议切分缝，不在本轮重写。

**当前基线：** 分支 `codex/self-audit-0.4.24`，起点 `ee6a1df`；上一轮完整测试为 3082 项（3076 通过、0 失败、6 跳过），需求矩阵为 159 满足、6 部分满足、1 废止。最新发布版仍是官方 v0.4.24，本轮只修改本地审计分支，不发布或覆盖历史资产。

## 轮次五：异步状态、错误可观测性与资源生命周期

### 任务 4：让崩溃恢复加载和忽略操作可行为测试

**创建：**

- `src/client/common/recovery/recovery-plan-operations.js`

**修改：**

- `src/client/store/load-data.js`
- `test/unit-ci/crash-recovery-ui.spec.js`

**TDD 步骤：**

1. 写失败测试覆盖：恢复计划加载成功、加载失败后安全降级并记录稳定事件、忽略持久化成功后才清理本地状态、忽略持久化失败时保留通知并返回原始错误。
2. 测试质量事件不得包含异常消息、路径、凭据或恢复内容，只允许稳定的 module/action/phase/result/messageCode。
