# ShellPilot v0.4.51 视觉门禁可靠性设计

> 本轮主要修正视觉测试的判定边界和测试前置条件；唯一获准的生产变更，是隔离关闭且保留挂载的右侧面板所造成的文档横向溢出。不得改变可见界面、交互、状态保留、性能策略或 SSH/SFTP/终端行为。

## 背景

v0.4.51 的单元测试、代码检查、生产构建、安全审计和关键 SSH/SFTP E2E 已通过。完整视觉矩阵仍报告四项失败，经隔离复测和页面几何诊断确认，它们来自三类测试假设：

- 在 590×400、175% 缩放下，顶栏操作轨道按设计横向滚动，通用文档溢出检测却把轨道中尚未滚入视口的按钮误判为整页溢出。
- 设置搜索测试在一个长场景中复用页面状态，紧凑布局断言偶尔继承前一阶段的展开状态；该用例隔离复测连续三次通过。
- UI 字体区域使用既有的延迟挂载策略，测试在字体区域进入视口前就断言 20 个选项已经存在。

专用顶栏测试已经验证操作轨道可通过键盘和滚轮到达、末端操作可用，且不会覆盖原生窗口控制区。因此本轮不重做顶栏布局，也不取消设置区的延迟挂载。

实施第 2 项时，聚焦用例越过原有文档溢出失败后又暴露一条更早遗留的断言：右侧面板关闭后仍要求 `.right-side-panel` 数量为 0。生产组件自 2026-08-21 起有意采用“首次打开后保留挂载、关闭时隐藏”的性能策略，现有单元契约也明确禁止关闭时卸载；因此这是此前被前置失败遮蔽的测试假设，不是新的生产回归。本规格按用户于 2026-09-04 确认的补充范围，纳入该测试断言的最小修正。

修正该断言后，聚焦用例继续执行并发现一项真实生产问题：在 590×400、175% 缩放的复杂紧凑状态链中，已关闭且保留挂载的右侧面板虽然满足不可见、`aria-hidden` 和 `inert`，其内部内容仍把 `documentElement` 从 337px 撑到 420px。该宽度在两帧、100ms 和 500ms 后均不收敛；临时只给 `.right-side-panel-hidden` 设置 `overflow: hidden` 时恢复为 337/337，移除后重新变为 420/337，且面板挂载和无障碍状态不变。用户于 2026-09-04 选择并确认最小生产修复方案，因此本规格增加一个精确的 CSS 例外。

## 目标

1. 让通用视觉基线区分整页横向溢出与顶栏操作轨道内的受控横向滚动。
2. 让紧凑设置搜索场景显式建立“搜索已收起”的测试前置条件。
3. 让字体生命周期场景通过真实滚动触发既有延迟挂载，再检查字体选项。
4. 保持原有可达性、无重叠、无裁切、字体预览/取消/保存及终端不受影响等断言不减弱。
5. 让视觉几何采样忽略由自身或祖先的透明/隐藏状态造成的不可见保留挂载节点，并验证右侧面板关闭后的真实隐藏契约。
6. 在不卸载右侧面板、不丢失内部状态的前提下，阻止关闭面板的后代参与文档横向 overflow 几何。

## 非目标与硬边界

- 除在 `src/client/components/side-panel-r/right-side-panel.styl` 的 `.right-side-panel-hidden` 中增加 `overflow hidden` 外，不修改 `src/` 下任何生产代码、样式或资源。
- 不改变顶栏布局、入口数量、入口名称、排序、隐藏规则或滚动方式。
- 不改变设置搜索的打开、关闭、键盘焦点或结果选择行为。
- 不改变设置分区延迟挂载、IntersectionObserver、帧调度或字体预览行为。
- 不改变右侧面板首次打开后保留挂载、关闭时隐藏的既有性能与状态保留策略。
- 不使用 `display: none`、条件卸载、宽度重写、位移到屏幕外或 store 状态重置来消除溢出。
- 不改变 SSH 登录、SFTP 身份、root 后端、终端输入、权限、安全确认、API 或快捷键。
- 不删除失败断言，不通过扩大通用容差、无条件忽略文档溢出或增加固定等待来换取通过。
- 不在本轮合并、推送、打标签或发布。

## 方案比较

### 方案 1：测试边界精确化（采用）

只调整 `test/e2e/022.secondary-ui-visual-matrix.spec.js` 及必要的测试契约。优点是生产行为零变化，能直接修复三类已定位的错误假设；缺点是受控滚动豁免必须足够严格，避免掩盖真实整页溢出。

### 方案 2：改变生产行为

可在设置关闭时强制收起搜索、提前挂载字体区域或重排顶栏。它会改变交互或性能策略，并扩大 SFTP 发布前的回归面，不符合本轮保守边界。

### 方案 3：豁免视觉矩阵

可把失败标记为允许失败后继续发布，但会削弱稳定版门禁，无法防止后续真实布局回归。

## 详细设计

### 1. 受控顶栏滚动判定

保留 `inspectDocumentBaseline()` 对 `documentElement`、`body`、应用根节点和屏幕外元素的采样。增加一个纯测试侧的判定/归一化步骤，仅在以下条件全部成立时，把由顶栏操作轨道产生的宽度差视为受控滚动：

1. 所有横向越界元素都位于唯一可见的 `.aigshell-topbar-actions` 内。
2. 操作轨道自身的左右边界位于当前视口内，且不进入 `.window-controls` 的矩形区域。
3. 操作轨道的计算样式 `overflow-x` 为 `auto` 或 `scroll`，并且 `scrollWidth > clientWidth`。
4. 除轨道内部后代外，没有其他可见元素越过视口右边界。
5. 既有专用测试继续验证键盘/滚轮可达、末端真实操作可用以及原生窗口控制区零命中。

该判定不扩大像素容差，也不允许任意滚动容器绕过基线。若任一条件不成立，仍按整页溢出失败，并输出原始节点宽度、越界元素和轨道几何用于诊断。

几何采样中的“可见元素”统一使用 `element.checkVisibility({ opacityProperty: true, visibilityProperty: true })`，并继续检查正尺寸、当前视口纵向相交、`display` 和 `visibility`。该过滤只用于测试侧的轨道几何与越界元素收集：自身或任一祖先处于透明/隐藏状态的保留挂载抽屉不计入可见越界元素；任何仍可见的轨道外越界元素继续导致失败。不得据此修改生产 CSS、组件挂载策略或通用容差。

### 2. 紧凑设置搜索状态复位

在进入 590×400 紧凑布局前，显式聚焦搜索输入框，再通过现有 Escape 交互关闭前一阶段的搜索结果并收起搜索；随后等待 `.is-expanded` 状态移除且查询清空，再调用现有表面复位和窗口尺寸设置。宽屏布局中的搜索框按设计始终可见，因此此阶段不以可见性作为复位条件。重新打开 590px 设置界面后，测试必须先确认搜索容器隐藏，再点击紧凑搜索按钮并继续原有的焦点、结果和无溢出断言。

不直接写入 React 状态，不调用私有组件方法，也不改变 `openSettings()` 的生产行为。这样测试仍验证用户能够观察到的真实交互，同时消除场景串联造成的状态歧义。

### 3. UI 字体延迟挂载触发

打开设置后，先定位 `.sp-setting-section-interface` 的占位区或已挂载分区，使用 `scrollIntoViewIfNeeded()` 将其带入设置内容视口。等待 `.sp-ui-font-picker` 可见后，再执行原有的 20 项数量、可用性、搜索、紧凑布局、预览、取消、保存及终端字体不变断言。

等待条件基于具体 DOM 状态，不使用固定睡眠。若滚动后字体选择器仍未挂载，测试应按超时失败，从而继续覆盖延迟挂载链路本身。

### 4. 右侧面板保留挂载契约

在紧凑工具场景的双面板固定态中，继续通过真实关闭按钮关闭右侧面板，并先等待 `window.store.rightPanelVisible === false`。关闭后不得再要求节点卸载，而应同时验证：

- `.right-side-panel` 仍恰好存在一个；
- 面板不可见；
- `aria-hidden="true"`；
- 存在 `inert` 属性。

随后沿用现有测试状态恢复步骤重新显示右侧面板，并继续验证它重新可见、固定切换、几何、重叠和后续工作区行为。该测试断言修正本身只与既有生产/单元契约对齐；下一节单独定义获准的隐藏态 CSS 修复。

### 5. 隐藏右侧面板的 overflow 隔离

仅在 `.right-side-panel-hidden` 上增加 `overflow: hidden`。右侧面板关闭时宽度可按既有共享几何收缩至 0，但保留挂载的标题、控制区或内容可能仍有自身最小内容宽度；隐藏根节点必须裁剪这些后代的 overflow，避免其传播为 `documentElement.scrollWidth`。

该声明随隐藏类一起添加和移除，因此只影响不可见、不可交互、`inert` 的关闭态。重新打开后不得保留该裁剪，面板内部原有纵向滚动、AI 内容、终端信息、标题控件、固定切换和状态保留行为均沿用现状。不得给可见 `.right-side-panel` 添加新的 overflow 规则，也不得修改组件或 store 逻辑。

### 6. 测试契约

如现有静态契约会约束视觉测试的调用顺序，则只增加精确契约，验证：

- 受控滚动判定必须检查轨道边界、滚动样式和原生控制区边界。
- 越界采样必须排除因自身或祖先透明/隐藏而不可见的保留挂载节点，但不得排除任何仍可见的轨道外越界元素。
- 右侧面板关闭后必须保留节点并同时满足不可见、`aria-hidden` 和 `inert`；重新启用后仍须可见。
- 静态单元契约必须先失败并证明 `.right-side-panel-hidden` 同时包含 `visibility hidden`、`pointer-events none` 和 `overflow hidden`，且仍不包含 `display none`。
- 聚焦 E2E 必须保留后期原始文档宽度断言；关闭面板后 `documentElement`、`body` 和根节点均不得产生横向滚动宽度，随后重新打开仍须可见。
- 字体选项数量断言发生在界面分区滚入视口且字体选择器可见之后。
- 紧凑搜索隐藏断言发生在显式 Escape 状态复位之后。

契约不得耦合无关实现文本，也不得要求修改生产文件。

## 数据流与失败处理

- 顶栏：页面几何快照 → 识别越界来源 → 校验受控轨道的全部安全条件 → 通过受控轨道或报告整页溢出。
- 保留挂载面板：关闭按钮 → 等待 store 关闭态 → 验证节点仍挂载但不可见、`aria-hidden`、`inert` → 恢复显示 → 验证重新可见。
- overflow 隔离：关闭类生效 → 隐藏根节点裁剪后代横向 overflow → 文档宽度保持在视口内；打开类移除 → 可见面板恢复既有布局和内部滚动。
- 搜索：结束宽屏搜索交互 → 聚焦输入框 → Escape 收起并等待展开状态移除、查询清空 → 复位页面 → 切换紧凑尺寸 → 验证隐藏和再次展开。
- 字体：打开设置 → 滚动界面分区 → 延迟挂载触发 → 字体选择器可见 → 执行完整生命周期断言。

测试失败时保留现有截图和结构化上下文。新增判定应把轨道矩形、滚动宽度、原生控制区矩形和未归类越界元素写入断言上下文，避免把未知异常静默归为允许状态。

## 实施与验收

实施采用红—绿—重构：测试侧判定先增加或收紧契约并观察预期失败；生产 CSS 例外先在 `ai-chat-layout.spec.js` 增加精确失败契约，再只增加一条隐藏态声明，最后运行聚焦 E2E 证明真实文档宽度恢复且面板可重新打开。

最低验收矩阵：

1. 相关单元测试契约通过，并证明缺少任一受控滚动安全条件时会失败。
2. 四个聚焦场景通过：顶栏极窄缩放、紧凑工具与右侧面板关闭/恢复、紧凑设置搜索、UI 字体生命周期。
3. `test/e2e/022.secondary-ui-visual-matrix.spec.js` 的完整 16 项矩阵零失败。
4. 完整单元测试零失败，既有平台条件跳过数量不增加。
5. `npm run lint` 和 `npm run compile` 通过，不产生新的警告类别。
6. 关键 SSH/SFTP E2E 继续通过，特别是目录双击不向终端注入提示符，以及 `hik → su → root → exit` 后文件面板身份恢复。
7. 几何采样忽略透明/隐藏的保留挂载抽屉，但人工制造的可见轨道外越界仍会失败；右侧面板关闭后仍有且仅有一个隐藏、`aria-hidden`、`inert` 的节点。
8. 隐藏右侧面板关闭态稳定后，`documentElement`、`body` 和根节点的 `scrollWidth` 不超过 `clientWidth`；重新打开后面板仍可见且内部交互不退化。测试使用状态/DOM 条件等待，不新增固定睡眠。
9. Git 差异中的生产文件只能出现 `src/client/components/side-panel-r/right-side-panel.styl`，且生产差异只能是 `.right-side-panel-hidden` 内新增 `overflow hidden`；不得修改组件、store、生产配置、依赖版本或发布脚本。
