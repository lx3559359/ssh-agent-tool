# ShellPilot 当前终端有效身份执行设计

## 1. 背景与根因

ShellPilot 同时存在两种远端命令执行上下文：

- 快捷命令通过当前交互式 PTY 提交，会继承该 Shell 的工作目录、环境和有效身份。
- 运维诊断、场景脚本和抓包通过 SSH `exec` 后台通道运行。该通道复用原 SSH 连接，但会创建新的非交互 Shell，身份始终是最初认证用户。

因此，用户先以 `hik` 登录，再在终端中执行 `su` 切换到 `root` 后，当前 PTY 已经是 root，但运维脚本仍由新的 `hik` exec Shell 执行。抓包脚本中的 `id -u` 会得到 hik 的 UID，随后尝试 `sudo -n`；当 hik 没有免密 sudo 时，任务错误地报告无权限。

这不是用户名字段刷新错误。交互式 `su` 只改变当前 PTY 的进程身份，不可能改变 SSH 连接的认证用户或其他新建通道的身份。

## 2. 目标

1. 用户在当前终端执行 `su`、`sudo -s` 或 `sudo -i` 后，快捷命令、运维诊断、场景脚本和抓包均按当前 Shell 的有效身份执行。
2. 登录身份与当前 Shell 身份保持分离：SFTP、SSH 端点绑定、主机密钥和审计连接身份继续使用最初登录用户。
3. 运维面板继续提供步骤状态、实时输出、退出码、取消、超时和历史记录。
4. 身份每次任务重新探测；退出 root Shell 后，下一任务不得沿用旧的 root 状态。
5. 不引入服务器常驻代理，不保存 `su` 密码，不伪造或提升 SSH 登录权限。

## 3. 非目标

- 不让 SFTP 继承交互式 `su` 身份。
- 不把标签页的登录用户名从 hik 改写为 root。
- 不通过提示符中的 `#`、用户名文本或窗口标题猜测权限。
- 不在后台 SSH exec 中模拟、重放或保存一次交互式 `su` 会话。
- 不允许多个自动任务同时占用同一个 PTY。
- 不在当前改动中新增任意脚本、自由 BPF 或新的提权方式。

## 4. 方案选择

采用“分步骤复用当前 PTY”方案。

对比过的替代方案：

1. 把整个场景脚本一次性注入 PTY。实现较小，但步骤进度、单步失败和取消边界会退化。
2. 在 root Shell 中启动后台代理。它可以保留后台体验，但会引入高权限常驻进程、认证、清理和重放防护，不符合当前范围。
3. 继续使用 SSH exec 并要求免密 sudo。它无法满足用户已经通过 `su` 获得 root Shell 后直接使用的要求。

分步骤 PTY 方案复用现有 Shell Integration 和命令完成追踪，能继承真实有效身份，同时保留现有任务模型。

## 5. 身份模型

一个 SSH 标签页同时暴露两种不可混用的身份：

| 字段 | 来源 | 用途 | 生命周期 |
| --- | --- | --- | --- |
| `connectionUsername` | SSH 标签页配置 | 端点键、SFTP、主机绑定、审计 | SSH 会话生命周期 |
| `effectiveUsername` / `effectiveUid` | 当前 PTY 内的 `id -un` / `id -u` | 运维脚本权限判断和任务展示 | 单次任务、重新探测 |

安全事务和任务历史的端点键继续采用 `connectionUsername@host:port`。当前 Shell 身份作为任务运行证据保存，但不能替换端点键，也不能授权 SFTP 或其他 SSH exec 操作。

界面应明确显示“登录用户：hik”和“当前 Shell：root”，避免把两者都称为“当前用户”。身份探测失败时显示“当前 Shell：未知”，并停止受控 PTY 任务，不回退到登录用户名继续执行。

## 6. 架构

### 6.1 PTY 运维任务通道

新增一个实现现有任务通道契约的 PTY 通道。任务运行器仍按步骤调用 `execute`，但实际提交路径改为当前标签页的终端实例，而不是 `terminal-apis.runCmd`。

PTY 通道负责：

- 校验标签页、PID、主机密钥和 SSH 端点仍与任务绑定一致。
- 确认终端位于普通提示符、没有待输入内容、密码提示或 TUI。
- 按需向当前 Shell 重新注入 Shell Integration。
- 为本次步骤建立随机、不可预测的输出边界令牌。
- 将步骤作为 `sh -c` 子进程在当前 PTY 中执行；子进程继承当前 Shell 的有效 UID、环境和工作目录，但脚本中的 `exit` 不会关闭交互式 Shell。
- 捕获边界内输出、规范化换行并去除 ANSI 控制序列，再通过现有 `onChunk` 回调送入任务面板。
- 从受信边界与 Shell Integration 完成事件交叉确认退出码。
- 在结束、失败、断线或取消后释放终端独占锁和输出监听器。

### 6.2 输出边界协议

每一步使用密码学随机令牌生成开始和结束控制标记。开始标记携带 Base64 编码的 `effectiveUid` 与 `effectiveUsername`，结束标记携带整数退出码。

标记由 Shell 包装器直接调用 `id` 生成，不读取提示符。客户端在写入 xterm 前通过流式解析器识别标记；解析器必须支持标记跨 WebSocket 数据块拆分，并拒绝令牌、阶段或字段格式不匹配的内容。

只有同时满足以下条件才认为步骤完成：

1. 收到匹配令牌的开始标记。
2. Shell Integration 观察到客户端提交的精确包装命令。
3. 收到匹配令牌、合法退出码的结束标记。
4. Shell Integration 报告同一次提交完成。

普通命令输出即使包含相似文本，也不能结束任务。控制标记不进入任务输出和历史记录。

### 6.3 终端独占与输入

每个 PTY 同时只允许一个受控运维任务。任务运行期间：

- 阻止其他快捷命令、Agent 终端命令和运维任务写入同一 PTY。
- 阻止普通键盘输入被发送给任务进程，保留 `Ctrl+C` 作为显式取消。
- 终端继续显示脚本和原始输出，让用户看见正在发生的操作。
- 面板持续显示同一份经过规范化和限额处理的输出。

终端返回普通提示符后才释放独占状态。若取消后无法证明提示符已经恢复，则任务标记为“取消结果未知”，终端保持受控忙碌提示，要求用户手动确认或重连；不得假装取消成功。

### 6.4 能力探测

打开运维面板时用于参数预填的后台探测可以继续使用登录用户的只读 SSH exec，但该结果只用于展示，不能作为执行权限证据。

用户点击运行后，任务运行器必须在同一个 PTY 中重新执行能力与身份探测，并以该结果构建和校验步骤命令。PTY 探测不跨任务缓存，避免 `su`、`exit`、重连或 PATH 变化后复用旧身份。

### 6.5 快捷命令兼容

现有快捷命令已经通过安全命令入口提交到当前 PTY，不改为 SSH exec。此次改动只让它们与新的 PTY 独占锁和身份展示共享同一运行状态：

- 空闲时按现有行为执行并继承当前有效身份。
- 运维任务占用 PTY 时拒绝新的快捷命令并显示明确原因。
- 快捷命令上下文中的用户名继续表示登录用户；执行结果可附带本次探测到的当前 Shell 身份。

## 7. 数据流

```text
用户点击运行
  -> 解析当前 SSH 标签页和终端实例
  -> 校验登录端点与主机密钥
  -> 获取 PTY 独占锁并确认普通提示符
  -> 在 PTY 中探测有效 UID、用户名和运行能力
  -> 记录 connectionUsername 与本次 effective identity
  -> 按步骤构建包装命令
  -> 提交当前 PTY
  -> 随机标记划分输出并实时同步到任务面板
  -> Shell Integration + 结束标记共同确认退出码
  -> 保存任务历史
  -> 返回提示符并释放 PTY 锁
```

任务记录新增可选运行证据字段，至少包括 `effectiveUid`、`effectiveUsername` 和执行通道 `pty`。旧历史记录没有这些字段时保持可读，不进行破坏性迁移。

## 8. 错误处理与取消

- **终端非空闲：** 命令尚未发送，提示用户先结束当前命令或交互程序。
- **密码提示或 TUI：** 命令尚未发送，不尝试输入密码或退出程序。
- **Shell Integration 注入失败：** 命令尚未发送，不降级为无法追踪的 PTY 粘贴。
- **身份探测失败：** 任务失败且不执行工具步骤，不把登录用户当成有效身份。
- **开始标记缺失：** 视为提交状态未知，停止后续步骤。
- **结束标记或完成事件缺失：** 不推断成功；等待超时后发送一次 `Ctrl+C`。
- **用户取消：** 向当前 PTY 的前台进程组发送 `Ctrl+C`，等待匹配完成事件和提示符恢复。
- **断线或重连：** 当前任务进入断开状态，清理本地监听器；新会话不得接受旧令牌的迟到输出。
- **输出过大：** 使用现有字节与行数上限截断，并保留截断标志；原始终端仍可按终端滚动缓冲显示。
- **步骤非零退出：** 保留已完成步骤和当前步骤输出，停止后续步骤，状态为部分完成。

独立 SSH exec 不再作为受控 PTY 任务的自动回退。自动回退会悄悄把身份从 root 变回 hik，正是本次需要消除的错误。

## 9. 安全边界

- PTY 执行不新增权限，只使用用户已经在该终端取得的有效身份。
- 资源敏感工具和修改类快捷命令继续经过现有确认与安全事务；切换执行通道不能降低风险等级。
- 连接端点验证仍绑定登录用户、主机、端口、标签页、PID 和主机密钥指纹。
- 有效身份仅来自任务包装器内的 `id`，不接受调用方、模型或表单传入。
- 任务令牌使用安全随机源，限定长度和字符集，只保存在内存中。
- 输出解析器在令牌验证前不信任任何远端文本；任务输出继续经过凭据脱敏和大小限制。
- SFTP、后台只读 Agent exec、服务器状态探测等未迁移功能继续明确标注为登录身份执行。

## 10. 测试计划

### 10.1 单元测试

- 登录用户 hik、PTY 探测为 UID 0/root 时，任务记录同时保留两个身份，脚本通过 PTY 通道执行。
- root Shell 中的抓包命令不进入 `sudo -n` 分支。
- 用户执行 `exit` 后下一任务探测为 hik，不复用 root。
- 直接 root 登录、普通用户登录和无权限用户保持正确分支。
- 输出标记跨数据块拆分、相似文本、错误令牌、重复开始/结束和非法退出码均安全处理。
- PTY 输出实时同步、ANSI 清理、UTF-8 边界和截断行为正确。
- 同一 PTY 并发任务、快捷命令和 Agent 命令被互斥。
- 覆盖普通完成、非零退出、`Ctrl+C`、超时、断线、重连和迟到输出。
- 验证运维任务不再调用 SSH `runCmd` 执行步骤；用于展示的只读预探测除外。
- 旧任务历史在没有有效身份字段时仍可读取。

### 10.2 集成与 E2E

- 使用本地 SSH/PTY fixture 模拟 `hik` 登录后进入 UID 0 子 Shell，运行只读诊断与抓包 fixture。
- 验证命令和输出在终端可见，运维面板收到同一任务的步骤输出和退出码。
- 验证退出 root 子 Shell 后，下一次任务显示并使用 hik。
- 验证任务期间普通输入被阻止，点击取消发送一次 `Ctrl+C` 并恢复提示符。
- 回归快捷命令、安全事务、运维工具、Agent 终端命令、SSH、SFTP 和客户端交互性能。

### 10.3 完成门槛

- 新增失败测试先证明现有 SSH exec 会得到 hik，而当前 PTY 会得到 root。
- 相关单元测试、完整 `test-unit-ci`、lint 和运维工具 E2E 全部通过。
- 不连接用户服务器；全部验证使用本地 fixture 和自动化环境。
- 自检确认没有把有效身份写回标签页、连接配置或 SFTP 上下文。

## 11. 验收标准

1. 用户以 hik 登录并在当前终端 `su root` 后，可直接运行抓包和运维脚本，无需 hik 具备免密 sudo。
2. 任务面板同时显示“登录用户：hik”和“当前 Shell：root”。
3. 抓包预检与执行均在当前 root PTY 中完成，并正确生成 pcap。
4. 用户退出 root Shell 后，下一任务重新识别为 hik，并在权限不足时给出真实错误。
5. SFTP 继续以 hik 运行，界面不宣称它拥有 root 权限。
6. 任务输出、退出码、取消、超时、断线和历史记录能力不退化。
7. 不存在从 PTY 自动回退到 SSH exec 的静默身份切换。
8. 自动化测试、lint 和 E2E 达到完成门槛。
