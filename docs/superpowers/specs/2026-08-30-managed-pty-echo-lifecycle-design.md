# Managed PTY 命令回显生命周期修复设计

> 结论：受控 PTY 命令的隐藏状态必须绑定命令提交生命周期，而不能依赖固定 5 秒计时器；真实 SSH 测试必须允许服务器回显内部命令。

## 背景与问题

ShellPilot 在当前交互终端已经进入 `su root`、`sudo -i` 等高权限 Shell 后，通过受控 PTY 命令完成 root 文件浏览和文件操作。命令必须发送到当前 PTY 才能继承该 Shell 的有效身份，但 `SHELLPILOT_FILE`、`SHELLPILOT_TOKEN` 和 `__sp_*` 等内部实现内容不应显示在用户终端。

v0.4.46 在发送前启动输出隐藏，并在收到带当前会话 nonce 的 `OSC 633;E` 后恢复输出。该版本仍有两个缺陷：

- 输出隐藏使用固定 5 秒超时。服务器回显或命令解析超过 5 秒时，隐藏提前结束，后续命令字节被写入 xterm。
- Electron/SSH E2E 夹具检测到特权命令前缀后主动关闭行回显，未覆盖真实服务器默认开启 PTY echo 的场景，形成测试假阳性。

## 目标

- 内部受控 PTY 命令无论长度、网络速度和回显分片方式如何，都不得显示在终端缓冲区。
- 仅当前 Shell Integration 会话的认证 `OSC 633;E;<nonce>;` 可以结束正常提交阶段的隐藏。
- 发送失败、任务取消、任务超时、连接断开或控制器失效时，隐藏状态必须显式清理，终端不能永久失去输出。
- 取消时先结束并丢弃隐藏的命令回显，再发送 `Ctrl+C`，使后续认证提示符能够进入命令追踪器并完成恢复。
- 正常协议输出从认证 `OSC 633;E` 开始继续进入 xterm 和远端输出订阅者，现有任务解析、身份校验与进度显示保持不变。
- E2E 测试必须由客户端隐藏真实服务器回显，不允许测试服务器替客户端绕过问题。

## 非目标

- 不取消 root 文件操作通过当前高权限 PTY 执行的能力。
- 不把大型内联协议改造成远端常驻助手或临时脚本。
- 不改变普通用户输入、普通安全命令、Shell Integration 注入或非受控终端输出的现有行为。
- 不隐藏任务已经开始后的合法命令输出、协议进度或错误信息。

## 方案

### 1. 建立受控回显隐藏租约

`AttachAddonCustom.submitManagedPtyCommand` 在写入 socket 前建立一次受控回显隐藏租约。该租约不再使用独立的 5 秒自动释放计时器，而是记录当前会话认证 marker，并保持到以下任一终止条件：

1. 收到完全匹配当前 nonce 的 `OSC 633;E`，正常结束隐藏并发布该 marker 及其后续数据。
2. socket 同步发送失败，立即结束隐藏并丢弃已缓存回显。
3. 控制器在取消、超时、执行拒绝或失效路径显式撤销隐藏租约。
4. Attach addon 因连接关闭或销毁而清理全部状态。

隐藏期间继续使用有界滚动扫描器，只保留认证 marker 长度减一的尾部；二进制 UTF-8 分片继续通过专用流式解码器处理，避免无界内存增长或跨包漏检。

### 2. 控制器拥有异常结束责任

`ManagedPtyTaskController` 增加一个窄接口，用于撤销当前提交的输出隐藏。控制器在以下边界调用它：

- 已提交任务开始取消或超时时，在发送 `Ctrl+C` 之前调用。
- 提交后的同步异常或追踪失败需要拒绝执行时调用。
- 终端连接失效、标签关闭或重新连接导致活动执行失效时调用。

正常执行不依赖该回调来显示输出：认证 `OSC 633;E` 会在命令真正开始时提前结束隐藏。执行最终清理再次调用时必须幂等，不能影响普通输出抑制或下一次提交。

### 3. 保持认证与数据发布边界

隐藏只接受由 `CommandTrackerAddon.getSessionNonce()` 提供且符合格式要求的 nonce。错误、过期或伪造 nonce 的 marker 继续被丢弃，不能释放隐藏。

匹配 marker 到达后：

1. 丢弃 marker 之前的全部命令回显。
2. 结束受控回显隐藏租约。
3. 将 marker 及同一数据块内的剩余内容同时写入 xterm 和远端输出订阅者。
4. 让现有命令追踪器确认精确命令、执行开始、退出状态和新提示符。

## 状态与错误处理

- 重复撤销：视为成功的幂等清理，不重新播放任何隐藏数据。
- 提交失败：不保留租约，不发布已缓存回显，错误继续返回控制器。
- 任务超时或用户取消：先撤销隐藏，再发一次 `Ctrl+C`；之后的提示符用于现有恢复判定。
- 取消后提示符缺失：维持现有 recovery lock 行为，要求重连；隐藏状态本身不能继续占用输出通道。
- 断线或 dispose：清除隐藏、decoder、扫描尾部和待发送输入，不尝试重放内部命令。
- 普通 Shell Integration 注入抑制：继续使用原有短超时机制，与受控 PTY 回显租约分离。

## 测试设计

### 单元测试

- 先建立失败测试：模拟旧 5 秒边界过去后继续输入命令回显，断言仍未写入终端。
- 认证 marker 到达后，只发布 marker 及后续协议数据。
- 错误 nonce、字符串分片、二进制 UTF-8 分片均不能提前释放。
- 显式撤销后隐藏状态清理；随后普通输出可见，缓存命令不被重放。
- 同步发送失败、重复撤销和 dispose 都保持幂等。
- 控制器取消/超时路径断言撤销隐藏发生在 `Ctrl+C` 之前。

### Electron/SSH E2E

- 删除本地 SSH 夹具针对 `SHELLPILOT_TOKEN` 和 `__sp_token` 的主动禁用回显逻辑，使其模拟默认开启 PTY echo 的服务器。
- 在普通 SFTP 降级到高权限 PTY、进入 `su root` 后的 root 文件操作、取消及恢复路径中，多次检查终端缓冲区不存在 `SHELLPILOT_FILE`、`SHELLPILOT_TOKEN` 或 `__sp_*`。
- 确认合法文件操作、身份继承、进度、取消和后续命令仍然成功。

### 回归验证

- 运行受控 PTY、终端输入、Shell Integration、远端文件后端相关单测。
- 运行完整 unit-ci 与 StandardJS。
- 运行真实 Electron + 本地 SSH/SFTP E2E。
- 运行生产构建，确认打包路径不受影响。

## 验收标准

- 旧版可稳定复现的“5 秒后出现 `__sp_*`”测试先失败，修复后通过。
- 开启真实服务器 PTY 回显的 Electron/SSH E2E 通过。
- 内部命令仍会发送到当前高权限 PTY，但用户终端缓冲区始终不可见。
- 取消、超时、断线和发送失败均不会造成永久黑屏、输入锁死或隐藏数据重放。
- 现有认证命令追踪、文件协议解析和有效身份约束保持通过。
