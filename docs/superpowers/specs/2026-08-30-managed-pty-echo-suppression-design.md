# ShellPilot Managed PTY 回显抑制设计

## 背景与根因

ShellPilot v0.4.45 在 SFTP 初始化和 root 文件操作前，会通过当前交互式 SSH 终端执行受管 PTY 命令，以继承用户在终端中通过 `su` 或 `sudo` 获得的有效身份。

`privileged-file` 的能力探测命令当前约为 20,972 字节。`AttachAddonCustom.submitManagedPtyCommand()` 将该命令和回车直接发送到远端 PTY。远端 TTY 启用了输入回显，因此完整的 `SHELLPILOT_FILE` / `__sp_*` 内部脚本会先进入 xterm 缓冲区，再由 Shell 执行。启用 SSH/SFTP 分屏、恢复到 SFTP 页面或打开 SFTP 时，用户会看到终端持续滚动并显示内部脚本。

## 目标

- 受管 PTY 自动命令不得在可见终端中显示其输入回显。
- 保留当前 Shell 的有效身份、命令追踪、取消、超时及提示符恢复语义。
- 受管协议解析器仍能收到 Shell 生命周期标记之后的全部原始数据，包括与第一个 OSC 633 标记位于同一数据块中的 `SHELLPILOT_FILE` 开始标记。
- 普通用户输入、粘贴、密码输入和非受管命令的显示行为保持不变。
- 回显抑制必须有超时边界，异常远端不能令终端永久停止显示。

## 非目标

- 不缩减或重写 privileged-file 安全协议。
- 不改用独立 SSH exec 通道，因为该通道不能可靠继承当前交互式 Shell 的有效身份。
- 不隐藏用户主动执行的命令。
- 不改变 SFTP 初始化时机、root 文件权限判断或原生 SFTP 回退策略。

## 设计

### 提交边界

`submitManagedPtyCommand()` 在验证命令非空之后、发送命令之前，启动一次仅用于受管命令的输出抑制。抑制期间，终端继续接收远端字节，但不把命令输入回显写入可见 xterm 缓冲区。

抑制采用现有 Shell 集成的 OSC 633 生命周期边界。远端 Shell 接收回车并开始处理命令时，会发送经过会话 nonce 认证的命令行或执行开始标记。收到第一个 OSC 633 标记后：

1. 丢弃标记之前积累的命令输入回显。
2. 解除输出抑制。
3. 把从该标记开始的完整剩余数据写给 xterm，使 `CommandTrackerAddon` 完成 nonce 校验和 E → C → D → A/B 生命周期追踪。
4. 把同一剩余数据发布给受管 PTY 原始输出订阅者，避免协议开始标记因数据包合并而丢失。

普通 Shell 集成注入继续沿用原行为；只有受管 PTY 提交要求在解除抑制时同步发布剩余原始数据。

### 状态与超时

回显抑制最多持续 5 秒。超时后丢弃已经缓存的自动命令回显并恢复正常显示。受管任务控制器继续依赖原有命令追踪和协议超时判断任务是否失败，不从“抑制超时”推断任务成功。

受管任务执行期间，现有控制器继续阻止普通键盘输入。Ctrl+C 仍通过 `interruptManagedPtyCommand()` 发送；远端返回的提示符生命周期标记会正常解除抑制并恢复终端。

### 安全边界

- 不降低 OSC 633 的会话 nonce 校验；最终命令状态仍由 `CommandTrackerAddon` 验证。
- 不把命令文本、文件路径或协议载荷复制到新的日志或持久化位置。
- 不允许调用方自行控制抑制超时或绕过受管命令租约。
- 未建立可靠 Shell 集成时，现有 `assertRunnableTerminalState()` 继续拒绝发送受管命令。

## 测试设计

### 单元测试

扩展 `test/unit-ci/terminal-input-stability.spec.js`：

- 提交受管命令后立即进入输出抑制。
- 模拟远端回显长 `SHELLPILOT_FILE` 命令，确认 xterm 没有收到该文本。
- 模拟 OSC 633 生命周期标记与 `SHELLPILOT_FILE` 开始标记位于同一数据块，确认 xterm 收到生命周期数据，原始输出订阅者收到协议数据。
- 确认空命令不启动抑制且不发送数据。
- 确认抑制超时能够恢复显示，不会永久锁住终端。

### Electron 回归测试

扩展本地 SSH/SFTP 的 managed PTY 场景：

1. 连接临时本地 SSH 服务并等待终端提示符。
2. 打开 SFTP，触发 privileged-file `probe`。
3. 切回终端并读取 xterm 缓冲区。
4. 断言缓冲区不含 `SHELLPILOT_FILE`、`__sp_` 或能力探测实现文本。
5. 执行普通 `echo` 命令，断言输入、输出和提示符仍正常。
6. 保留现有 root 身份继承、退出 root 后回退 SFTP、取消和清理验证。

## 验收标准

- 最新源码构建的 ShellPilot 连接本地测试 SSH 服务后，打开 SFTP 不再显示内部脚本。
- SFTP 普通用户与有效 root 两条路径均能完成能力探测和文件列表加载。
- 受管任务的开始、结束、取消、超时和提示符恢复测试全部通过。
- 相关单元测试、完整 unit-ci 测试、目标 Electron E2E 测试和生产构建均通过。
