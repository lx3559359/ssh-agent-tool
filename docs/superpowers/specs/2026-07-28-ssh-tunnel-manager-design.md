# ShellPilot SSH 隧道管理器设计

## 目标

在不改写 SSH 终端核心、不依赖服务器安装额外脚本的前提下，为 ShellPilot 增加面向中国用户的“一键 SSH 隧道”能力。功能复用现有 SSH 会话、书签认证、跳板配置和 `ssh-tunnel.js` 转发实现，使初学者可以通过中文表单创建、测试、停止和保存隧道。

## 现有能力

当前底座已经支持以下能力：

- 本地转发 `forwardLocalToRemote`
- 远程转发 `forwardRemoteToLocal`
- 动态 SOCKS5 转发 `dynamicForward`
- 书签中的多隧道配置 `sshTunnels`
- 会话建立时启动隧道并返回运行结果
- SSH 断开时释放相关监听
- 端口转发被服务端策略拒绝时显示中文诊断

本次开发不重新实现 SSH 协议，只补充运行时控制接口、中文向导、状态管理和自动化测试。

## 非目标

- 不通过向终端输入 `ssh -L`、`ssh -R` 或 `ssh -D` 来维持隧道。
- 不在服务器安装常驻脚本、代理服务或守护进程。
- 不在首版提供流量统计、限速、链路复用或隧道共享市场。
- 不允许模型 API 或 Agent 绕过用户直接创建公网监听。
- 不修改现有 SSH、SFTP、跳板机和普通书签连接流程。

## 用户入口

### 顶部入口

顶部工具栏增加“SSH 隧道”。当前存在已连接 SSH 会话时可直接打开；未连接时仍可浏览功能，但“启动隧道”显示“连接 SSH 后启动”，并提供“选择服务器”和“新建连接”入口。

在 1366 像素宽度或 Windows 125%/150% 缩放下，入口可以收入现有更多菜单，不能挤压窗口控制按钮。

### 会话入口

- SSH 标签页右键菜单增加“管理 SSH 隧道”。
- 已保存服务器的右键菜单增加“配置 SSH 隧道”。
- 书签高级设置继续保留原有隧道配置，作为高级入口。

## 隧道向导

向导以三种类型卡片开头：

1. **本地转发（推荐）**
   - 说明：通过本机端口访问服务器或服务器内网中的服务。
   - 默认监听：`127.0.0.1`
   - 预设：Web 服务、MySQL、PostgreSQL、Redis、自定义目标。

2. **远程转发**
   - 说明：让远程服务器通过远程端口访问本机服务。
   - 标记为“网络暴露风险”。
   - 默认远程监听：`127.0.0.1`

3. **动态转发**
   - 说明：通过当前 SSH 会话建立本地 SOCKS5 代理。
   - 默认监听：`127.0.0.1:1080`

表单根据类型只显示必要字段：

- 隧道名称
- 当前 SSH 服务器
- 本地监听地址和端口
- 远程目标地址和端口
- 是否保存到服务器配置
- 是否在该服务器连接后自动启动

表单下方实时显示数据流向，例如：

`本机 127.0.0.1:3307 -> SSH 服务器 -> 127.0.0.1:3306`

## 运行时架构

### 隧道定义

继续使用现有 `sshTunnels` 数据结构，新增稳定的运行时标识和可选设置：

- `id`
- `name`
- `sshTunnel`
- `sshTunnelLocalHost`
- `sshTunnelLocalPort`
- `sshTunnelRemoteHost`
- `sshTunnelRemotePort`
- `autoStart`

保存前删除纯界面状态，不把运行错误、连接对象或临时统计写入书签。

### 会话控制

在现有 SSH 会话服务上增加受限的运行时动作：

- `ssh-tunnel-start`
- `ssh-tunnel-stop`
- `ssh-tunnel-list`
- `ssh-tunnel-test`

动作只操作当前会话拥有的隧道。停止隧道必须释放本地监听、远程转发注册和相关连接；失败不能关闭 SSH 终端。

### 状态模型

每条隧道显示以下状态：

- 未启动
- 正在启动
- 运行中
- 正在停止
- 已停止
- 启动失败
- SSH 已断开

运行状态保存在当前会话内，不写入书签。SSH 重连后，仅自动恢复已明确设置为自动启动的隧道。

## 一键模板

首版模板如下：

| 模板 | 本地端口 | 远程目标 | 远程端口 |
| --- | ---: | --- | ---: |
| Web HTTP | 8080 | 127.0.0.1 | 80 |
| Web HTTPS | 8443 | 127.0.0.1 | 443 |
| MySQL | 3307 | 127.0.0.1 | 3306 |
| PostgreSQL | 5433 | 127.0.0.1 | 5432 |
| Redis | 6380 | 127.0.0.1 | 6379 |
| SOCKS5 | 1080 | 不适用 | 不适用 |

模板只负责预填，用户仍可修改。若默认本地端口被占用，客户端给出一个可用端口建议，不静默替换用户输入。

## 安全规则

- 本地和远程监听默认使用 `127.0.0.1`。
- 本地监听改为 `0.0.0.0` 或局域网地址时，显示暴露范围提示并二次确认。
- 远程转发首次启动时显示风险说明；仅监听远程 `127.0.0.1` 时无需重复确认。
- 监听特权端口、远程公网地址或可能覆盖现有监听时必须确认。
- 纯本地只读检查、状态刷新、复制地址和停止隧道不二次确认。
- 参数必须通过地址、端口和名称校验，不允许注入 Shell 字符。
- 日志记录隧道 ID、类型、目标、状态和错误，不记录密码、私钥或代理凭据。
- SSH 连接关闭时自动停止临时隧道。

## 运行管理

管理页面列出当前会话及已保存配置中的隧道。每条隧道提供：

- 启动或停止
- 复制访问地址
- 测试连通性
- 编辑并重启
- 保存为服务器配置
- 开启或关闭自动启动
- 查看失败原因

“测试连通性”从客户端连接本地监听地址验证链路，不在服务器执行额外诊断命令。测试失败时区分本地端口占用、SSH 转发策略拒绝、远程目标拒绝和 SSH 会话断开。

## 兼容与降级

- 老书签中的 `sshTunnels` 无需迁移即可继续工作。
- 不支持运行时控制时，页面提示“重新连接后生效”，不能白屏。
- 模块按需加载失败时使用现有懒加载错误边界，并提供“重新加载模块”。
- 隧道模块故障不能影响 SSH 终端输入、SFTP、AI 助手和窗口控制。

## 验收标准

1. 当前 SSH 会话可在不重连的情况下启动和停止本地、远程、动态三类隧道。
2. 本地转发可以通过本机端口访问测试服务器上的目标服务。
3. 动态转发可建立可用的 SOCKS5 地址。
4. 端口占用、服务端禁止转发和目标拒绝时显示明确中文原因。
5. SSH 断开后临时监听被释放，终端和客户端不会崩溃。
6. 保存的隧道在下次连接时按用户设置自动启动。
7. 默认监听不对局域网或公网开放。
8. 1366×768、1920×1080、Windows 125%/150% 缩放下表单和管理列表可完整操作。
9. 日间和夜间主题下状态、错误和风险提示均清晰可读。
10. SSH、SFTP、AI、运维工具及现有书签连接回归测试全部通过。

## 测试范围

- 隧道定义、参数校验、模板和状态转换单元测试。
- SSH 会话运行时启动、停止、断开清理和错误隔离测试。
- 书签保存、自动启动及旧数据兼容测试。
- 三类隧道的 Electron 端到端测试。
- 真实 SSH 服务器的本地转发和断开清理回归。
- Windows 多分辨率、多缩放和日间/夜间截图回归。
