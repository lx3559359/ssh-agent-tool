# Managed PTY 取消恢复与终端解锁设计

> 结论：取消已提交的受控 PTY 命令时，ShellPilot 必须继续隐藏内部命令回显，并以当前 Shell Integration 会话认证的下一次提示符作为恢复边界；只有收不到可信提示符时才保持终端锁并要求重连。

## 背景与根因

ShellPilot v0.4.47 通过当前交互式 SSH PTY 执行受控文件命令，以继承用户已经取得的有效身份。提交阶段会隐藏 `SHELLPILOT_FILE`、`SHELLPILOT_TOKEN` 和 `__sp_*` 等内部命令文本。

用户在真实 VPS 上触发取消后出现两个相互关联的问题：

- 控制器在发送 `Ctrl+C` 前立即撤销回显隐藏。远端 PTY 队列中尚未返回的内部命令尾部随后进入可见终端。
- `Ctrl+C` 可能发生在 Shell Integration 发出认证 `OSC 633;D` 命令结束事件之前。Shell 已经返回带当前会话 nonce 的 `OSC 633;A` 新提示符，但控制器仍要求先看到命令结束事件，因此把恢复误判为未知并永久占用终端输入租约。

截图中的可见内部脚本尾部、已经出现的 Shell 提示符、红色“终端释放状态未知”提示和无法键盘输入，正好对应这两个状态转换缺陷。

## 目标

- 取消或超时后，任何迟到的内部命令回显都不得显示在 xterm 中。
- 当前会话 nonce 认证且发生在取消请求之后的 `OSC 633;A` 足以证明交互式 Shell 已恢复，可释放终端租约。
- 恢复成功后保留原始取消或超时结果，不把取消误报为命令成功。
- 没有收到可信提示符时继续保持 recovery lock，并要求用户重连，避免把仍在运行的命令误判为已结束。
- 普通命令完成、协议解析、有效身份继承和非受控终端输入行为保持不变。

## 非目标

- 不根据可见提示符文本、正则表达式或主机名猜测 Shell 是否恢复。
- 不在取消后无条件解锁终端。
- 不改写 privileged-file 协议，也不改用无法继承当前交互身份的独立 SSH exec 通道。
- 不自动向用户的真实 VPS 发送诊断命令；验证默认使用本地 SSH 夹具和自动化测试。

## 方案比较

### 方案 A：认证提示符恢复边界（采用）

取消时把回显隐藏的释放标记从认证 `OSC 633;E` 切换为同一会话 nonce 的认证 `OSC 633;A`。收到该提示符后，丢弃此前所有隐藏字节，发布提示符标记及其后续数据，并允许控制器在缺少 `D` 事件时完成取消恢复。

该方案同时解决回显泄漏与输入锁死，沿用现有 nonce 信任边界，并保留无提示符时的保守锁定。

### 方案 B：匹配可见提示符文本

通过 `[user@host]#`、`$` 或类似文本判断恢复。它兼容没有 Shell Integration 的终端，但命令输出可以伪造提示符文本，无法作为安全释放依据，因此不采用。

### 方案 C：发送 Ctrl+C 后立即解锁

实现简单，但不能证明远端前台任务已经停止，后续用户输入可能进入仍在运行的命令，也会继续泄漏迟到回显，因此不采用。

## 组件与数据流

### 1. AttachAddon 的两阶段取消接口

受控回显隐藏增加“准备提示符恢复”动作，与现有“彻底取消隐藏”动作分离：

1. 正常提交时，仍以当前 nonce 的 `OSC 633;E` 为释放标记。
2. 开始取消时，不停止隐藏；将释放标记原子切换为当前 nonce 的 `OSC 633;A`，并清空仅用于旧标记匹配的有界扫描尾部。
3. 随后发送一次 `Ctrl+C`。
4. 远端返回认证 `A` 标记时，丢弃此前全部内部回显，从 `A` 标记开始恢复 xterm 写入和原始输出发布。
5. 执行最终清理、连接失效或 addon 销毁时，使用独立的幂等硬清理动作丢弃缓存并停止隐藏。

PTY 字节有序，因此提示符前到达的迟到命令回显会继续被隐藏；认证提示符本身会进入 `CommandTrackerAddon`，形成同一个可信恢复事件。

### 2. ManagedPtyTaskController 的取消恢复判定

每次执行记录取消请求发生时的提示符序号。正常完成仍要求认证命令结束事件之后出现新的认证提示符；取消路径则允许以下两种恢复证明：

- 已收到匹配提交 token 和命令文本的 `D`，随后收到新提示符；或
- 未收到 `D`，但取消请求之后收到新的认证提示符。

第二种情况只完成“终端已恢复”的判断，Promise 仍以原始 `AbortError` 或 `TimeoutError` 结束。控制器清理活动执行后，租约可以正常释放，`handleUserInput` 不再吞掉键盘输入。

取消请求之前的旧提示符、错误 nonce、过期会话或普通输出均不能触发恢复。

### 3. 终端接线

终端组件向控制器提供两个职责明确的回调：

- `prepareSubmissionOutputRecovery`：在发送 `Ctrl+C` 前把当前受控隐藏切换到认证提示符边界。
- `cancelSubmissionOutput`：在最终清理或失效时硬停止隐藏并丢弃缓存。

两个回调必须幂等。前者只有在当前受控提交仍处于隐藏状态时生效；后者不能影响普通 Shell Integration 输出抑制或后续提交。

## 状态与错误处理

- 正常完成：`E → C → D → A` 路径保持不变。
- 用户取消或任务超时：先准备提示符恢复，再发送一次 `Ctrl+C`，等待认证新提示符。
- 取消后收到认证 `A` 但缺少 `D`：按原始取消原因结束任务并释放输入。
- 恢复期限内没有认证 `A`：返回 `CancellationUnknownError`，保留 recovery lock，提示用户重连。
- 错误或旧 nonce 的 `A`：继续隐藏并等待，不解锁。
- 连接断开、提交异常、控制器失效或 addon dispose：硬清理隐藏状态，不重放内部数据；连接生命周期负责解除旧终端状态。
- 重复取消或重复清理：不重复发送 `Ctrl+C`，不抛出新错误，不影响下一次提交。

## 测试设计

### 控制器单元测试

- 先建立失败测试：取消后只收到新提示符、没有命令结束事件，断言返回原始取消错误、租约可释放且键盘输入不再被处理。
- 断言输出恢复准备发生在发送 `Ctrl+C` 之前，硬清理发生在执行结束时。
- 取消前的提示符不能完成恢复。
- 没有提示符时继续得到 `CancellationUnknownError` 并保持终端锁，直到连接失效。
- 正常 `D → A` 完成路径保持通过。

### AttachAddon 单元测试

- 受控提交后切换到提示符恢复模式，注入迟到的 `__sp_*` 命令尾部，断言终端与输出订阅者均不可见。
- 当前 nonce 的完整或跨包 `OSC 633;A` 到达后，只发布该标记及后续提示符数据。
- 错误 nonce 的 `A` 不解除隐藏。
- 最终硬清理、重复调用和 dispose 都保持幂等，不重放缓存。

### 接线与本地集成验证

- 静态接线测试验证两个回调没有混用。
- 使用开启 PTY echo 的本地 SSH 夹具触发受控任务取消，验证终端缓冲区不含 `SHELLPILOT_FILE`、`SHELLPILOT_TOKEN` 或 `__sp_*`，提示符返回后可以输入普通命令。
- 运行相关终端、受控 PTY、SFTP 后端测试，完整 unit-ci、代码规范、生产构建和 Windows 便携包自检。

## 验收标准

- v0.4.47 截图对应的“内部脚本尾部可见 + 提示符已返回但输入被锁”场景有自动化回归测试，并在修复前稳定失败、修复后通过。
- 认证提示符返回后，任务显示原始取消/超时结果，终端输入立即恢复。
- 没有认证提示符时仍不会冒险解锁。
- 真实 PTY echo 场景不再泄漏内部命令文本。
- 正常任务执行、取消、超时、断线和后续命令均通过回归验证。

## 对既有设计的修正

本设计取代 `2026-08-30-managed-pty-echo-lifecycle-design.md` 中“取消时先撤销隐藏、再发送 Ctrl+C”的取消顺序。真实 VPS 证据表明该顺序会暴露已经进入远端 PTY 队列但尚未返回的命令尾部；新的顺序是在认证提示符出现前持续隐藏，只在最终清理时硬撤销。
