# ShellPilot v0.4.31 冰川冷银卡片化全客户端设计

日期：2026-08-04  
设计状态：用户已确认  
实现基线：`master`，ShellPilot `v0.4.31`，提交 `cd7718c`  
范围：Electron 客户端全部可见界面

## 1. 背景

本次改造参考用户提供的浅色卡片界面风格，但不复制参考界面的信息架构。ShellPilot 当前 `v0.4.31` 的布局、功能位置、工作流和新版 AI 助手结构是实现时的唯一布局基准。

设计过程已通过当前 `master` 实机确认以下最新版界面：

- 未连接首页及最近连接；
- 顶部品牌、版本、连接状态、圆形快捷入口和窗口控制区；
- 左侧紧凑图标导航；
- 中间标签条与主工作区；
- 右侧新版 AI 助手，包括模型选择、检测状态、AI 接管、引用终端、引用选中、引用文件、生成命令、读取网页、上传、生成成果以及对话/Agent 切换；
- 运维工具大覆盖层、五个页签、推荐排查流程和高密度工具网格；
- 设置中心的顶部搜索、一级页签、左侧目录和分组表单。

改造目标是把上述现有客户端统一为“连续蓝紫品牌顶栏 + 冰川冷银卡片 + 点阵浅色背景”的视觉体系，并提供结构一致的配套深色模式。

## 2. 目标与非目标

### 2.1 目标

- 全客户端使用同一套颜色、圆角、描边、阴影、间距和交互状态语义。
- 浅色模式成为新安装用户的默认主题，卡片使用柔和的冰川冷银渐变。
- 深色模式提供同源的石墨冷银表面，而不是简单反色。
- 顶部标题、状态、快捷入口和窗口控制区使用连续、统一的蓝紫品牌色带。
- 保留终端、SFTP 表格、日志、执行记录和任务输出的紧凑信息密度。
- 保留键盘操作、焦点可见性、禁用态辨识、语义色和减少动态效果支持。
- 不改变现有用户数据、SSH/SFTP/AI 行为、安全确认或回滚能力。

### 2.2 非目标

- 不采用参考图的宽侧栏、首页信息架构或导航结构。
- 不移动、合并、删除或重命名 `v0.4.31` 的功能入口。
- 不重写现有路由、状态模型、存储模型、远程调用或安全事务。
- 不把每一行表格、每一段日志或每一个终端区块都做成带阴影卡片。
- 不引入硬反光带、深灰金属板、明显分段色阶或高亮镜面材质。
- 不借本次视觉改造进行无关重构。

## 3. 设计原则

### 3.1 布局以最新版客户端为主

实现必须以 `v0.4.31` 实机布局和当前源码为准。顶部保持圆形快捷入口及其顺序；左侧保持紧凑图标导航；中间保持标签条和工作区；右侧保持新版 AI 助手；运维工具和设置中心保持当前覆盖层结构。

允许的 JSX 调整仅限于补充缺失的语义容器或状态类名。不得为了实现卡片外观改变组件顺序、交互流程、快捷键、可访问名称或数据绑定。

### 3.2 外层卡片化，内部数据扁平化

卡片材质用于：

- 首页与功能入口卡；
- 页面摘要、状态摘要和操作卡；
- 设置分组；
- AI 面板、消息卡和输入容器；
- 运维工具、服务器状态、成果物、故障档案等分组面板；
- Modal、Drawer、Popover 和菜单的外层容器。

以下内容保持紧凑扁平：

- 终端画布；
- SFTP 文件行与表头；
- 日志正文与日志行；
- 执行记录、任务输出和虚拟列表行；
- 高密度表格、树和目录内容。

扁平内容可以使用细分隔线、行悬停底色和选中底色，但不得逐行增加大圆角和阴影。

### 3.3 品牌色与语义色分工

蓝紫色用于品牌、导航选中、主按钮、焦点环和主要交互强调。成功、信息、警告和错误继续使用独立语义色，并同时配合文字、图标或状态标签，不以颜色作为唯一信息载体。

## 4. 视觉系统

### 4.1 默认浅色：冰川冷银

建议基础颜色：

| 角色 | 建议值 |
| --- | --- |
| 页面底色 | `#EDF5FB` |
| 点阵颜色 | `rgba(83, 126, 178, 0.30)` |
| 品牌蓝 | `#306290` |
| 品牌过渡蓝 | `#40588E` |
| 品牌紫 | `#5547A6` |
| 交互强调 | `#5C5BE9` |
| 主文字 | `#14243F` |
| 次文字 | `#65738A` |
| 冷灰描边 | `#CFDCE7` |

冰川冷银卡片不是纯白，也不是高对比金属板。标准卡片使用两层柔和背景叠加：

```css
background:
  radial-gradient(
    110% 90% at 15% 0%,
    #FFFFFF 0%,
    rgba(255, 255, 255, 0.82) 35%,
    transparent 72%
  ),
  linear-gradient(
    150deg,
    #F6FAFC 0%,
    #EAF1F6 58%,
    #DCE6EE 100%
  );
```

该材质使用漫反射式明度变化：左上柔白、主体冷白、右下淡冰蓝银灰。不得添加硬边反光带、深银落底或强烈色阶。大面板的渐变对比应比操作卡更弱，避免大面积发灰。

页面背景使用低对比点阵，但终端、表格和日志内部不叠加点阵。

### 4.2 配套深色：石墨冷银

深色模式沿用相同层级和色相关系：

- 页面底色使用深石墨蓝黑；
- 卡片从冷石墨灰过渡到深蓝灰；
- 顶部仍使用蓝紫连续色带，但降低亮度；
- 描边与高光比浅色更克制；
- 终端背景与前景继续遵守现有固定可读性约束。

建议深色卡片主区间为 `#2A3543 → #202A37 → #18212C`，描边使用 `#3A495C`。深色模式不得直接把浅色卡片反色，以免高光和阴影关系颠倒。

### 4.3 顶部统一色带

顶部品牌、版本、连接状态、快捷入口和窗口控制区组成一条连续色带：

```css
linear-gradient(
  100deg,
  #306290 0%,
  #40588E 52%,
  #5547A6 100%
)
```

`v0.4.31` 的圆形快捷按钮保持当前尺寸、顺序和命中区域。默认、悬停、选中和禁用状态通过白色透明度、描边、焦点环和轻阴影表达，不使用与顶栏割裂的灰色胶囊。

### 4.4 圆角与阴影

建议层级：

| 层级 | 圆角 | 使用位置 |
| --- | ---: | --- |
| 小控件 | 8–10px | 输入框、按钮、标签、页签 |
| 操作卡 | 14–16px | 首页入口、工具卡、摘要卡 |
| 分组面板 | 16–20px | 设置分组、AI 面板、页面分组 |
| 弹层 | 20–24px | Modal、Drawer、大覆盖层 |

阴影分为控件、卡片、面板和弹层四级。每级都由外部冷色阴影和轻微顶部内高光组成。阴影不得应用到终端字符画布、表格行、日志行和任务输出行。

## 5. 组件与交互状态

### 5.1 顶部与侧栏

- 顶部圆形快捷入口保持当前图标和排列。
- 悬停仅上浮 1px，并轻微提高背景透明度。
- 选中状态增加清晰描边和外环，不改变控件尺寸。
- 禁用状态保持可辨识轮廓，透明度不低于可访问性要求。
- 左侧导航保持当前紧凑宽度和文字标签；选中项使用轻冰银表面和品牌紫强调。

### 5.2 卡片与面板

- 可点击卡片使用冰川冷银标准渐变和卡片级阴影。
- 主操作卡允许使用蓝紫品牌渐变，以建立明确主次关系。
- 大面板使用更弱的冰川冷银渐变和更高层级阴影。
- 面板嵌套超过两层时，最内层改用扁平底色，避免层层阴影。

### 5.3 页签与表单

- 页签容器使用轻银扁平底色，选中项使用冷白表面和品牌紫文字。
- 输入框默认使用近冷白底色；聚焦时使用品牌紫边框和低透明焦点环。
- 开关、单选和复选的开启状态使用品牌色，错误状态使用语义红。
- 所有现有 label、description、ARIA 名称、Tab 顺序和关闭后焦点恢复行为保持不变。

### 5.4 状态与风险确认

- 信息、成功、警告、错误保持独立语义色。
- 高风险确认继续突出影响范围、备份、验证和回滚信息。
- 危险主按钮使用语义红，不使用蓝紫渐变。
- 加载、空状态、禁用和失败状态必须在浅色、深色和高缩放下可读。

### 5.5 动效

- 控件悬停与焦点：120ms；
- 卡片和面板状态变化：150ms；
- Modal、Drawer 和大覆盖层：180ms；
- 不使用大幅位移、弹跳或持续发光；
- `prefers-reduced-motion: reduce` 下关闭上浮和非必要过渡。

## 7. 技术架构与数据流

### 7.1 令牌层

在现有主题和 CSS 变量体系中扩展以下语义角色：

- 页面底色与点阵；
- 冰银卡片、冰银面板、冷白控件、扁平数据层；
- 控件、卡片、面板、弹层四级阴影；
- 四级圆角；
- 品牌色、语义色、文字、描边、焦点环；
- 交互动效时长和减少动态效果覆盖。

令牌必须同时提供浅色与深色值，并为缺失值保留现有主题变量回退。

### 7.2 共享表面契约

通过集中 Stylus mixin、语义类或共享样式模块定义以下表面：

- control surface；
- action card；
- grouped panel；
- overlay surface；
- flat data surface。

页面样式引用语义表面，不应各自复制渐变和阴影常量。不得通过一个高优先级全局覆盖文件堆叠选择器。

### 7.3 页面定向适配

先替换可由令牌自然覆盖的样式，再为无法表达正确层级的页面增加最小定向样式。只有当现有 DOM 缺少明确表面边界时，才增加语义 wrapper 或状态类名。

### 7.4 业务数据流

主题改造不改变 SSH、SFTP、AI、运维工具、安全事务、更新或配置同步的数据流。主题切换继续由现有配置存储驱动。

新安装用户默认使用冰川冷银浅色主题。现有用户继续保留已选择主题；只有主题值缺失或失效时才回退到冰川冷银浅色。

冰川冷银与石墨冷银组成明确的浅深色配对：当前使用冰川冷银时，“夜间”切换进入石墨冷银，切回时恢复冰川冷银。现有用户若正在使用其他内置主题，则继续遵守现有主题切换与恢复行为，不得覆盖其已存储选择。其他内置主题继续可用，并通过同一语义令牌继承新的表面几何、层级和交互状态，同时保留各自的配色语义。

## 8. 异常处理与兼容性

- 主题变量缺失时回退到可读的冷白或石墨纯色，不产生透明文字或透明面板。
- 浏览器不支持组合渐变时，卡片使用基础冷白/深石墨底色与描边。
- 终端背景和前景继续通过现有主题约束保证最低对比度。
- 语义状态必须在渐变背景上通过对比度检查。
- 590×400、200% 缩放和英文长文案下，不得因阴影、圆角或新增 wrapper 产生横向溢出。
- 焦点顺序、Escape 分层关闭、关闭后焦点恢复和背景隔离行为必须保持现有实现。
- 当前工作区已有的无关修改不得纳入本次 UI 改造提交。

## 10. 测试与验收

### 10.1 自动化验证

- 为主题令牌、回退值、浅深色配对和现有用户主题保留逻辑增加单元测试；
- 为共享表面、禁止渐变区域和交互状态增加样式契约测试；
- 运行现有全量单元测试；
- 运行覆盖首页、连接、终端、SFTP、AI、设置、运维工具和主要弹层的 Electron E2E；
- 运行 lint 和生产编译；
- 验证没有新增横向溢出、不可见焦点或背景可交互问题。

### 10.2 视觉矩阵

- 主题：冰川冷银浅色、石墨冷银深色；
- 语言：简体中文、英文；
- 窗口：590×400、920×600、1100×700、1600×900、1920×1080；
- 缩放：75%、100%、125%、150%、200%；
- 状态：默认、悬停、焦点、选中、禁用、加载、空、成功、警告、错误；
- 页面：首页、连接态、终端、SFTP、AI、设置、运维工具、服务器状态、安全中心和主要弹层。

### 10.3 设计 QA

实现完成后必须使用同一视口、同一主题和同一状态对比设计基准与实机截图。所有 P0、P1、P2 问题修复后，项目根目录 `design-qa.md` 必须记录 `final result: passed`。P3 仅可作为后续微调记录。

### 10.4 成功标准

- 用户能明确识别冰川冷银卡片，不会把卡片看成纯白，也不会感到金属反光突兀；
- 顶部区域在全宽范围内保持一致蓝紫色系；
- `v0.4.31` 的布局、入口顺序、交互和功能没有变化；
- 高密度区域保持紧凑，主要工作区没有新增横向溢出；
- 浅色与深色均通过视觉、可访问性、功能和构建验收；
- 新安装用户默认进入浅色主题，现有用户设置与数据保持不变。
