# AI 助手全功能自检与完善设计

## 目标

对 ShellPilot v0.4.22 已有 AI 助手能力进行分层、可复现的完整自检，在不扩大远程写入风险的前提下验证真实模型、真实 SSH/SFTP 和 Electron 界面链路。发现缺陷后采用测试先行的方式实施最小修复，并补齐文档已声明但界面或实现未完整兑现的低风险功能。

本轮工作的重点是现有能力的正确性、安全性、稳定性和可恢复性，不新增新的 AI 产品形态，不重做界面视觉风格，也不进行与缺陷无关的大规模架构重构。

## 选定方案

采用风险分层审计：

1. 静态检查和现有单元测试确认基础契约。
2. 为边界输入和审查发现的缺陷增加最小复现测试。
3. 使用隔离 Electron 配置执行界面和进程间调用测试。
4. 使用当前已配置模型进行最小真实联网调用。
5. 使用专用 VPS 执行只读 SSH/Agent 验证；SFTP 写入仅允许发生在 `/tmp` 下的随机隔离目录并自动清理。
6. 完成聚焦测试后再执行完整单元、构建、依赖审计和发布链路回归。

不采用“只增加大量 E2E”方案，因为 UI 时序失败难以定位根因；不采用“先重构 AI 架构”方案，因为会显著扩大已发布版本的回归面。

## 审计批次

### 批次一：模型配置与对话核心

覆盖以下行为：

- 多配置的新增、编辑、删除、切换和持久化。
- API 地址、模型路径、认证 Header、代理和高级参数归一化。
- 拉取模型、连接测试、健康状态和失败提示。
- 普通对话提交、流式分块、UTF-8 边界、空响应和非流式响应。
- 同一会话上下文、跨终端会话隔离和历史窗口裁剪。
- 停止、超时、断线、重试、重复提交和陈旧响应隔离。
- API Key 仅通过凭据引用进入主进程，不进入聊天历史、诊断日志或导出内容。

真实模型验证只发送无敏感信息的短提示，验证一次普通流式回答、一次取消或超时收口，以及当前配置支持时的一次结构化工具请求。模型回复只保留有界、脱敏的测试摘要。

### 批次二：内容输入与多模态

覆盖以下来源：

- 本地文件选择、拖放和剪贴板文件。
- SFTP 当前选择和拖放文件。
- PDF、DOCX、PPTX、XLSX、文本、日志、JSON、CSV、HTML。
- PNG、JPEG、WebP 和 GIF 图片。
- 公网 HTTP/HTTPS 网页及其重定向。

验证文件大小、Office 解压膨胀、图片 MIME 与扩展名冲突、无磁盘路径的浏览器 `File`、二进制拒绝、文本截断、附件失败不发送空请求、图片只在当前请求内存中存在、多个附件与会话上下文合并，以及网页的本机、内网、凭据和 DNS 重绑定防护。

### 批次三：Agent 与工具边界

覆盖以下能力：

- 终端输出、服务器状态、日志、端口和文件范围等只读工具。
- SFTP 列表、状态、分段读取和受控写入。
- 快捷命令、运维工具、后台任务、Skill、MCP 和本地 CLI。
- 工具授权范围、风险分类、确认门、委托身份和 endpoint 绑定。
- Agent 取消、远程停止、部分完成、验证、证据和最终状态。
- 多任务并发、重复工具调用、失效标签页和 SSH 断线。

真实 VPS 默认只执行 `uname`、`id`、`pwd`、状态读取和有界日志查询。任何写入测试必须使用 `/tmp/.shellpilot-e2e-<随机值>`，不得修改服务、账号、防火墙、计划任务、系统配置或生产文件；测试结束必须删除隔离目录。取消不视为回滚，远端最终状态必须单独核验。

### 批次四：稳定性、呈现与交接

覆盖以下行为：

- 长历史分页、虚拟滚动、未读计数和回到最新。
- 对话模式与 Agent 模式切换时的任务隔离。
- 配置切换、标签页切换、组件卸载和应用重启后的状态恢复。
- AI 健康状态、错误编号、可操作提示和模块重新加载。
- 生成成果物、继续编辑、导出、删除和故障档案交接。
- 诊断报告、工具证据和历史记录中的脱敏与大小边界。

低风险且已有后端契约支持的缺口可以在本轮补齐。涉及新数据模型、新远程权限或大规模界面重排的建议只记录为后续事项，不在稳定性修复中顺带实现。

## 数据流与安全边界

Renderer 只提交经过限制的消息、附件描述和凭据引用。文件内容通过已有细粒度 IPC 进入主进程，由主进程执行格式识别、大小检查、Office 压缩包预检、网页 SSRF 防护和多模态归一化。主进程根据凭据引用读取受保护配置并调用模型，返回有界流式事件；Renderer 负责会话显示和一次性图片内容登记，不持久化图片 Data URL。

Agent 工具必须经过现有作用域、授权、风险分类和 endpoint 网关。真实环境测试不得绕过这些入口直接执行远程写操作。测试日志不得输出 API Key、VPS 密码、Authorization Header、Cookie、私钥或完整敏感模型响应。

## 错误处理原则

- 输入问题在请求模型前失败，并提供具体、可操作的提示。
- 某个附件失败时显示对应文件名和原因；如果没有任何有效内容，则不得发送请求。
- 流式请求只允许一个最终状态：完成、失败、取消或超时。
- 陈旧响应不得覆盖新的聊天、配置或标签页状态。
- Agent 取消后必须等待本地与远程取消屏障，并区分已取消、部分完成和状态未知。
- 导出内容必须在限长后保持目标格式有效，并保留明确截断标记。
- 依赖安全修复仅使用经过兼容性测试的窄版本覆盖，不执行自动强制降级或破坏性升级。

## 测试策略

每个确认缺陷执行完整红—绿流程：先写最小行为测试并确认因缺陷失败，再实施单一修复，最后运行聚焦测试和相邻回归。

验证层次包括：

1. Node 单元和契约测试。
2. lint 与静态源代码约束。
3. 隔离 Electron E2E，包括配置、普通对话、取消、附件和 Agent 界面。
4. 当前模型配置的最小真实 API 调用。
5. 专用 VPS 的只读 Agent 与隔离 SFTP 测试。
6. 完整 `test-unit-ci`、生产构建、运行时打包验证、生产依赖审计和在线更新源验证。

性能验证关注首个流式事件、只读 Agent 工具调用、长历史呈现和取消收口。网络抖动只允许在证据明确时重试一次，不通过放宽既有阈值掩盖问题。

## 完成标准

- 用户指南中声明的 AI 配置、对话、附件、网页、多模态、Agent、Skill、MCP、CLI、成果物和故障档案交接路径均有对应验证记录。
- 所有本轮确认缺陷都有自动化回归测试和根因说明。
- lint、聚焦测试、完整单元测试、生产构建和运行时验证为零失败。
- 生产依赖审计中的可兼容修复项已消除；无法安全消除的项有调用面和风险说明。
- 最小真实模型调用成功，或有明确的外部服务错误证据且本地错误收口正确。
- 真实 VPS 只读 Agent 和隔离 SFTP 验收通过，远端隔离目录完成清理。
- 最终差异不包含 API Key、密码、私钥、VPS 地址凭据或生成的测试产物。

## 明确不在本轮范围

- 新增模型提供商协议或自建网关。
- 新的远程写权限、无人确认的自动运维或生产环境变更。
- 重新设计整个 AI 面板、成果物中心或故障档案信息架构。
- 为清除审计数字而执行不兼容的依赖强制升级。
- 发布新版本或更新线上资产；如修复验证完成，是否发布由后续明确指令决定。
