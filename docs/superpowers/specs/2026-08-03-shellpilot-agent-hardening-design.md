# ShellPilot Agent 兼容性加固设计

## 背景

ShellPilot v0.4.28 的 Agent 已具备聊天、诊断、SSH 接管、风险确认和结构化工具能力，但审计发现运行边界分散在任务注册、模型请求、工具解析、SSH 会话和 React 状态之间。现有实现能够通过大部分测试，却仍存在混合作用域并发绕过、取消成功误报、畸形参数降级执行、诊断失败界面卡住、固定延时交接、端点漂移和缺少全局资源预算等问题。部分测试只检查源码形态，没有覆盖真实行为，因此无法阻止这些回归。

## 目标

- 修复已确认的 Agent 运行、取消、参数、端点和 UI 缺陷。
- 默认启用宽松但有限的总时长、模型调用、工具调用和内容大小预算。
- 保持现有 IPC、工具名称、工具参数、历史会话数据和 UI 操作向后兼容。
- 统一聊天 Agent 与诊断 Agent 的取消、错误和结束语义。
- 统一工具参数解析、Schema 校验、风险判断和执行输入。
- 增加仅保存在本地的脱敏运行观察信息，不上传外部遥测。
- 将关键路径从大型模块中逐步提取为可独立测试的组件。
- 用行为测试覆盖并发、竞态、取消失败、预算耗尽、断线重连和旧接口兼容。

## 非目标

- 不重写全部 Agent 内核或更换模型 SDK。
- 不删除、重命名或改变现有 IPC 与工具公开接口的必填字段。
- 不迁移或清空历史聊天、任务记录、风险审计或用户配置。
- 不让同一 SSH 终端上的有状态工具并行执行。
- 不读取工作区中的真实服务器凭据来完成自动化冒烟测试。
- 不引入外部日志、分析或遥测服务。

## 兼容性约束

现有 `agent.js`、IPC 方法、工具名称和参数继续作为兼容入口。新字段只能是可选字段；旧调用方不传入新字段时使用安全默认值。历史任务缺少新状态或预算字段时，通过读取期适配器映射到兼容状态，不修改原始记录。

内部错误将使用稳定错误代码，但原有可读错误文本仍会保留。新增结束原因和观察字段不得改变现有成功结果的结构；需要扩展时使用可选属性。旧 UI 动作仍调用原入口，由入口转发到新的内部控制器。

## 总体架构

在现有入口后增加四个边界清晰的内部组件：

1. `AgentRunBudget` 管理总运行时间、模型请求次数、工具调用次数、单轮工具数、响应体大小、参数大小和结果大小。
2. `AgentCancellationController` 统一模型请求、聊天 Agent、诊断流和 SSH 工具的取消状态及停止屏障。
3. `AgentToolCallParser` 对参数执行一次性解析、Schema 校验和规范化，并把同一份不可变结果交给风险判断与执行层。
4. `AgentRunObserver` 记录脱敏的本地阶段事件、耗时、预算、取消结果和错误来源。

任务注册表继续作为并发入口，但改用统一资源键集合判断冲突。每个任务至少声明标签页作用域键；能够解析端点时再声明端点键。任意资源键相交即视为冲突，解决“一个任务有端点、另一个任务只有作用域”时绕过互斥的问题。

每次运行创建不可变上下文，保存任务 ID、初始标签页、初始端点指纹、配置快照、取消控制器和预算。后续工具调用只能引用这份上下文。端点断开后重新连接到同一标签页时，旧运行不会自动切换到新端点。

## 运行状态与结束语义

Agent 运行使用统一阶段：

- `creating`
- `running`
- `cancelling`
- `cancelled`
- `cancel_failed`
- `budget_exceeded`
- `endpoint_changed`
- `failed`
- `finished`

所有结束结果都包含稳定的 `reason` 和可选的 `errorCode`。成功完成仅使用 `finished`；取消请求已发出但后端未确认停止时必须保持 `cancelling`，不得提前写入 `cancelled`。`cancel_failed` 是可见的故障状态，但在后台活动仍未结束时不视为可释放资源的终态。

聊天 Agent 和诊断 Agent 共用取消控制器。控制器登记所有活动停止函数，并等待它们全部完成。重复取消返回同一个停止 Promise，保证幂等。停止函数拒绝、返回 `{ cancelled: false }` 或超过停止期限时，结果为 `cancel_failed`，UI 提供重试入口，本地观察记录失败阶段。停止过程中仍拒绝启动同资源的新任务；取消失败后也继续持有资源锁，直到后台活动自然结束、后续取消确认成功，或所属端点被明确销毁并完成清理。

## 工具参数协议

工具调用按固定流水线处理：

1. 在解析前检查参数文本字节数。
2. 严格执行 JSON 解析；解析失败返回 `tool_arguments_invalid_json`。
3. 按工具 Schema 校验类型、必填项、枚举和额外字段规则。
4. 执行工具专属规范化，得到冻结的规范参数。
5. 使用规范参数评估风险并生成确认内容。
6. 使用同一个规范参数执行工具。

任何失败都返回标准工具错误，且不进入风险判断或执行。无参数工具也必须收到合法的空对象或缺省参数，不允许将畸形 JSON 静默替换为 `{}`。风险评估和执行不得各自重新解析参数，避免两者语义不一致。

工具注册信息逐步集中为单一清单，包含 Schema、风险属性、是否纯读取、是否依赖 SSH 会话状态、结果限制和展示元数据。现有公开工具定义由该清单派生，但公开名称和参数保持不变。

## 端点与并发边界

任务创建时生成资源键：

- `scope:<tab-or-task-scope>`
- `endpoint:<stable-endpoint-fingerprint>`（能够解析时）

注册表只要发现任一键重合就拒绝新任务。端点稍后才可解析时，任务必须原子地补充端点键并再次检查冲突；发生冲突则停止尚未开始的执行，不能覆盖已有任务。

运行上下文冻结初始端点指纹。每次进入 SSH 工具网关前校验当前端点；指纹不一致时返回 `agent_endpoint_changed` 并终止运行。这样同一逻辑任务不会混合来自不同服务器的证据或写操作。

工具执行默认串行。只有注册表明确标记为纯读取、不依赖终端状态、作用域互不相交的工具调用，才可进入小规模并发队列。并发数使用内部保守上限，且计入同一工具预算。首轮实现不改变已有 SSH 工具的串行语义。

## 默认资源预算

所有预算默认启用，并允许通过现有 Agent 配置的新增可选字段覆盖：

| 预算 | 默认值 |
| --- | ---: |
| 总运行时间 | 60 分钟 |
| 模型请求次数 | 100 次 |
| 工具调用次数 | 256 次 |
| 单轮工具调用次数 | 32 次 |
| 单次模型响应体 | 8 MiB |
| 单个工具参数 | 256 KiB |
| 单个工具结果 | 8 MiB |

模型请求的现有单次超时和重试策略保留，但必须同时受总运行时间与模型请求次数约束。预算在发起昂贵操作前预留，在操作结束后结算；并发调用也不能越过总额。

达到限制时停止继续请求模型或执行工具，保留已完成对话和工具结果，结束原因为 `budget_exceeded`，并指出具体预算类型。结果超过限制时使用统一截断元数据，不能生成看似完整但实际被静默裁剪的输出。模型响应的传输层也设置内容长度限制，防止先完整缓冲再由业务层截断。

## UI、交接与恢复

诊断任务 UI 根据显式状态渲染：

- 创建中显示加载状态。
- 创建失败显示错误与重试入口。
- 运行中显示当前阶段、耗时和预算用量。
- 取消中禁用重复操作并显示停止进度。
- 取消失败提供重试取消和关闭界面操作。
- 预算耗尽或端点变化保留已有结果并提供重新运行入口。
- 完成后显示摘要、调用统计和结束原因。

`task` 为空不再永久等同于加载中；任务创建失败必须有独立可见状态。

AI 接管删除固定 120ms 延时，改为有界条件等待。交接逻辑等待目标聊天组件、输入接口和任务上下文就绪后再提交提示。达到等待期限时保留提示内容，显示重试入口，不静默丢弃用户动作。现有舰队状态交接中的条件轮询实现作为项目内参考模式。

后台任务按任务 ID 保存最小恢复快照，包括状态、阶段、预算摘要、结束原因和端点指纹。组件重新挂载时恢复可见状态，但不会恢复敏感参数，也不会把旧端点任务绑定到新连接。

## 本地观察与错误模型

`AgentRunObserver` 只写入现有本地日志/审计通道，记录：

- 任务 ID 与匿名端点指纹。
- 状态转换和阶段耗时。
- 模型请求、工具调用和重试计数。
- 预算用量、命中类型和截断信息。
- 取消请求、后端确认、失败或超时结果。
- 稳定错误代码和错误发生层级。

不得记录凭据、完整命令、工具原始参数、命令输出、完整模型响应或完整对话。观察写入失败不能影响 Agent 主流程，但不能使用无信息的空捕获；失败需进入现有安全的本地诊断通道，并执行频率限制，避免递归日志。

错误按来源分类为 `model`、`tool_arguments`、`tool_policy`、`tool_execution`、`cancellation`、`budget`、`endpoint`、`persistence` 和 `ui_handoff`。UI 显示可理解信息，本地事件保留稳定代码和阶段。

## 模块拆分

实施期间保留原入口，并逐步提取以下职责：

- 预算与计数从 `agent.js` 提取到独立预算模块。
- 取消编排从聊天和诊断控制器提取到统一取消模块。
- 工具参数解析和 Schema 校验从 `agent.js` 与 `agent-tools.js` 提取到解析模块。
- 运行观察和错误分类提取到观察模块。
- `agent-tools.js` 按会话、主机信息、文件、服务、网络和会话外读取能力拆分内部实现，原聚合导出保持不变。

拆分依据是责任与状态依赖，而不是机械按文件长度切割。每次提取先用现有行为测试锁定公开接口，再移动实现，避免把功能修复与大规模重构混在同一个不可验证步骤中。

## 实施批次

### 批次一：运行安全

- 修复混合作用域任务冲突。
- 统一取消屏障并校验后端取消结果。
- 冻结和校验运行端点。
- 修复诊断任务创建失败后的永久加载状态。
- 用条件等待替代固定交接延时。

### 批次二：工具协议与预算

- 引入单次解析、Schema 校验和标准工具错误。
- 默认启用全局与单项预算。
- 限制模型响应、工具参数和工具结果大小。
- 增加预算耗尽、输出截断和背压语义。
- 仅对声明安全的独立读取工具预留有限并发能力。

### 批次三：UI 与本地观察

- 补齐全部运行、取消、失败和恢复状态。
- 显示阶段、耗时、预算和结束原因。
- 保存并恢复最小任务快照。
- 增加脱敏本地结构化观察和错误阶段。

### 批次四：架构与测试治理

- 提取预算、取消、解析、观察和工具分组模块。
- 保留聚合导出和旧调用适配器。
- 将关键源码正则断言替换或补充为真实行为测试。
- 增加兼容性、竞态、压力和恢复测试。

## 测试策略

所有行为变更遵循测试驱动开发：先写一个最小失败测试并确认因目标缺陷而失败，再写最小实现使其通过，最后重构并运行相关回归。

必须覆盖：

- 端点任务与仅作用域任务的双向混合冲突。
- 端点后解析时的原子补锁竞态。
- 聊天与诊断取消等待后端停止、失败、超时和重复取消。
- `{ cancelled: false }` 不得被记录为成功取消。
- 畸形 JSON、Schema 错误、超大参数和无参数工具不执行。
- 风险判断与执行接收同一个规范参数对象。
- 总时长、模型、工具、单轮、响应、参数和结果预算边界。
- 断开后同标签页重连到不同端点时终止旧运行。
- 诊断创建失败、交接未就绪、组件重挂载和任务恢复。
- 旧 IPC、工具调用、历史会话和旧配置保持兼容。
- 本地观察脱敏且观察写入失败不影响主流程。
- 串行 SSH 工具顺序不变，只有明确安全的读取工具允许受限并发。

验证分层执行：目标单元测试、Agent/AI/UI 相关测试、代码规范检查、全量单元测试。真实 SSH 接管冒烟测试只在提供隔离配置、专用测试服务器、主机指纹和恢复确认后运行；否则在交付报告中明确标注未执行。

## 验收标准

- 已确认缺陷均有先失败后通过的行为回归测试。
- 任意共享作用域或端点的 Agent 任务不能并发接管。
- UI 不会在后端未确认停止时报告成功取消。
- 任何参数解析或校验失败都不会执行工具。
- Agent 不跨端点继续运行。
- 默认资源预算生效，命中后保留已有结果并返回明确原因。
- 诊断创建失败和 AI 交接超时均提供可见错误与重试路径。
- 本地观察信息不包含凭据、完整命令、原始输出或完整对话。
- 现有 IPC、工具名称/参数、历史会话和 UI 操作保持兼容。
- 目标测试、相关回归、代码规范和全量单元测试结果均在交付时如实记录。
