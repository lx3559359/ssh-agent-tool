# ShellPilot 0.4.17 稳定性增强设计

## 目标

在不改变 SSH 终端核心连接方式的前提下，增强四条高频链路：

1. SSH 隧道断线恢复与端口冲突处理。
2. AI 修改远程文件前的差异预览、备份和快捷回滚。
3. SFTP 传输冲突、失败恢复和覆盖前备份。
4. 已安装客户端从上一稳定版平滑升级到当前版本。

每个子项目独立实现、独立测试、独立提交。任何一个子项目未通过门禁，都不阻塞其他子项目继续开发，但会阻止整体版本发布。

## 设计原则

- 普通 SSH 输入、快捷键和终端渲染路径不增加额外拦截。
- 只读操作不增加二次确认。
- 修改、覆盖、删除和网络暴露操作必须保留备份或回滚入口。
- 自动恢复不得静默改变端口、目标地址或文件路径。
- UI 只展示用户可采取的动作，底层错误转换为中文、可定位的错误编号。
- v0.4.16 及更早版本的书签、隧道和连接信息保持兼容。

## 子项目一：SSH 隧道可靠性

### 现状

已保存且开启“连接后自动启动”的隧道，会在新的 SSH 会话就绪时重新启动。当前缺口是：

- 本地监听端口冲突只返回底层错误，用户不知道可用端口。
- 自动启动失败只附着在标签页提示中，隧道管理器缺少可操作建议。
- 临时启动但未保存的隧道不会在重连后恢复，界面没有明确说明。

### 方案

新增独立的端口探测模块，只处理本地转发和 SOCKS5 的本地监听端口：

- 启动前检查请求端口。
- 端口占用时，在同一监听地址上向后搜索 20 个端口。
- 返回 `SSH_TUNNEL_PORT_IN_USE`、原端口和建议端口。
- 不自动修改或启动建议端口，必须由用户点击“改用建议端口”。
- 远程转发由远端 SSH 服务决定监听状态，不在本机探测。

自动启动沿用现有书签数据和 SSH 会话生命周期：

- 只恢复“已保存、启用、自动启动”的配置。
- 重连后为每条配置记录成功或失败结果。
- 失败结果保留错误编号、简短原因和建议端口。
- 未保存的临时隧道标注“仅当前连接有效”。

### 测试

- 端口可用时保持原端口。
- 端口占用时返回第一个可用建议端口。
- 搜索范围耗尽时不返回错误建议。
- 远程转发不执行本地端口探测。
- 自动启动失败不影响 SSH shell 和其他隧道。
- 断开后资源释放，重连后仅恢复已保存自动启动项。

## 子项目二：AI 文件差异与回滚

AI 不直接绕过现有安全事务框架。所有远程文件写入统一经过：

1. 读取原文件并计算摘要。
2. 生成统一 diff 预览。
3. 用户确认后创建带时间戳的远程备份。
4. 使用临时文件写入并原子替换。
5. 验证写入结果并记录操作链路编号。
6. 在安全操作中心提供“立即回滚”。

新建文件不要求备份，但仍展示完整新增内容。只读分析、列目录、读取文件不确认。

## 子项目三：SFTP 可靠传输

复用现有传输任务队列，补充：

- 同名冲突策略：询问、跳过、覆盖、自动重命名。
- 覆盖远程文件前自动备份，可从安全操作中心恢复。
- 临时文件上传成功后再原子改名，避免留下半文件。
- 网络中断后保留任务与已传字节；服务端支持时继续传输，不支持时明确从头重试。
- 文件夹任务逐项记录，单文件失败不抹掉已完成结果。

## 子项目四：客户端升级回归

使用正式安装版完成 `0.4.16 -> 0.4.17` 的真实升级：

- 客户端内检查更新、下载和安装。
- 不出现安装范围、安装目录等首次安装页面。
- 保留书签、AI 配置、主题、历史记录和安全操作记录。
- 更新失败时保留旧版可执行文件并给出恢复入口。
- GitHub 与魔塔资产、版本和哈希必须一致。
