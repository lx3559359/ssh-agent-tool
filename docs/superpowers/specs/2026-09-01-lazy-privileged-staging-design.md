# ShellPilot 特权 SFTP 暂存区延迟初始化设计

日期：2026-09-01  
状态：用户已选择方案 1，等待书面规格确认

## 背景与证据

在真实 VPS 上以临时普通账号登录，再通过密码执行 `sudo -k -i` 切换到 root 后，点击 SSH 页面内的半屏 SFTP 会卡在远端目录刷新。终端输出抑制保持开启，普通输入无法立即使用。

实测确认当前任务并非运行旧构建。最新版构建已包含压缩后的 `probe`、`list` 和 `list-bound`，其命令长度都低于 3840 字节；阻塞命令实际是 root 文件后端创建时无条件执行的 `stage-handshake`，长度约 25965 字节。该握手服务于上传、下载、摘要与复制所需的安全暂存区，但目录浏览并不使用暂存区。

交互式 Linux PTY 对超长单行输入存在截断和规范模式限制。结果是半屏 SFTP 在只读首屏阶段发送一条不必要且无法可靠提交的长命令，既拖慢响应，也可能使隐藏命令回显和终端输入恢复进入异常状态。

## 目标

1. 半屏或完整 SFTP 的只读首屏不得创建特权暂存区或执行 `stage-handshake`。
2. root 目录浏览只执行短命令，并保持内部协议、命令和探测文本对用户不可见。
3. 首次真正需要暂存区的传输操作才进行一次安全握手。
4. 并发传输只能共享同一个初始化过程，不能创建多个 session root。
5. 初始化失败、关闭竞态和释放失败均保留现有安全清理语义。
6. 普通账号登录、密码 sudo 到 root、半屏 SFTP 和返回终端输入必须在真实 VPS 连续三轮通过。

## 非目标

- 不削弱暂存区 challenge/response、路径、设备号、inode、uid/gid、mode 或内容摘要验证。
- 不把 root 文件访问降级为登录账号的普通 SFTP 权限。
- 不通过延长超时掩盖 PTY 命令过长问题。
- 不为只读首屏后台预热暂存区；后台握手仍可能抢占终端输入。
- 不改动 VPS 业务文件、现有账号或 sudo 配置；测试账号必须临时创建并在 `finally` 中删除。

## 方案选择

### 方案 1：后端内单航班延迟初始化（采用）

`createPrivilegedFileBackend` 只验证 SFTP 合同、PTY lease、root 身份、能力表和协议，不立即创建暂存会话。第一次需要暂存区的操作通过单航班 Promise 创建会话，后续操作复用同一结果。

优点是只读首屏没有无关握手，现有安全暂存协议保持原样，改动集中在后端生命周期。代价是第一次上传或下载会承担一次初始化延迟。

### 方案 2：继续预初始化并压缩 `stage-handshake`（不采用）

需要压缩大量安全校验及参数，审计面大，而且浏览目录仍要等待不需要的握手。

### 方案 3：首屏后后台预热（不采用）

视觉首屏可能更快，但后台仍会占用与用户共享的 PTY，继续存在抢占输入和隐藏回显风险。

## 架构与数据流

### 1. 后端创建

后端创建阶段执行同步合同验证并建立特权文件协议对象，但暂存会话保持 `undefined`。创建成功后即可执行不依赖暂存区的固定操作，包括目录列表、`lstat`、`stat`、`readlink`、`realpath`、简单目录创建、既有条目的元数据调整和同文件系统重命名。安全删除、缺失文件的 `touch`、内容摘要及传输仍先初始化暂存区。

只读目录首屏的数据流为：

`probe → 创建无暂存后端 → list/list-bound → 发布 root 文件身份 → 释放 capability/lease`

该路径不得出现 `stage-handshake`、暂存目录创建或暂存 SFTP 读写。

### 2. 单航班暂存初始化

后端增加内部 `ensureStaging()`：

- 后端已关闭时立即拒绝；
- 已有活动会话时直接返回；
- 已有初始化 Promise 时复用；
- 否则调用现有 `createPrivilegedStagingSession`，并通过现有串行 PTY 队列执行握手；
- 成功后仅在后端仍开放时发布会话；
- 初始化失败时清除可重试 Promise，并把原错误返回给发起操作；
- 如果初始化完成时后端已进入释放状态，立即释放新会话，不允许其被后续操作使用。

依赖暂存区的公开操作在创建 allocation、读取 `rootBinding` 或执行暂存 cleanup 前调用 `ensureStaging()`。上传、下载、文件读取/摘要、跨位置文件复制和传输 capability 属于该类操作。

### 3. 并发与关闭

公开操作继续由 `activePublicOperations` 跟踪，PTY 请求继续由 `executeTail` 串行化。释放流程按以下顺序执行：

1. 将后端标记为关闭，阻止新操作和新初始化；
2. 等待已接纳的公开操作完成；
3. 等待进行中的暂存初始化确定成功或失败；
4. 仅在暂存会话确实存在时处理 import/digest 残留并调用其 `release()`；
5. 最后释放 PTY lease。

若从未需要暂存区，释放不得创建暂存区或发送握手。多个清理错误继续采用“首个错误为主、附加错误不覆盖主错误”的现有约定。

### 4. 可观察接口

生产调用方继续只拿到受保护的文件 capability，不暴露原始暂存对象。原始后端的 `staging` 只作为只读 getter 反映已成功初始化的会话；初始化前返回 `undefined`，不会触发初始化。

不新增包含主机、账号、路径、命令正文或凭据的日志。

## 错误处理

- 浏览目录失败只报告对应 `probe/list` 错误，不应被暂存握手错误污染。
- 首次传输握手失败时，传输失败并执行现有暂存目录安全清理；后端 lease 在 capability 释放时正常回收。
- 初始化 Promise 失败后允许后续独立传输重试，但一次失败中的并发等待者得到同一个错误。
- release 与初始化竞态时，初始化结果不能发布给已关闭后端；成功创建的会话必须被释放。
- SFTP endpoint 代次变化仍由现有 `assertCurrentEndpoint` 拒绝，不能跨连接复用暂存会话。

## 测试驱动实施

先新增失败测试，再修改生产代码。自动化覆盖：

1. 创建 root 后端及执行 `list` 不产生 `stage-handshake`，release 也不产生握手。
2. 首次暂存依赖操作恰好握手一次；第二次和并发操作复用同一会话。
3. 初始化失败只在暂存依赖操作暴露，并保持主错误与清理错误关系。
4. release 在初始化进行中会等待并清理，释放后不得发布或再次创建暂存会话。
5. 未初始化、已初始化和初始化失败三种状态都只释放一次 PTY lease。
6. 现有暂存区路径/inode/uid/gid/mode/摘要与残留清理测试继续通过。
7. `probe`、`list`、`list-bound` 命令继续低于 3840 字节。
8. 终端输入、SFTP 生命周期、传输边界、lint 和生产编译全部通过。

## 真实 VPS 验收

每轮都通过 root SSH 临时创建随机 `spqa` 普通账号，加入系统现有 `wheel` 或 `sudo` 组但不配置 `NOPASSWD`。应用使用该账号登录，再输入账号密码执行 `sudo -k -i`。

每轮验证：

- 登录与 sudo 前后终端不出现 `__sp_`、`SHELLPILOT_FILE` 或 `shellpilot root one read`；
- 点击 SSH 页内半屏 SFTP，远端目录完成加载且身份通道为 `pty-root`、有效 uid 为 `0`；
- 第一次半屏打开目标不超过 5 秒，第二、三次目标不超过 1.5 秒；
- SFTP 打开后终端能立即输入并看到唯一随机回显；
- 关闭/重开半屏不会残留 active lease、输出抑制或待输入队列；
- `finally` 删除临时账号和 home，测试后额外查询确认不存在 `spqa*` 残留。

最终门禁为同一测试连续三轮全部通过。任何一轮失败都不声明问题已解决。
