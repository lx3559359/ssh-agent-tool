# ShellPilot SFTP 醒目传输进度设计

## 背景

SFTP 传输层已经持续上报已传输字节、总大小、速度和任务状态，文件管理器中也已有底部进度坞的基础实现。当前进度坞高度和进度条视觉权重偏低，用户在上传或下载开始后仍可能忽略传输状态。

本次只强化上传、下载进度的可见性与状态表达，不改变传输协议、队列、重试、暂停、恢复、取消和安全事务语义。

## 目标

1. 上传或下载开始后，用户无需打开菜单即可立即看到进度。
2. 进度坞在 SFTP 文件区底部保持稳定、醒目，同时不遮挡主要文件操作。
3. 同时显示方向、文件名、百分比、已传输/总大小、速度和任务数。
4. 支持展开现有逐文件传输详情。
5. 在未知总量、暂停、失败和完成状态下提供准确反馈。
6. 不显著增加渲染频率或输入延迟。

## 方案比较

### A. 文件区顶部横条

最容易在传输开始时被看到，但会推动文件列表下移并改变可用高度，频繁出现和消失时页面跳动明显。

### B. 文件区底部固定进度坞（采用）

进度坞贴近本地与远程文件区，位置稳定，不改变文件列表布局；通过更强的边框、状态文字和加粗进度条提高可见性。它还能直接复用当前底部进度坞和逐任务详情组件，改动范围最小。

### C. 右下悬浮卡片

占用布局空间最少，但容易遮挡文件列表，多任务详情扩展空间有限，也可能与右侧 AI 面板或通知竞争。

## 交互与视觉设计

- 当前 SFTP 标签页有活动传输时，进度坞自动出现在文件区底部，左右和底部保留小幅安全间距。
- 摘要行从左到右显示方向与任务数、当前文件名、百分比与字节、速度、展开按钮。
- 活动状态使用主色强调边框和 8px 进度条；暂停使用警告色，失败使用错误色，完成使用成功色，并同时保留文字说明，避免只依赖颜色。
- 已知总大小时显示 0–100% 的确定进度；未知总量时显示循环活动条，不伪造百分比。
- 点击“展开详情”复用现有逐任务列表和暂停、继续、取消等控制。
- 传输完成后短暂展示 100% 与完成状态，然后自动隐藏；取消任务不得误报完成。
- 无活动或需要展示的终态任务时不渲染进度坞，不占据文件列表空间。
- 窄窗口优先保留任务数、当前文件名、百分比和展开按钮；空间不足时隐藏字节与速度。

## 组件与数据流

`sftp-entry.jsx` 继续按当前标签页挂载 `SftpTransferProgressDock`。进度坞从现有传输列表和历史中读取任务，由 `sftp-transfer-progress-model.js` 完成以下纯计算：

1. 按当前 `tabId` 过滤任务，避免其他会话文件名或进度进入当前视图。
2. 对已知大小的任务按字节加权聚合，钳制异常或重试回退数据。
3. 选择正在运行的任务作为当前文件，其次为暂停或等待任务。
4. 汇总速度并形成稳定的状态键。
5. 通过现有发布门将普通字节更新最多每 100ms 提交一次，状态切换立即提交。

`sftp-transfer-progress-dock.jsx` 只负责格式化和展示。展开区域继续复用 `Transporter`，不创建第二套任务控制逻辑。`sftp.styl` 负责视觉强调、状态颜色和窄窗口退化。

## 错误和边界状态

- 总大小未知：显示不确定进度动画，并继续显示已传输字节。
- 速度为零：不显示无意义的 `0 B/s`，保留任务状态和进度。
- 暂停或连接中断：冻结当前进度，使用警告状态文字和颜色。
- 失败：显示失败状态和错误色，不把历史中的失败任务合成为完成。
- 取消：立即从活动摘要清理，不能触发 100% 成功终态。
- 完成：只有传输历史确认成功时才短暂展示 100%。
- 多文件：整体百分比按字节聚合；展开后分别显示每个文件状态。

## 测试策略

按测试驱动方式补充或调整验证：

1. 先新增失败测试，约束进度坞必须具备醒目的活动状态类、清晰方向文本和加粗进度条样式。
2. 验证上传和下载任务都能进入当前标签页摘要，并正确显示方向。
3. 验证多文件字节聚合、未知总量、重试回退、暂停、失败、取消和完成状态。
4. 验证 ARIA 进度属性、展开状态和键盘可操作按钮。
5. 运行 SFTP 相关单元测试、进度 UI 静态契约测试、代码规范检查和客户端构建。

## 验收标准

1. 上传或下载开始后，SFTP 文件区底部立即出现明显的固定进度坞。
2. 用户无需展开即可看到方向、文件名、百分比、字节、速度和任务数。
3. 进度条高度至少为 8px，活动状态边界在当前主题下清晰可辨。
4. 展开后可查看并控制逐文件任务，原有传输行为不变。
5. 未知总量、暂停、失败、取消和完成状态准确，不出现虚假百分比或成功提示。
6. 当前标签页不会展示其他会话的传输信息。
7. 相关测试、代码规范检查和客户端构建通过。
