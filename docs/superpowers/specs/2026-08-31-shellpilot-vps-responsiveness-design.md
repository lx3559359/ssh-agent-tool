# ShellPilot 真实 VPS 响应速度与交互恢复设计

日期：2026-08-31  
状态：用户已确认设计方向，等待实现计划

## 背景与实测证据

在最新版 ShellPilot 连接真实高延迟 VPS 后，基础 SSH 和 SFTP 可建立，但受控 PTY 运维任务稳定超时，超时前没有步骤结果，结束后可能残留待提交命令状态。隔离界面与只读直连测试得到以下基线：

- SSH 主机指纹确认后到终端可用约 4.34 秒；
- SFTP 首次目录首屏约 2.22 秒；
- 同一目录连续刷新约 1.55–2.16 秒；
- VPS 上的能力探测子命令各自在 0.64–2.01 秒内完成，组合执行远低于现有 30 秒超时；
- 简短和完整受控 PTY 脚本都会超时，而相同 WebSocket 控制通道可成功发送普通短命令。

根因位于受控 PTY 的输出解除条件：客户端等待 Shell Integration 回报与整段包装脚本完全一致的命令记录；Bash 的 `DEBUG` 钩子对分号串联脚本回报第一个简单命令，因此完成边界一直被输出抑制层遮挡，直至任务超时。当前服务器侧还会静默忽略受控输入拒绝结果，使传输问题只能等待任务级超时才暴露。

## 目标

1. 受控 PTY 脚本在 Bash、Zsh 和 Fish 中都能被准确追踪，内部脚本不显示在终端。
2. 受控输入未被服务器接受时快速失败，任务结束、取消或超时后立即恢复普通终端输入。
3. SFTP 再次打开同一会话目录时立即呈现最近成功结果，并在后台刷新。
4. 合并同一路径的并发刷新，避免首屏后的补偿刷新、手动刷新和操作后刷新互相叠加。
5. 保留服务器实时结果的权威性，不让缓存参与安全判断或写操作前置校验。
6. 增加可持续执行的真实 VPS 性能回归，并以三轮独立自检验收。

## 非目标

- 不在 SSH 成功后自动建立额外 SFTP 连接；
- 不持久化远端目录内容；
- 不降低主机指纹、会话身份或文件安全校验；
- 不通过延长任务超时掩盖协议错误；
- 不改动 VPS 现有服务或业务文件。

## 设计

### 1. 单一顶层受控命令

PTY 协议构建器把现有复合包装脚本放入一个顶层 `sh -c` 命令。交互 Shell 只观察到一个完整简单命令，内部脚本仍以 Base64 传入并由受控子 Shell 执行。

客户端继续使用当前会话 nonce 和完整顶层命令做精确匹配；匹配成功后才解除命令回显抑制并把受控提交标记为已观察。任务边界 token、有效 UID/用户名和退出码校验保持不变。

该方案不接受宽松前缀匹配，也不信任远端普通文本伪造的边界。

### 2. 受控输入确认与快速失败

终端服务器在处理 `managed-input` 后返回只含请求 ID 和状态的控制消息：

- `accepted`：请求通过校验并开始写入；
- `written`：全部分块和回车已写入 PTY；
- `rejected`：请求无效、已有写入进行或终端已释放；
- `interrupted`：未发送尾部已丢弃并写入 Ctrl+C。

状态只能按 `accepted` → `written` 或 `accepted` → `interrupted` 前进，`rejected` 是未接受请求的终态；`written` 只表示内容已写入 PTY，不表示远端脚本执行完成。控制消息不得回传命令正文。客户端等待 `accepted` 的上限为 2 秒；`rejected` 或确认超时会立即取消预期提交、解除输出抑制并返回明确错误，不再等待 30 秒任务超时。

终端 WebSocket 建立时由服务器声明受控输入协议版本。客户端只有确认版本兼容后才能发送 `managed-input`；缺少能力声明时快速失败，不得降级为普通终端输入。

任务级超时和取消路径统一清理提交 token、输出订阅和抑制状态。只有无法确认提示符恢复时才保持恢复锁；观察到新提示符后自动解锁。

### 3. SFTP 会话内短期缓存

目录缓存仅保存在渲染进程内存中，键由以下字段组成：

- SSH 会话代次；
- 主机、端口和登录用户；
- 文件操作身份/后端类型；
- 规范化远端路径。

缓存保存最近一次成功列表和时间，采用 30 秒 TTL，并按会话使用最多 32 个路径的 LRU 上限。再次打开相同目录时，未过期的列表会在一个渲染帧内显示，并标注“正在刷新”；后台仍发起权威读取。过期条目不用于首屏展示。重连、身份变化、标签关闭或后端变化会立即失效对应缓存。

刷新失败时保留旧列表，并显示“正在显示上次结果，刷新失败”，不得把旧列表标记为最新。新建、删除、重命名、上传和下载后的可见结果仍以服务器响应和后续刷新为准。

### 4. 刷新合并与状态呈现

同一缓存键在任一时刻只允许一个目录读取请求。后续自动刷新、补偿刷新或手动刷新复用进行中的 Promise；不同路径或不同会话仍可独立执行。

首次连接按阶段显示：

1. 正在建立 SFTP 通道；
2. 正在读取目标目录；
3. 已显示缓存，正在刷新；
4. 刷新完成或显示上次结果。

刷新期间不清空已有列表，不阻塞切回终端。手动刷新必须在 100ms 内出现可见反馈。

### 5. 性能与可观测性

新增或扩展性能指标：

- `managed_input_ack_ms`；
- `operations_first_output_ms`；
- `operations_total_ms`；
- `first_sftp_ready_ms`；
- `sftp_cached_paint_ms`；
- `sftp_refresh_ms`；
- 合并的刷新请求数。

指标不包含主机、账号、命令、路径或目录内容。

## 安全与兼容性

- 继续校验 SSH 主机指纹、终端 PID、SSH 会话代次和登录身份；
- 缓存不能跨会话、跨身份或跨服务器复用；
- 受控输入确认消息通过现有本地终端 WebSocket 返回，必须验证请求 ID；
- 旧客户端/新服务器组合不得把内部脚本降级为普通终端输入；协议不兼容时快速失败；
- Bash、Zsh、Fish 和非 UTF-8 终端编码需要覆盖回归；
- SFTP 缓存只优化展示，不改变写操作合同或安全删除流程。

## 测试与验收

实现采用测试驱动：先添加失败测试，再修改生产代码。

自动化覆盖：

1. 顶层命令在 Bash/Zsh/Fish 的命令记录中可精确匹配；
2. 受控输入 `accepted/written/rejected/interrupted` 状态及超时清理；
3. 任务完成、取消、超时和断线后无残留租约或提交记录；
4. SFTP 缓存键隔离、重连失效、失败保留旧列表和同路径刷新合并；
5. 性能指标完整且不包含敏感字段。

真实 VPS 三轮自检：

- 第一轮：普通终端输入、系统概览和健康基线；验证无内部脚本、任务完成、输入立即恢复；
- 第二轮：SFTP 首开、连续刷新、目录切换和终端/SFTP 往返；记录首屏与刷新耗时；
- 第三轮：任务取消、SSH 重连和 SFTP 重开；验证恢复锁、缓存隔离与终端输入。

验收预算：

- SFTP 首次首屏在当前 VPS 上不高于 3 秒；
- 同会话缓存首屏不高于 100ms；
- 手动刷新反馈不高于 100ms；
- 受控输入拒绝或传输确认失败在 2 秒内明确返回；
- 三轮结束后无 PTY 租约、待提交命令或远端临时沙箱残留。
