# ShellPilot 当前 root Shell 远程文件操作设计

## 1. 背景与根因

ShellPilot 的一个 SSH 标签页同时存在两个彼此独立的远端执行上下文：

- 交互式终端 PTY。用户以书签账号登录后，可以在该 PTY 中执行 `su root`、`su - root`、`sudo -i` 或 `sudo -s`，从而让当前 Shell 的有效 UID 变为 0。
- SFTP 通道。它是使用书签账号在同一 SSH 连接上新建的独立子系统通道，其进程身份始终是最初通过 SSH 认证的账号。

2026-08-22 的“当前终端有效身份”改动已经让运维任务和抓包复用当前 PTY，因此这些任务能够继承 `su` 后的 root 身份。但该设计有意把 SFTP 排除在外，并在测试和用户指南中规定 SFTP 继续使用登录账号。

当前远程文件面板仍直接调用 `this.sftp.list/readFile/writeFile/rename/rm/chmod` 等接口。双击远程文件时，读取由 SFTP 完成；编辑器保存和其他修改还会通过以 SFTP 为传输层的安全事务创建快照、暂存、替换和验证。因此，仅修改标签页用户名、root 提示文案或 `username === 'root'` 判断都不能改变真实执行身份。

这正是问题反复出现的根因：客户端已经能确认当前 PTY 是 root，但远程文件面板没有统一的“有效文件操作身份”和可继承该身份的文件后端。

## 2. 目标

1. 书签登录账号不是 root、当前 SSH 终端已经真实进入 UID 0 Shell 时，整个远程文件面板自动使用该 root 能力。
2. root 文件能力覆盖目录浏览、属性读取、文件读取、双击编辑、保存、上传、下载、新建、改名、安全删除、快速删除、chmod、批量操作和目录操作。
3. 用户退出 root Shell 后，下一次文件操作重新探测身份并自动恢复原生 SFTP，不复用旧 root 状态。
4. 登录身份与文件操作身份保持分离。书签、SSH/SFTP 认证端点、主机密钥和审计连接身份继续记录真实登录账号。
5. root 模式继续保留传输进度、暂停、取消、完整性校验、安全确认、恢复快照、结果验证和历史记录。
6. 不保存或重放 `su` 密码，不启动服务器常驻 root 代理，不把 root 能力扩散到其他标签页、其他服务器或后台 SSH exec。

## 3. 非目标与平台边界

- 不尝试把已经建立的 SFTP 子系统进程“变成 root”；SSH/SFTP 协议不支持让交互式 `su` 改变其他通道身份。
- 不把 `tab.username`、书签用户名或 SFTP 端点用户名改写为 root。
- 不根据提示符中的 `#`、窗口标题、当前目录或历史命令猜测身份。
- 不部署常驻 root 守护进程、文件代理、FIFO 队列或可被登录用户长期复用的 root capability。
- 不让普通 FTP、非 SSH 标签页或没有 POSIX Shell 的远端进入 root 文件模式。
- 首期支持能够运行当前 Shell Integration，并提供 `sh`、`id`、`base64`、`stat`、`mkdir`、`cp`、`mv`、`rm`、`chmod`、`chown` 以及 SHA-256 工具（`sha256sum` 或 `shasum -a 256`）的 SSH 服务器。能力缺失时明确说明 root 文件后端不可用，并保持原生 SFTP 行为。

## 4. 方案选择

采用“统一有效身份协调器 + 双远程文件后端 + SFTP 暂存传输”方案。

对比过的替代方案：

1. **常驻 root 文件代理。** 性能和并发能力较好，但会在服务器留下高权限服务或可轮询的命令队列。登录用户一旦取得代理令牌，就可能在离开 root Shell 后继续使用权限，生命周期和攻击面不符合本项目的安全边界。
2. **权限失败后局部 PTY 回退。** 改动较小，但无法浏览登录用户无权列出的目录，会形成“列表由普通用户读取、修改由 root 执行”的混合状态，也不能彻底覆盖传输、批量和恢复。
3. **统一双后端。** 每次操作重新确认当前 PTY 身份，UID 0 时让整个文件面板使用 root 后端；文件字节仍由 SFTP 暂存传输。该方案不新增持久权限，能够覆盖完整动作矩阵，并复用现有传输和安全事务能力。

## 5. 身份与能力模型

同一标签页公开三类不能混用的状态：

| 状态 | 来源 | 用途 | 生命周期 |
| --- | --- | --- | --- |
| `connectionIdentity` | SSH 书签和已验证端点 | SSH/SFTP 登录、端点键、主机绑定、审计 | SSH 会话 |
| `effectiveShellIdentity` | 当前 PTY 内的 `id -u`、`id -un` | 判断本次操作是否可使用当前 Shell 权限 | 单次探测 |
| `remoteFileCapability` | 身份协调器结合端点、终端状态和能力探测生成 | 为一次文件操作选择 `sftp` 或 `pty-root` 后端 | 单次操作租约 |

界面可以保留最近一次成功探测结果用于展示，但缓存结果不能授权文件操作。每次实际操作都必须重新取得同一标签页终端的独占租约，在租约内探测身份与所需命令能力。

只有同时满足以下条件才生成 `pty-root` 文件 capability：

- 标签页仍是同一个 SSH 会话；
- tabId、终端 PID、SSH 主机、端口、登录用户名和主机密钥指纹与文件面板完全一致；
- 终端处于可追踪的普通空提示符，没有密码提示、TUI 或待执行输入；
- PTY 探测返回合法的 UID `0` 和非空用户名；
- root 文件协议所需的命令能力通过本次探测。

如果探测返回非零 UID，文件面板选择原生 SFTP。如果探测因终端忙碌、密码提示、TUI 或跟踪失败而无法完成，自动刷新保持现有列表，用户发起的操作默认停止并说明原因；界面可以提供明确标注的“仅以登录账号使用 SFTP”重试入口，但不得依据旧 root 缓存静默降级后继续操作。

## 6. 组件与边界

### 6.1 有效文件身份协调器

在终端侧新增面向远程文件操作的 capability 入口，复用现有 Managed PTY 控制器的端点校验、Shell Integration 重跟踪、随机令牌、输出订阅、超时、取消和身份一致性检查。

协调器负责：

- 解析与 SFTP 面板属于同一标签页的终端实例；
- 获取一次独占 PTY 租约；
- 探测有效 UID、用户名和 root 文件协议能力；
- 返回绑定本次租约、端点和身份的不可变 capability；
- 在完成、取消、失败、断线或身份异常后释放或锁定租约。

协调器不把有效身份写回 Store 的标签页配置，也不提供跨操作复用的 root 令牌。

### 6.2 统一远程文件后端接口

文件面板通过一个传输无关的接口访问远端文件，至少覆盖：

- `list`、`lstat`、`realpath`、`readlink`；
- `readFile`、`writeFile`、上传和下载准备；
- `mkdir`、`rename`、`rm`、递归目录删除；
- `chmod` 以及安全事务需要的受限元数据操作；
- 快照、暂存、原状态校验、执行后校验和回滚。

原生后端包装现有 SFTP 客户端。root 后端使用本次 PTY capability 执行控制命令，并把文件字节传输委托给会话专属的 SFTP 暂存区。

`sftp-entry.jsx`、`file-item.jsx`、传输计划和安全事务不得再直接假设 `this.sftp` 是唯一远端文件 transport。所有动作在开始时解析一次后端，并在该动作的整个生命周期内使用同一个 capability。

### 6.3 root PTY 文件协议

root 文件协议与现有运维 PTY 协议使用不同的 marker 名称、操作类型和解析器，避免任务输出与文件控制帧互相接受。

协议要求：

- 每次操作使用密码学随机令牌；
- 路径、文件名和其他字符串字段先编码后传输，不直接插入 Shell 源码；
- 命令只接受固定的操作枚举和有界参数结构；
- 目录项和结果元数据使用不可见的 OSC 控制帧分块返回；
- 每一块携带令牌、序号、总块数和有限长度负载；
- 解析器拒绝错误令牌、乱序、重复、缺块、非法 UTF-8、超限数据和不匹配的结束状态；
- Shell Integration 完成事件与协议结束帧必须同时确认相同退出码；
- 文件内容和凭据不得作为普通终端输出返回。

协议支持空格、中文、引号、换行、通配符和前导短横线等合法 POSIX 文件名。NUL 和 `/` 仍按 POSIX 路径规则处理。远端输出中的相似文本不能伪造协议帧或成功结果。

### 6.4 会话专属暂存区

文件字节通过登录账号可以访问、但与其他账号隔离的会话暂存区传输。原生 SFTP 先在其已验证家目录下创建 `.shellpilot-privileged-transfers/<session-token>/<operation-token>`，使用独占创建与 `0700` 权限；root PTY 不自行猜测 SFTP 家目录。暂存区绑定连接端点、随机会话标识和当前操作标识。

首次生成 root 文件 capability 时必须执行双通道握手：SFTP 在候选目录中创建带随机内容的探测文件并读取 `lstat/realpath`，root PTY 只检查客户端传入的编码候选绝对路径，验证同一随机内容、目录 uid/gid、mode 和非符号链接状态，再写回另一个随机响应；SFTP 必须能够从同一候选目录读取该响应。只有双向内容和元数据都匹配，才证明 SFTP 与 root Shell 看到的是同一个目录。

SFTP chroot、虚拟根或服务端路径映射导致任一步不一致时，root 文件后端标记为不可用。客户端不得搜索服务器目录来猜测真实宿主机路径，也不得把固定路径当作回退。

暂存实现必须：

- 拒绝已存在路径、符号链接和规范化后逃逸；
- 验证候选目录由本次 SFTP 登录 uid/gid 拥有且 mode 为 `0700`，root 生成的传输文件在交给 SFTP 前恢复为该 uid/gid；
- 对每个暂存文件记录大小、摘要、类型和操作方向；
- 只允许本次登录账号通过 SFTP 访问对应暂存对象；
- 完成或明确失败后清理；
- 对断线、取消或结果未知的对象写入受限清理记录；
- 重连后只在端点、主机密钥、登录身份和事务令牌完全匹配且再次取得所需 root capability 时清理。

不使用固定 `/tmp` 文件名，也不扫描或删除不属于 ShellPilot 当前端点的远端目录。

## 7. 文件操作数据流

### 7.1 面板激活与身份展示

进入远程文件面板时可以执行一次只读探测，显示：

```text
SSH 登录：hik
文件操作：root（来自当前终端）
```

该状态只用于展示。真正的列表刷新、打开文件或修改操作开始时再次探测。探测为非 root 后立即显示真实登录账号；探测不可用时显示“文件操作：未知”，不宣称拥有 root 权限。

### 7.2 目录浏览和元数据

1. 解析同一标签页终端并校验完整端点。
2. 获取短期 PTY 租约并探测身份。
3. UID 0 时由 root 后端执行有界 `list/lstat/readlink` 操作，以控制帧返回目录项和元数据。
4. 非零 UID 时由原生 SFTP 执行同一后端接口。
5. 文件面板消费统一结果，更新路径、文件树、owner/group、选择和历史。
6. 成功或明确失败后释放租约。

目录列表必须有条目数、总元数据字节和单项字段长度上限。超限时显示可操作的错误，不返回不完整列表冒充成功。

### 7.3 双击编辑和文本保存

打开远程文件时，文件面板通过已解析后端读取，不再由 `file-item.jsx` 直接调用 `sftp.readFile`。

root 读取流程：

1. 在 PTY 租约内对目标执行 `lstat`，拒绝非预期类型和符号链接替换。
2. root 将目标复制到本次暂存对象并计算大小与摘要。
3. 原生 SFTP 读取暂存对象；客户端校验收到内容的大小和摘要。
4. root 清理暂存对象，编辑器显示内容和原始指纹。

root 保存流程：

1. 客户端对编辑内容计算摘要，并通过原生 SFTP 写入上传暂存对象。
2. root 后端重新验证上传暂存对象摘要和目标原始指纹。
3. 通过安全事务创建目标恢复快照。
4. 在目标父目录创建同文件系统暂存项，写入内容并应用约定的 mode、uid、gid。
5. 原子替换目标并验证最终摘要和元数据。
6. 清理上传暂存项；成功后关闭或刷新编辑器。

任何阶段失败都保留编辑器文本和打开状态。原始目标未通过替换前不得改变；替换后验证失败则进入可恢复失败状态。

### 7.4 上传、下载和目录传输

root 上传把现有传输管线的远端目标改为会话暂存对象。SFTP 完成传输和源摘要校验后，root 后端才创建恢复点、验证暂存树清单并把内容安装到真实目标。

root 下载先由 root 后端把目标的固定快照复制到暂存区并生成受限清单，随后现有 SFTP 下载管线从该固定快照读取。下载完成后校验本地内容与远端固定快照摘要，再清理暂存区。

目录操作使用已固定、排序且有预算限制的描述树。暂存期间新增、删除或改变的源项不能未经校验进入本次传输。大文件内容不经过 PTY，现有进度、速度、任务数、暂停、继续和取消能力保持可用。

特权传输在整个生命周期内持有 root 文件 capability 租约。租约存在时终端拒绝普通输入和其他自动任务；`Ctrl+C` 取消当前传输及其控制阶段。这样用户不能在传输安装前退出 root，使操作身份在中途变化。

### 7.5 创建、改名、权限和删除

创建、改名、chmod、安全删除及快速删除均调用本次解析出的统一后端。

- 创建、改名和 chmod 继续经过现有确认与恢复策略。
- 安全删除继续创建并验证恢复快照。
- 快速删除不创建恢复点，仍显示一次明确的不可恢复危险确认，并应用现有受保护路径规则。
- 批量操作在一个已确认身份和端点的 capability 下执行，限制并发并保留逐项结果。
- root 模式不能降低任何现有确认级别或绕过 `.shellpilot-transactions`、`.shellpilot-backups` 等受保护路径规则。

## 8. 安全事务与恢复

现有 SFTP 安全事务适配器需要抽离对具体 SFTP transport 的假设，使原生 SFTP 后端和 root 后端实现相同的准备、验证、执行和回滚契约。

事务端点继续使用真实的 `connectionUsername@host:port`、tabId、终端 PID、session type 和主机密钥指纹。事务运行证据新增：

```text
channel: pty-root
effectiveUid: 0
effectiveUsername: root
```

运行证据不能替换端点键，也不能授权其他操作。

root 模式创建的快照由 root 后端管理。用户退出 root 后查看记录仍然可见，但执行回滚前必须重新取得同一端点的 UID 0 capability。无法取得时提示用户回到对应终端重新进入 root 后重试，不能改用普通 SFTP 或标记为已恢复。

客户端崩溃、断线或结果未知时保留事务阶段和清理证据。启动恢复只能读取受限记录，不自动重放任何可能已经执行的远端修改。

## 9. 错误处理和取消

- **终端忙碌、密码提示或 TUI：** 命令尚未发送，提示用户结束当前交互程序后重试。
- **Shell Integration 无法重跟踪：** 命令尚未发送，不采用无法确认退出码的粘贴方式。
- **身份探测失败：** 文件操作停止；不使用提示符或旧缓存授权。
- **探测为普通用户：** 新操作使用原生 SFTP，并立即更新身份展示。
- **root 能力执行中身份不一致：** 取消当前操作，保留事务与暂存证据，不继续后续步骤。
- **协议帧缺失或非法：** 结果视为未知，发送一次取消并等待可确认提示符恢复。
- **用户取消：** 同时取消 SFTP 传输和当前 PTY 控制命令，等待双方收口后清理。
- **取消结果未知：** 终端保持锁定，要求重连；不得宣称取消或清理成功。
- **连接断开：** 清理本地监听器，记录远端事务和暂存状态；新会话拒绝旧令牌迟到结果。
- **摘要或原状态不匹配：** 停止安装或替换，保留原目标并报告文件已变化。
- **只读文件系统、ACL/SELinux、不可变属性或服务限制：** 返回真实 root 操作错误，不把 UID 0 等同于无限权限。
- **能力命令缺失：** 明确列出缺失能力，root 文件模式不可用；普通 SFTP 功能保持原行为。

## 10. 界面行为

远程面板标题同时显示登录身份和文件操作身份，不再用单个 `{username}@{host}` 暗示所有动作都使用该用户：

```text
远程：hik@example.com
文件操作：root（当前终端）
```

root 文件 capability 占用终端时，远程面板和终端显示同一运行状态及取消入口。长传输明确提示终端暂时不能接受输入。

错误信息必须说明：

- 实际执行后端是原生 SFTP 还是当前 root Shell；
- 登录账号与本次有效账号；
- 失败阶段是身份探测、暂存、快照、传输、安装、替换、验证、清理还是恢复；
- 编辑内容、恢复记录或暂存清理是否仍然保留。

## 11. 测试策略

### 11.1 失败回归测试

先增加能够稳定复现旧问题的测试：书签用户为 `hik`，当前 PTY 已进入 UID 0/root，但双击和保存 root-only 文件仍调用普通 SFTP 并得到权限错误。测试必须在生产代码修改前失败，并明确证明失败来自缺少统一文件 capability，而不是测试配置错误。

### 11.2 单元测试

- 每次操作重新探测身份；UID 0 选择 root 后端，非零 UID 选择 SFTP。
- 展示缓存不能授权操作，执行 `exit` 后下一次操作恢复 SFTP。
- 端点、主机密钥、tabId、PID 或登录账号变化时 capability 失效。
- 目录浏览、属性、读取、保存、上传、下载、创建、改名、两种删除、chmod、批量和目录动作都经过统一后端。
- 路径含空格、中文、引号、换行、通配符、前导短横线和 Shell 元字符时不会进入命令结构。
- 控制帧跨块、乱序、重复、缺失、错误令牌、非法 UTF-8、超限和错误退出码均失败关闭。
- 暂存目录拒绝预存在、符号链接、路径逃逸、端点错配和旧令牌。
- 空文件、文本、二进制、大文件和目录描述树的大小、摘要、类型和元数据验证正确。
- 编辑保存和上传遵循快照、暂存、原状态校验、原子替换与结果验证顺序。
- 保存失败保留编辑器内容，loading 和确认状态正常复位。
- root 恢复记录在非 root 状态下不可执行；重新进入 root 后可验证并恢复。
- terminal busy、密码提示、TUI、断线、超时、取消和取消结果未知正确收口。
- root 能力不写回书签、标签页用户名或 SFTP endpoint，不泄漏到其他标签页。

  -> 当前终端 exit

## 12. 验收标准

1. 书签使用非 root 账号登录、当前终端真实有效 UID 为 0 时，整个远程文件面板自动使用 root capability。
2. 用户可以浏览登录账号无权列出的目录，并能双击读取、修改和安全保存 root-only 文件。
3. 上传、下载、创建、改名、删除、chmod、批量和目录操作与双击编辑使用同一个有效文件身份。
4. 大文件内容通过 SFTP 暂存传输，进度、暂停、取消和摘要验证不退化。
5. 所有修改类操作保留现有确认、快照、验证和恢复边界；快速删除仍明确不可恢复。
6. 用户退出 root 后，下一次操作重新识别普通 UID 并恢复原生 SFTP，不沿用 root 缓存。
7. 界面同时、准确显示登录账号和文件操作身份，不把 SSH/SFTP 登录身份伪装为 root。
8. 无法确认身份、端点或执行结果时失败关闭，不静默降权、提权或伪造成功。
9. 不保存 `su` 密码，不部署常驻 root 代理，不让权限跨标签页、跨服务器或跨会话传播。
10. 自动化测试、lint、E2E、构建和性能门槛全部满足。
