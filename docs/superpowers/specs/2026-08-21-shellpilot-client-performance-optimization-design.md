# ShellPilot 客户端交互性能优化设计

**日期：** 2026-08-21
**目标版本：** ShellPilot 0.4.35 后续版本
**状态：** 已确认，待实施计划

## 背景与证据

用户反馈当前客户端整体操作发卡，最明显的表现是 AI 对话输入时字符响应迟缓。现有性能门禁覆盖启动、首个窗口可交互、终端就绪、内存、AI 首字和 AI 总响应时间，但没有覆盖按键到界面更新的交互延迟，因此历史性能报告通过并不能证明输入流畅。

根因调查确认 AI 输入热路径存在重复工作：

- `AIChat` 的 `prompt` 状态在每次输入时更新并触发组件渲染。
- 每次渲染都会调用 `getAIChatHistoryForScope()`。
- 该选择器在筛选会话前调用 `normalizeAIChatHistoryForStorage()`，重复遍历、清洗并重建全部历史消息。
- `AIChatHistoryItem` 虽然使用 `memo`，但重建后的消息对象失去引用稳定性，导致最多 24 条可见 Markdown 消息重新渲染。
- 在 100 条、总计约 158 万字符的历史数据上，单次范围选择的实测中位数为 81.287ms，P95 为 99.14ms，最大值为 110.823ms；100 条消息中保留原对象引用的数量为 0。

现有启动加载、历史追加和消息更新路径已经执行安全清洗，因此渲染阶段的重复清洗不是安全边界，可以移出热路径。

## 目标

1. 消除 AI 输入热路径中的全历史重复清洗和无关 Markdown 重渲染。
2. 在 100 条、约 150 万字符历史下，将连续输入的按键响应 P95 控制在 50ms 以内，且不丢字。
3. 为已加载 AI 面板、右侧面板切换和设置中心建立可重复的交互性能门禁。
4. 保留现有启动、内存、终端和 AI 请求性能门禁。
5. 通过测量区分 JavaScript、React 渲染和样式绘制成本，只优化超过预算的具体路径。

## 非目标

- 不重写全局状态管理框架。
- 不改变 AI 对话、Agent、附件、流式输出、停止、重试或清空历史的产品行为。
- 不降低现有视觉层级或统一移除阴影、过渡效果；只有性能记录证明样式绘制超标时才调整具体样式。
- 不为已经满足预算的模块做无关重构。
- 不在生产环境逐键持久化性能日志。

## 采用方案

采用“指标驱动的分阶段优化”：先修复已证实的 AI 输入热路径，再用稳定的交互预算检查客户端其他高频入口。该方案比只修输入框覆盖面更完整，同时避免全局状态重构带来的高回归风险。

## 架构与组件边界

### 历史规范化边界

`src/client/components/ai/ai-chat-actions.js` 保留以下安全边界：

- `normalizeAIChatHistoryOnStartup()` 在加载持久化历史时规范化旧数据并恢复中断状态。
- `appendAIChatHistory()` 只规范化新增消息，再与已经可信的历史合并和执行容量裁剪；不重建未变化消息。
- `updateAIChatHistoryEntry()` 仅规范化发生变化的消息，并保留其他历史消息的对象引用。
- `removeAiHistory()` 改为不可变数组赋值，确保删除操作产生新的历史数组引用。
- 旧历史迁移和重试消息创建继续经过规范化。

`getAIChatHistoryForScope()` 改为纯选择器：只处理数组兜底、会话 ID 比较和筛选，不再执行凭据清洗或消息对象重建。该选择器返回原历史中的消息对象，使未变化消息保持引用稳定。

### AI 编排边界

`src/client/components/ai/ai-chat.jsx` 使用 `useMemo`，以 `props.aiChatHistory` 和 `conversationScopeId` 为失效条件缓存当前会话历史。活动请求从同一份范围结果派生，避免一次渲染内重复筛选。

输入内容仍由 AI 编排组件管理，以保持外部 `refsStatic` 的 `setPrompt` 和 `handleSubmit` 接口兼容。按键引发的父组件渲染允许更新输入区、发送状态和轻量工具栏，但不会重新计算或重绘历史内容。

### 历史渲染边界

`src/client/components/ai/ai-chat-history.jsx` 建立显式 memo 边界，并通过 props 接收历史、Agent 运行状态和配置版本依赖。历史子树仅在以下条件变化时更新：

- 当前会话历史数组引用变化；
- Agent 运行状态变化；
- AI 配置凭据版本变化；
- 历史窗口的内部分页、未读或滚动状态变化。

流式响应和 Agent 状态更新仍通过新的历史数组与被替换的消息对象触发更新；未变化的已完成消息继续由 `AIChatHistoryItem` 的 memo 边界跳过。

### 交互性能门禁

新增独立客户端交互性能场景，并纳入 `npm run test-performance-e2e`：

| 场景 | 固定数据条件 | 预算 |
| --- | --- | --- |
| AI 连续输入 | 100 条历史、约 150 万字符、24 条可见消息 | 按键响应 P95 ≤ 50ms |
| 已加载 AI 面板打开 | AI 模块已经完成首次懒加载 | ≤ 250ms |
| 右侧面板切换 | AI 与终端信息均已加载 | ≤ 250ms |
| 设置中心打开 | 主窗口已交互、设置入口可用 | ≤ 500ms |

输入延迟从输入事件开始测量，到 React 提交后的下一稳定动画帧结束。测试记录每次采样并计算 P95，同时断言最终输入值完整。测试性能数据只存在于测试进程，不写入用户配置或本地性能历史。

现有 `test/e2e/029.performance-baseline.spec.js` 的启动、终端、内存、AI 首字和 AI 总时间预算保持不变。新的交互场景使用隔离数据目录、确定性历史数据和已编译的真实 Electron 渲染器。

## 数据流

### 启动

1. 持久化层读取 `aiChatHistory`。
2. `normalizeAIChatHistoryOnStartup()` 清洗凭据、修复旧字段并恢复中断消息。
3. 规范化后的数组进入 store，成为渲染与后续更新的可信内存模型。

### 输入

1. 文本框接收输入事件并更新 `prompt`。
2. `AIChat` 重新渲染输入区。
3. 因历史数组和会话 ID 未变化，范围选择缓存命中。
4. 因历史 props、Agent 状态和配置版本未变化，历史子树跳过渲染。
5. 浏览器提交文本框更新并完成下一稳定动画帧。

### 消息更新

1. 提交、流式内容、停止、失败或 Agent 状态产生消息更新。
2. 更新函数规范化变化字段并替换目标消息。
3. store 发布新的历史数组，未变化消息保留原对象引用。
4. 范围选择重新计算，历史容器更新。
5. 只有变化消息及必要的滚动、未读状态重新渲染。

## 缓存失效与错误处理

- 历史数组引用变化时重新筛选，避免流式内容或清空历史不刷新。
- 会话 ID 变化时重新筛选，避免跨标签串消息。
- 配置凭据版本变化时刷新历史项请求配置，避免重试使用过期配置。
- 旧版、空值或非数组历史在启动边界转为安全数组；快速选择器只对可信内存模型工作。
- 直接删除消息使用不可变数组赋值，既触发缓存失效，也保持剩余消息引用。
- 中文输入法组合事件、传统 `keyCode 229` 防护、Shift+Enter、附件粘贴和拖放行为保持不变。
- 如果交互门禁仍超标，先采集主线程长任务、React 提交和绘制耗时，确认单一瓶颈后再修改对应组件；不叠加未经验证的优化。

## 测试策略

实施遵循测试先行：

1. 新增失败的单元测试，证明范围选择器应保留未变化消息引用，并且活动请求可以从已筛选历史派生。
2. 运行该测试并确认它因当前全历史规范化和对象重建而失败。
3. 实现最小的数据边界与 memo 调整，使单元测试通过。
4. 新增长历史 Electron 交互测试，先在当前实现上确认 P95 超过 50ms或历史渲染次数不满足约束。
5. 验证优化后 P95、最终输入值、中文输入法、Shift+Enter 和流式更新。
6. 运行 AI 聊天布局、稳定性、提交、取消、历史窗口、滚动和长历史相关单元测试。
7. 运行 AI E2E 与完整性能 E2E。
8. 运行 `npm run lint`、完整 `npm run test-unit-ci` 和 `npm run b`。

回归测试不得只检查源码正则；引用稳定性使用真实函数断言，交互预算使用真实 Electron 页面测量。

## 实施阶段

### 阶段一：AI 热路径

- 建立失败的引用稳定性与活动请求派生测试。
- 将规范化固定在加载和写入边界。
- 缓存当前会话历史并建立历史 memo 边界。
- 验证 AI 长历史输入门禁。

### 阶段二：客户端交互门禁

- 增加已加载 AI 面板、右侧面板和设置中心场景。
- 记录 JavaScript、React 提交和绘制阶段耗时。
- 对超过预算的单一组件做最小优化；满足预算的路径只保留回归门禁。

### 阶段三：发布验证

- 运行相关和完整自动化验证。
- 构建生产前端，确认现有懒加载与功能边界未回退。
- 记录优化前后长历史输入 P50、P95、最大值和各交互门禁结果。

## 完成标准

- AI 长历史连续输入 P95 不超过 50ms，最终文本完整。
- 已加载 AI 面板、右侧面板切换和设置中心满足各自预算。
- 未变化历史消息在范围选择和历史更新中保持对象引用。
- 流式回复、Agent 状态、配置版本和跨标签会话仍能正确刷新。
- 所有相关单元测试、AI E2E、性能 E2E、lint、完整 unit-ci 与生产构建通过。
- 用户已有未提交修改不被覆盖或纳入本次提交。
