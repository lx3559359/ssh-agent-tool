# ShellPilot 故障档案闭环设计

日期：2026-07-29
状态：设计已确认，等待实施计划
目标版本：分阶段交付，不绑定单一版本号

## 1. 背景

ShellPilot 已具备 SSH、SFTP、AI 助手、服务器状态、运维工具、安全操作中心、备份回滚和成果物等能力，但一次排障产生的信息仍分散在终端、AI 对话、日志、任务记录和备份记录中。用户完成故障处理后，排查经验没有形成可持续复用的个人资产；再次遇到相似问题时，仍需要重新查找日志、回忆命令和整理结论。

本设计面向单人运维、站长和运维初学者，建立本地优先的“故障档案闭环”。它把问题现象、排查证据、执行过程、安全修改、验证结果和复盘报告关联为同一条可搜索、可继续、可导出、可选同步的记录。

产品粘性来自用户长期积累的可信排障经验，而不是增加无法沉淀价值的入口或提醒。

## 2. 目标

1. 将一次故障从发现、排查、处理、验证到归档形成完整生命周期。
2. 复用现有 SSH、SFTP、AI、运维工具和安全操作能力，不改写终端核心。
3. 让历史故障可搜索、可比较，并能安全复用已验证的只读检查步骤。
4. 默认本地保存，支持用户选择 WebDAV、Git 或 S3 兼容存储同步。
5. 对凭据和敏感数据设置不可绕过的保存与同步边界。
6. AI 不可用、同步失败或单项证据采集失败时，档案基础功能仍可使用。
7. 支持将完整排障过程生成 Markdown、HTML、PDF 和 DOCX 报告。

## 3. 非目标

1. 首期不建设 ShellPilot 官方账号、官方云存储或多人实时协作。
2. 不静默记录全部终端输入、输出或所有浏览过的 SFTP 文件。
3. 不让历史档案继承旧任务的风险确认或绕过当前安全策略。
4. 不保证所有远程操作都可自动回滚；只能对已有恢复提供方支持的操作展示回滚入口。
5. 不使用故障档案替代现有安全中心、任务中心或成果物中心。
6. 不把 AI 生成的根因在未经用户确认时标记为事实。
7. 首期不强制安装本地向量模型或其他额外运行环境。

## 4. 核心生命周期

故障档案状态统一为：

```text
排查中 -> 等待操作 -> 验证中 -> 已解决/未解决 -> 已归档
```

允许从“排查中”直接结束为“误报”，允许从“已归档”重新打开为“排查中”。任何状态变化都写入时间线。

### 4.1 创建档案

用户可以从以下位置主动创建档案：

- AI 对话消息或工具结果
- 服务器状态异常项
- 运维工具诊断结果
- 安全操作中心记录
- 终端选中内容
- SFTP 文件或日志
- 故障档案入口中的“新建档案”

系统可以在检测到异常时提示“是否建立故障档案”，但不得静默创建档案或记录完整终端会话。

创建时自动关联当前服务器引用、会话、时间和已知服务；用户可以修改标题、严重程度和标签。

### 4.2 收集证据

支持的证据类型包括：

- 终端选中输出或明确引用的命令结果
- AI 对话消息、计划和工具调用结果
- 服务器状态快照
- 运维工具诊断结果
- SFTP 文件、配置片段和日志片段
- 安全操作的修改前快照、备份和回滚信息
- 用户上传的附件、截图和文字说明

每项证据记录来源、采集时间、内容摘要、完整性状态和脱敏状态。大文件默认只保存用户选择的范围、摘要和原文件引用，不自动复制完整内容。

### 4.3 执行排查

AI 可以生成只读排查计划。计划中的每一步展示：

- 目标与原因
- 将要执行的命令或工具
- 风险级别
- 当前状态
- 开始时间、结束时间和耗时
- 输出摘要与原始结果入口

任务支持暂停、取消、跳过和手动补充结论。只读步骤遵循现有免确认规则；涉及修改的步骤继续使用安全事务和二次确认。

### 4.4 安全处理

配置修改、文件变更、服务重启、防火墙、网络和其他风险操作继续由现有安全中心负责。故障档案只保存安全事务的引用和摘要，不复制实现。

档案必须明确展示：

- 修改了什么
- 为什么修改
- 执行者与执行时间
- 修改前备份或恢复点
- 是否支持快捷回滚
- 回滚验证结果

历史档案中的确认不得继承到当前任务。复用历史修改方案时必须重新识别目标服务器、展开真实参数并执行当前风险审查。

### 4.5 验证并关闭

处理完成后必须进入验证阶段。用户可以选择：

- 已解决
- 临时缓解
- 未解决
- 误报

“已解决”需要至少一条人工确认或自动验证结果。验证未通过时，系统不得默认标记为已解决。

### 4.6 形成成果

归档前生成结构化复盘，至少包含：

- 故障摘要
- 影响范围
- 已确认信息
- 暂未确认信息
- 根因
- 排查时间线
- 有效步骤
- 失败尝试
- 修改与回滚
- 验证结果
- 预防建议

支持生成 Markdown、HTML、PDF 和 DOCX。报告生成失败时保留结构化源数据，并提供单独重试，不影响档案本身。

已验证的通用步骤可以由用户主动保存为个人 Skill 或运维脚本，保存前仍需审查权限、参数和风险范围。

### 4.7 再次遇到

ShellPilot 根据服务器、服务、错误码、日志特征和历史结论推荐相似档案。推荐结果必须展示相同点和不同点，不能只显示一个相似度数值。

只读检查步骤可以一键重新执行；所有修改性步骤必须重新审查。命令、路径、服务或环境失效时标记为“需要重新识别”。

## 5. 信息架构与界面

### 5.1 主入口

左侧导航增加“故障档案”，作为独立工作区，不长期占用终端或 AI 对话区域。

故障档案工作区使用两栏布局：

- 左侧：档案列表、搜索和筛选
- 右侧：档案概览、证据、时间线、修改与回滚、验证和报告

列表支持按服务器、服务、状态、严重程度、标签和时间筛选，并支持全文搜索、收藏、置顶和相似故障聚合。

### 5.2 当前任务提示

排障进行时，AI 面板顶部显示一条紧凑任务状态：

```text
INC-20260729-003  Nginx 502  ·  排查中  ·  已完成 4/7
```

点击状态栏打开档案详情。状态栏不得遮挡聊天记录或输入框。

### 5.3 首页摘要

首页增加紧凑摘要，不使用大面积卡片：

- 本周处理故障数
- 尚未解决
- 最近复发
- 最近更新的档案

用户可以从未解决项直接继续排查。

### 5.4 快捷添加证据

终端、AI、服务器状态、运维工具、安全中心和 SFTP 均只增加“加入故障档案”或“建立故障档案”入口，不复制档案管理界面。

如果当前已有进行中的档案，入口优先显示“加入当前档案”，同时允许选择其他档案。

## 7. 组件边界

### 7.1 IncidentRepository

负责档案、标签、状态和关联关系的增删改查，不读取 SSH 凭据，不直接执行远程操作。

### 7.2 EvidenceCollector

通过明确接口接收终端、AI、SFTP、服务器状态、运维工具和安全中心证据。每个来源适配器只负责转换为统一证据结构。

### 7.3 SensitiveDataRedactor

在证据持久化和同步前检测密码、API Key、Token、Cookie、私钥和其他已知凭据格式。无法确认是否安全的内容默认不进入同步包。

### 7.4 IncidentTimeline

将计划、任务、命令结果、备份、回滚和验证统一为时间线事件，不取代原任务存储。

### 7.5 SimilarityMatcher

负责本地全文检索、字段匹配、候选排序和可选 AI 语义重排。AI 不参与时仍能返回确定性结果。

### 7.6 IncidentReporter

从结构化档案生成多格式成果。每种导出格式独立失败、独立重试。

### 7.7 IncidentSyncAdapter

定义 WebDAV、Git 和 S3 的统一同步接口，具体适配器互不依赖。

### 7.8 IncidentStorageManager

负责证据对象去重、压缩、空间统计、保留策略、清理和本地恢复。

## 8. 本地存储与隐私

### 8.1 本地结构

- SQLite 保存档案元数据、状态、时间线和索引。
- 独立对象目录保存附件、配置快照、日志片段和报告。
- 对象以内容摘要寻址，相同内容只保存一次。
- 数据存放在 ShellPilot 用户数据目录下，不写入安装目录。

### 8.2 保存策略

提供三种策略：

- 轻量：仅保存摘要、命令和结论
- 标准：保存关键输出、引用日志和回滚信息，作为默认值
- 完整：保存用户明确选定的全部证据

用户可以查看单个档案和全部档案的占用空间，并配置保留期限与清理规则。

### 8.3 敏感信息边界

以下内容不得进入档案正文、报告或同步包：

- SSH 密码
- API Key
- 私钥正文
- 登录 Cookie
- 访问 Token
- 系统安全存储中的凭据

服务器地址、用户名、内网地址、业务名称和日志内容属于可能敏感信息，保存和导出前应提供脱敏预览。

## 9. 可选同步

同步默认关闭，由用户主动配置。

### 9.1 WebDAV

适合 NAS 和个人网盘，上传加密的完整档案包。

### 9.2 Git

默认只同步 Markdown 报告、脱敏元数据、标签和版本历史，不同步二进制附件和凭据。

### 9.3 S3 兼容存储

适合大附件和长期归档，上传加密的完整档案包。

### 9.4 加密与冲突

- 完整档案包使用带认证的对称加密。
- 跨设备解密密钥由用户同步口令派生，不依赖官方服务器。
- 同步目标的认证信息使用系统安全存储。
- 首期支持手动同步和定时同步，不做实时多人协作。
- 同一档案出现并发修改时保留冲突副本，禁止静默覆盖。
- API Key、SSH 密码和私钥即使经过加密也不进入同步包。

## 10. 相似故障与 AI

### 10.1 本地确定性匹配

本地匹配字段包括：

- 服务器与环境标签
- 操作系统
- 服务名和进程名
- 端口、路径和错误码
- 日志关键词与稳定特征
- 根因分类
- 解决状态

使用 SQLite 全文搜索和字段权重排序，不需要联网。

### 10.2 AI 语义重排

用户启用后，AI 只接收脱敏后的候选摘要，对本地匹配产生的有限候选进行语义重排。AI 不直接扫描全部本地档案，也不决定安全权限。

推荐结果需要解释：

- 相同点
- 不同点
- 可以复用的步骤
- 不能直接复用的步骤
- 需要重新确认的环境信息

### 10.3 反馈闭环

用户可以标记“有帮助”“无关”或“方案已过时”。反馈用于调整本地排序，不自动修改历史根因。

相似问题连续复发时，ShellPilot 可以建议创建定期巡检、告警规则、Skill 或运维脚本，但必须由用户确认创建。

## 11. 错误处理与恢复

1. AI 不可用时，档案创建、编辑、证据保存和全文搜索继续工作。
2. 单项证据采集失败时标记“证据缺失”，不让整个档案创建失败。
3. 报告生成失败时保留结构化源数据，允许按格式重试。
4. 同步失败只影响远端副本，不影响本地档案。
5. 数据库迁移前创建本地备份，迁移失败时恢复旧数据库。
6. 来源文件或任务已删除时保留摘要，并显示“原始来源不可用”。
7. 客户端崩溃后恢复进行中的档案，但不自动继续远程命令。
8. 达到单档案、单附件或总空间上限时停止自动采集，并提示用户选择清理或提高限制。
9. 同步冲突保留两个版本，提供差异比较和手动合并。
10. 本地索引损坏时可从档案元数据重建，不要求重新下载附件。

## 12. 性能约束

1. 档案列表和时间线使用分页或虚拟滚动。
2. 搜索索引与附件对象分离，搜索不扫描原始大文件。
3. 大日志在后台分段处理，不阻塞终端和 UI 主线程。
4. 相似匹配先本地筛选，再把有限候选交给 AI。
5. 未打开故障档案时，不加载报告生成器和同步适配器。
6. 新功能不得增加 SSH 首个终端可用时间的阻断步骤。
7. 10,000 条档案规模下仍需保持可搜索、可分页和可打开。

## 13. 分阶段实施

### 阶段 1：档案基础

- 故障档案入口、列表、详情和状态流转
- 手动创建、标签和文字记录
- SQLite、迁移、备份和空间管理
- 首页未解决故障摘要

### 阶段 2：证据与时间线

- 接入终端、AI、服务器状态、运维工具、SFTP 和安全中心
- 脱敏、来源标记和完整性摘要
- 统一排查时间线
- 从档案继续排查

### 阶段 3：复盘与相似故障

- 多格式复盘报告
- 本地全文检索与相似故障排序
- 只读检查步骤复用
- 用户反馈和复发提醒

### 阶段 4：可选同步

- WebDAV、Git、S3 适配器
- 加密档案包
- 冲突副本与跨电脑恢复
- 导入、导出和同步状态

每个阶段独立测试、独立发布并保留上一版本。前一阶段未通过发布门禁时，不进入下一阶段发布。

## 14. 测试策略

### 14.1 单元测试

- 状态机与非法状态迁移
- 数据模型校验
- 脱敏规则
- 内容摘要和去重
- 本地匹配排序
- 同步冲突检测
- 保存策略和空间限制

### 14.2 集成测试

- 终端、AI、SFTP、服务器状态、运维工具和安全中心证据接入
- 数据库迁移与恢复
- 报告生成失败后的单独重试
- AI 不可用时的本地降级
- 同步失败与冲突副本

### 14.3 端到端测试

- 创建档案并完成完整状态流转
- 从异常服务开始只读排查
- 风险修改关联备份和回滚
- 修复验证后生成报告
- 相似故障推荐与只读步骤复用
- 崩溃后恢复进行中的档案

### 14.4 真实服务器回归

- SSH、Ctrl+C、终端输入和标签页不受影响
- SFTP 浏览、上传、下载、暂停恢复和备份不受影响
- 只读证据采集不修改服务器
- 风险操作继续经过安全事务
- 回滚入口引用正确任务和备份

### 14.5 UI 回归

- 1366x768 与 1920x1080
- Windows 100%、125% 和 150% 缩放
- 日间与夜间主题
- 长标题、长日志、窄 AI 侧栏和窗口缩放
- 关键页面截图基准

## 15. 验收标准

1. 新功能不改变 SSH、终端和 SFTP 的默认行为。
2. 未经用户主动操作，不记录完整终端会话或浏览过的全部文件。
3. AI 不可用时，档案仍可完整查看、编辑和检索。
4. 只读历史步骤无需二次确认；风险操作必须重新审查。
5. 凭据、私钥、API Key、Token 和 Cookie 不进入档案及同步包。
6. 单个大日志不会阻塞客户端界面。
7. 10,000 条档案仍能正常搜索和分页。
8. 数据库迁移失败、同步失败和同步冲突均有恢复路径。
9. 报告生成失败不导致档案或证据丢失。
10. 每个发布版本独立保留，并能回退到上一个稳定版本。

## 16. 成功指标

在不引入强制账号和云服务的前提下，观察以下本地统计；统计默认仅保存在本机：

- 故障档案创建率
- 已解决档案比例
- 从历史档案继续排查的次数
- 相似故障推荐采纳率
- 从档案复用只读步骤的次数
