## 1. 背景与目标

ShellPilot v0.4.26 已完成真实 SSH/SFTP 外部环境验收并在线发布，核心功能可日常使用。最新版交互审计没有发现阻断核心流程的 P0 缺陷，但确认了以下系统性问题：

- 顶部导航、复杂工具页和多面板工作区的信息密度偏高。
- 连接向导、服务器状态、安全中心、运维工具、模型 API 与设置的视觉层级仍可收敛。
- 未配置 AI 面板长期占用工作区，但本轮不得改变其显示行为。
- “终端/SFTP”、SFTP 文件行、设置分类、数值控件和部分图标按钮缺少稳定的辅助技术语义。
- 弹窗打开时，背景内容仍可能出现在 Windows 可访问树中。
- 更新日志直接暴露 Markdown 标记，部分设置文案存在中英文混排或不自然翻译。

本项目在不改变任何业务能力、安全边界和服务器现有服务的前提下，完成已确认的 UI、文案和无障碍优化，执行三轮自检和发布门禁，并统一发布 v0.4.27。

## 2. 成功标准

项目完成必须同时满足：

1. 审计覆盖的 14 个界面完成已确认的可实施优化。
2. 所有现有功能入口、名称、顺序、字段、按钮、数据结构和业务路径保持不变。
3. 允许范围内的 ARIA、标签关联、焦点隔离、焦点恢复和标准键盘语义完成修复。
4. 浅色、深色、常用窗口尺寸和 100%/125%/150% 缩放下无新增遮挡、裁切或溢出。
5. 三轮自检、完整需求回归、Windows 发布资产门禁和在线更新链路全部通过。
6. GitHub 与 ModelScope 均提供相同的 v0.4.27 九项资产，且版本、大小、SHA256 和下载字节一致。
7. 客户端更新中心能从已发布 v0.4.26 识别 v0.4.27。
8. 全程不修改、重启或重载 x-ui、sshd、防火墙、容器、数据库、业务目录或其他服务器现有服务。

## 3. 不可突破的边界

### 3.1 允许的改动

- 主题令牌、颜色、对比度、字号、字重、行高、间距、边框、圆角、阴影和滚动条。
- 现有容器内部的纯展示布局与响应式样式，且不改变信息和入口顺序。
- 为样式增加 `className`、纯展示包装层或复用组件。
- 修正文案中的 Markdown 暴露、英文残留、术语不一致和不自然中文。
- 增加或修正 `role`、`aria-*`、`aria-live`、`aria-labelledby`、`aria-describedby`、标签关联和可访问名称。
- 在不改变业务快捷键的前提下，补齐标准标签页、列表、网格、按钮和弹窗焦点语义。
- 弹窗背景隔离、焦点进入、焦点循环与关闭后的焦点恢复。
- 为以上改动增加单元、契约、端到端和视觉回归测试。

### 3.2 禁止的改动

- 新增、删除、合并、重命名或重新排序功能入口。
- 修改点击、双击、右键、拖拽、传输、终端输入、滚轮、既有快捷键或安全确认行为。
- 修改 store、状态机、数据结构、持久化键、API、IPC、网络请求、权限或回滚机制。
- 修改 SSH、SFTP、AI、运维命令、隧道、更新或服务器状态扫描逻辑。
- 自动收起未配置 AI 面板。
- 新增帮助搜索、帮助目录跳转或其他当前不存在的功能。
- 改变“保存为连接”的默认值。
- 改变连接测试前是否允许直接连接。
- 新增未保存内容确认流程。
- 修改服务器 x-ui、sshd、防火墙、容器、数据库、Web 服务或业务目录。

如果某项优化必须依赖新业务状态、新功能路径或改变用户操作流程才能实现，则停止该项并记录，不以功能改动换取视觉或无障碍结果。

## 4. 实现结构

### 4.1 主题与通用样式层

以现有 Aurora 主题令牌和 Stylus 层为基础，集中实现：

- 主、次、禁用、成功、警告和错误状态的对比度。
- 统一焦点环、按钮、输入框、标签页、弹窗、抽屉、空状态和滚动条。
- 顶部入口的分组、间距、分隔、选中态和窄窗口保真。
- 深色与浅色主题的一致层级。
- 减少重复阴影和卡片套卡片，同时保留 Aurora Lift 的接触阴影、环境阴影和顶部高光。

优先修改：

- `src/client/common/ui-theme-tokens.js`
- `src/client/css/basic.styl`
- `src/client/css/includes/theme.styl`
- `src/client/css/includes/secondary-ui.styl`
- 与被审计界面直接关联的现有局部 Stylus 文件

### 4.2 页面展示层

只允许增加样式类、展示包装和已批准文案修正。事件处理器、业务条件、数据读取和组件公开接口保持不变。

### 4.3 无障碍适配层

无障碍增强复用现有组件和事件：

- 可点击文本补充正确角色与名称，但不得创建第二套业务动作。
- 标签页复用当前切换处理器，补充标准角色、选中状态和关联面板。
- SFTP 行复用当前选中、双击、右键和键盘处理，只补充网格/列表语义与行描述。
- 弹窗复用当前显示和关闭状态，补充背景隔离、初始焦点和焦点恢复。
- 动态状态复用当前状态值，通过 `aria-live` 或等效机制通知，不新增轮询或请求。

## 5. 四批实施范围

### 5.1 第一批：全局框架、主题、导航和通用弹窗

- 顶部全部入口保持现有顺序，通过纯视觉分组降低拥挤。
- 统一顶部、侧栏、按钮、输入框、标签页、图标按钮、滚动条和状态色。
- 强化 hover、pressed、selected、disabled 和 focus 状态。
- 纯图标按钮和窗口控制补充可访问名称与标准按钮语义。
- 弹窗打开时隔离背景可访问内容。
- 弹窗初始焦点、Tab 循环、Escape 关闭与焦点恢复遵循现有关闭规则。
- Toast 避免遮挡标题栏和主要操作。
- 支持系统减少动态效果设置。

### 5.2 第二批：连接向导、终端、SFTP 和 AI 面板

连接向导：

- 压缩无效空白，不改变步骤或字段顺序。
- 为协议、主机、端口、用户名、认证、密码等字段建立显式标签关联。
- 明确必填、可选、建议填写和保存到本机的说明。
- 强化服务器摘要、连接测试状态和下一步动作层级。
- 保留测试前可直接连接和默认保存连接的现有行为。

终端：

- “终端/SFTP”补充标准标签页语义、选中状态和焦点样式。
- 保留现有点击、快捷键、终端输入和会话行为。
- 工具图标补充名称，长标签补充完整内容提示。
- 优化连接、重连、断开和底部状态的对比度。

SFTP：

- 双栏、表头、路径工具、排序、选中行、焦点行和滚动区层级收敛。
- 文件项补充列表/网格行语义、名称、大小、时间、类型和选中状态。
- 保留双击、右键、拖拽、多选、复制、移动、上传、下载和安全事务行为。
- 为截断文件名提供完整名称提示。
- 区分加载、空目录、权限不足、请求失败和断线状态的现有反馈。
- 禁用的一键备份补充可见或可访问原因，前提是现有状态已提供该信息。

AI 面板：

- 压缩未配置状态内部空白和重复提示。
- 保留面板宽度、显示条件、接管开关和全部行为。
- 强化 API 配置为未配置状态的主要动作。
- 统一模型不可用、未配置、检测中和可用状态。

### 5.3 第三批：服务器状态、安全中心和运维工具

服务器状态：

- 保留现有“异常”状态名称和检测结果。
- 使用已有结果补充严重度、影响和建议说明；不得增加扫描命令或检测逻辑。
- 强化摘要、资源、服务和需要关注区域的层级。
- 重复 AI 诊断入口降为次级视觉，不删除或合并。
- 优化嵌套滚动、标签选中态、扫描时间和只读安全说明。

安全中心：

- 保留顶部汇总和标签计数，只突出一组，另一组降为辅助信息。
- 提高空状态、筛选器、刷新、记录状态和旧版说明的可读性。
- 记录行补充标准列表/表格语义和可访问名称。
- 不改变回滚、历史、旧版数据或筛选行为。

运维工具：

- 保留 17 项命令、标签、顺序、搜索、筛选、编辑、预览、执行和回滚。
- 调整卡片列数、宽度、标题、说明、只读/需编辑标签和领域标签层级。
- 优化底部抽屉高度、滚动、关闭入口和多面板并存状态。
- 保证“只读”“需编辑”“默认预览”“确认执行”“可回滚”的安全信息不被弱化。
- 不修改任何命令模板、参数、风险判定或事务逻辑。

### 5.4 第四批：模型 API、帮助、更新、设置和文案

模型 API：

- 强化首次配置的三个基础字段，不改变字段或保存/测试逻辑。
- 降低推荐平台区域对基础配置的视觉干扰。
- 统一必填、可选、建议填写、密钥本地保存和拉取模型说明。
- 密钥显示、搜索、筛选、套用模板、官网链接和高级选项补充名称与状态。

帮助：

- 保持首次使用默认展开和全部章节顺序。
- 优化介绍、安全提示、章节标题、折叠状态和长内容滚动。
- 不新增搜索或目录跳转。

更新：

- 使用现有内容渲染标题、列表和段落，不直接显示 Markdown 标记。
- 强化当前版本、最新版本、更新状态、更新源和上次检查层级。
- 优化检查中、已是最新、失败、下载和重试状态的现有反馈。
- 不修改更新源选择、下载、校验或安装逻辑。

设置：

- 保留顶部标签、左侧分类、字段顺序和自动保存。
- 通过层级与选中态区分顶部标签、分类和页面分组。
- 左侧分类补充标准按钮、列表或树语义。
- 超时和 Keepalive 控件补充名称、单位、范围和当前值。
- 代理、字体、主题、开关、密码和重置控件补充关联与状态。
- 清理已确认的英文残留、不自然翻译、术语和空格不一致。

## 6. 文案规则

- 使用产品现有术语，不重命名功能入口。
- 状态文案保持现有名称，只补充解释，不改变状态含义。
- 更新日志显示为结构化内容，不修改发布说明原文含义。
- “先测试再连接”只通过说明和视觉层级解决，不禁用连接按钮。
- “保存为连接”增加本机持久化说明，不改变默认勾选。
- 中文界面不保留无必要英文句子；技术缩写、协议名和标准名除外。
- 统一中英文空格、标点、版本号、日期、时间和单位格式。

## 7. 数据流与错误处理

本次不新增数据流。所有状态仍来自现有 store、props、IPC 和服务结果。

错误处理原则：

- 不吞掉现有错误，不改变错误码或恢复动作。
- 仅改善错误信息的层级、关联、对比度和辅助技术通知。
- 动态通知只观察现有状态，不增加网络请求、计时器或后台任务。
- 若样式或语义增强无法从现有状态推导，则不实现该项。
- 弹窗焦点增强失败不得阻断关闭和原有操作；相关测试必须覆盖无触发元素和触发元素已卸载的降级场景。

## 8. 测试驱动策略

每批遵循红—绿—重构：

1. 为目标令牌、样式契约、ARIA、标签关联、焦点行为或文案增加失败测试。
2. 运行测试并确认因当前实现缺失而失败。
3. 进行最小、边界内的实现。
4. 运行针对性测试直至通过。
5. 运行受影响页面 E2E、全量单元测试、lint 和编译。
6. 保存相同状态截图并与 v0.4.26 基线比较。

测试不得通过弱化断言、跳过场景或删除现有覆盖来获得通过结果。

## 9. 三轮自检

### 9.1 第一轮：代码与组件自检

- 主题令牌、样式契约、ARIA、标签关联、焦点管理和文案测试。
- `npm run test-unit-ci`。

### 9.2 第二轮：用户交互与视觉自检

- 断开首页、新建连接三步、连接测试、SSH、SFTP完整重放。
- 服务器状态、安全中心、运维工具、模型 API、帮助、更新和设置检查。
- 浅色、深色、常用窗口尺寸和 100%/125%/150% 缩放。
- 使用相同状态和视口比较 v0.4.26 与 v0.4.27 截图。
- 纯键盘、弹窗隔离、焦点进入/循环/恢复、可访问树和至少一种 Windows 屏幕阅读器检查。
- 发现问题后修复并重放受影响的完整用户旅程。

### 9.3 第三轮：需求、外部环境与发布自检

- 使用授权 VPS 进行 SSH/SFTP 只读和隔离沙箱回归。
- 远端写入仅允许随机 `/tmp/.shellpilot-*`，结束后验证清理。
- 不修改、重启或重载 x-ui、sshd、防火墙、容器、数据库、Web 服务或业务目录。
- 复核 166 项需求矩阵无退化。
- 运行既有质量、性能、隧道、SFTP 和真实服务器门禁。
- 构建 Windows x64 目录包、安装器、blockmap、便携 ZIP 和更新元数据。
- 完成 EXE、安装器、ZIP、签名、校验和与资产清单验证。

## 11. 发布设计

目标版本为 v0.4.27，作为 v0.4.26 的补丁更新，不覆盖历史资产。

发布步骤：

1. 更新版本、发布说明、更新元数据和校验清单。
2. 生成并验证九项本地发布资产。
3. 运行 GitHub Release dry-run，确认目标为新建 v0.4.27。
4. 发布非 draft、非 prerelease GitHub Release。
5. 同步相同资产到 ModelScope。
6. 对两条更新源执行版本、资产名、大小、SHA256 和逐字节下载校验。
7. 从已发布 v0.4.26 客户端检查更新，确认识别 v0.4.27。
8. 记录发布 URL、资产数量、发布时间和双源校验结果。

发布失败时：

- 不删除或覆盖 v0.4.26 及更早历史版本。
- 若 GitHub 已发布而 ModelScope 失败，保持 v0.4.27 资产不变，修复同步后重新验证，不重建不同字节的同版本资产。
- 若在线字节与本地批准资产不一致，停止更新链路验收并修复源，不宣称发布完成。
