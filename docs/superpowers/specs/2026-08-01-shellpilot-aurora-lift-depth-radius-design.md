# ShellPilot Aurora Lift 强阴影与大圆角设计补充

- 日期：2026-08-01
- 状态：视觉与实施边界已获用户确认，等待书面规格复核
- 适用版本：ShellPilot 0.4.23 当前 UI 现代化分支
- 依赖规格：`2026-08-01-shellpilot-aurora-ui-modernization-design.md`
- 选定方向：B · Aurora Lift

## 1. 背景与目标

当前 Aurora 实现采用大模糊、低透明度阴影，实际呈现更接近柔和光晕；深色主题的黑色阴影又容易融入页面背景。卡片与主框最大圆角为 18px，仍未达到用户要求的年轻、圆润和明显立体感。

本补充规格将全工具的视觉深度升级为 **接触阴影 + 环境阴影 + 顶部高光**，同时提高卡片、面板、弹窗、工具栏和表单控件的圆角。用户在正常缩放下无需仔细观察，即可辨认容器与页面背景之间的高度差。

## 2. 不可突破的 UI-only 边界

本次只允许修改主题令牌和样式文件，包括颜色、圆角、边框、阴影、纯视觉间距和避免裁切所需的样式属性。

不得修改：

- JSX/TS/JS 业务组件、路由、入口顺序或信息顺序。
- 点击、键盘、拖放、滚动、菜单、弹窗、表单、终端、SFTP 或 AI 行为。
- store、状态机、API、IPC、持久化、数据结构、权限和安全门。
- 现有功能文案、功能可见性、条件渲染和快捷键。
- 任何为追求视觉效果而新增的页面、功能或交互动画。

若某个视觉调整必须改变组件结构或事件行为才能完成，则停止该项，不以功能改动换取视觉一致性。

## 3. 选定视觉系统

### 3.1 圆角层级

| 语义令牌 | 数值 | 使用范围 |
| --- | ---: | --- |
| `--sp-radius-small` | 10px | 小装饰、小标签、紧凑型内部元素 |
| `--sp-radius-control` | 14px | 输入框、下拉框、按钮、页签、搜索框 |
| `--sp-radius-toolbar` | 18px | 工具栏、筛选条、列表头、组合控件容器 |
| `--sp-radius-card` | 22px | 内容卡片、信息卡、分组卡片、预览卡片 |
| `--sp-radius-panel` | 28px | 主工作区、侧栏主体、大型内容框 |
| `--sp-radius-overlay` | 28px | 弹窗、菜单、抽屉、浮层、传输面板 |

约束：

- 同一容器内，子元素圆角必须小于父容器圆角。
- 圆形头像、状态点、药丸标签继续使用 `50%` 或 `999px`，不替换为上述令牌。
- 与窗口边缘或分栏边缘相接的容器只放大可见外角，贴边角继续保持 0。
- 表格行、日志行、文件行不转换为独立圆角卡片。

### 3.2 浅色主题阴影

```css
--sp-shadow-sm:
  0 3px 0 -1px rgba(62, 58, 160, 0.16),
  0 8px 18px rgba(62, 58, 160, 0.18);

--sp-shadow-md:
  0 6px 0 -2px rgba(73, 66, 196, 0.18),
  0 18px 34px rgba(73, 66, 196, 0.26);

--sp-shadow-lg:
  0 9px 0 -3px rgba(75, 66, 202, 0.20),
  0 28px 56px rgba(75, 66, 202, 0.32);

--sp-shadow-focus:
  0 4px 0 -1px rgba(77, 70, 245, 0.22),
  0 16px 30px rgba(77, 70, 245, 0.36);
```

浅色表面继续使用 1px 顶部内高光，主容器边框保持可见。接触阴影负责明确“离地高度”，环境阴影负责柔化边缘，两者必须同时存在。

### 3.3 深色主题阴影

```css
--sp-shadow-sm:
  0 3px 0 -1px rgba(0, 0, 0, 0.52),
  0 10px 20px rgba(0, 0, 0, 0.56),
  0 0 0 1px rgba(138, 130, 255, 0.18);

--sp-shadow-md:
  0 6px 0 -2px rgba(0, 0, 0, 0.58),
  0 20px 38px rgba(0, 0, 0, 0.64),
  0 0 0 1px rgba(138, 130, 255, 0.22);

--sp-shadow-lg:
  0 10px 0 -3px rgba(0, 0, 0, 0.64),
  0 30px 60px rgba(0, 0, 0, 0.72),
  0 0 0 1px rgba(138, 130, 255, 0.28);

--sp-shadow-focus:
  0 4px 0 -1px rgba(0, 0, 0, 0.50),
  0 16px 32px rgba(116, 109, 255, 0.42),
  0 0 0 2px rgba(138, 130, 255, 0.30);
```

深色主题通过黑色接触阴影制造落差，通过细紫色轮廓与背景分离。不得只提高模糊半径，也不得把所有容器改成发光效果。

### 3.4 层级映射

| 层级 | 阴影 | 对象 |
| --- | --- | --- |
| L0 | 无 | 页面底层、终端字符画布、表格/日志/文件行 |
| L1 | `shadow-sm` | 输入框、按钮、紧凑控件、未展开的轻量工具条 |
| L2 | `shadow-md` | 卡片、工具栏、设置分组、选中对象 |
| L3 | `shadow-lg` | 主工作区、侧栏、抽屉、弹窗、打开的浮层 |
| Focus | `shadow-focus` | 键盘焦点、主操作和明确选中态 |

已有 `shadowControl`、`shadowCard`、`shadowOverlay` 兼容别名继续分别映射至 `sm`、`md`、`lg`，不改变调用方式。

## 4. 页面覆盖

以下页面和浮层均使用同一圆角与阴影体系：

1. 连接工作台与最近连接。
2. Fleet 状态总览、筛选工具栏、状态表格外框和服务选择抽屉。
3. AI 产物列表、预览区与相关工具栏。
4. 服务器、历史和右侧详情面板。
5. 终端标签栏、会话工具栏和终端主容器外框；终端字符画布保持 L0。
6. SFTP 双栏主框、路径栏和传输浮层；文件行保持 L0。
7. 密码管理、日志、设置导航、设置分组和主题卡片。
8. 运维工具工作区、推荐流程、工具分组和历史外框；内部历史行保持 L0。
9. AI 助手输入区、对话外框和历史面板。
10. 事件归档、SSH 隧道、服务器状态、安全提示和通用弹窗。
11. 系统菜单、右键菜单、抽屉、上下文浮层和其他通用框体。

硬编码为 4–14px 的圆角需逐项分类：属于框体或控件的替换为相应令牌；属于状态点、进度条、滚动条、窗口拼接边、终端内部标记或功能性几何形状的保持原值。

## 5. 交互与布局规则

- 不新增 `transform` 位移动画；Hover 仅改变颜色、边框和阴影层级。
- 不改变控件宽高、点击区域、焦点顺序和键盘导航。
- 不因圆角增大而扩大内容间距，除非现有内容会与弧形边界发生视觉裁切；此类补偿只允许使用样式内边距。
- 含 `overflow: hidden` 的框体必须检查阴影是否由父级裁切。优先调整现有父级样式的溢出或留白，不增加包装节点。
- 分栏贴边容器保持贴边侧直角，避免出现透底缝隙。
- 终端、SFTP、日志和表格继续优先保障信息密度，不对每一行单独加阴影。
- 动效时长继续使用现有 120–180ms 令牌，并尊重减少动态效果设置。

## 6. 实现结构

1. 在 `src/client/common/ui-theme-tokens.js` 中更新圆角和浅/深色阴影令牌。
2. 通过现有 CSS 变量让已令牌化页面自动升级。
3. 审计 Aurora 覆盖的 Stylus 文件，将卡片、框体、工具栏、弹窗和表单控件的旧硬编码圆角替换为语义令牌。
4. 只在视觉层级缺失或阴影会被裁切时增加局部样式覆盖。
5. 不编辑 JSX/TS、路由、数据和业务文件。

本次没有新的数据流、错误状态、加载状态或业务异常处理。需要处理的风险均为视觉风险：阴影裁切、圆角遮挡、边框错位、深色模式分层不足和密集页面过度卡片化。

## 7. 测试与视觉验收

### 7.1 测试驱动顺序

1. 先修改主题令牌测试，要求精确的新圆角值及多层阴影结构。
2. 运行测试并确认因旧值和旧阴影结构而失败。
3. 更新主题令牌，运行测试直至通过。
4. 先增加关键页面的样式契约断言，再替换对应硬编码圆角和阴影。
5. 运行 Stylus 编译、相关单测、全量单测和 lint。

### 7.2 视觉验收矩阵

- 每个一级页面至少生成一张新截图。
- 设置、终端、SFTP 和 AI 助手至少同时检查浅色与深色主题。
- 使用相同视口与相同页面状态，将旧定稿截图和新截图并排比较。
- 检查主面板、卡片、工具栏和控件的圆角层级是否清晰。
- 检查 L3 阴影是否在正常缩放下明显强于当前版本。
- 检查深色主题阴影是否可见但不形成大面积紫色发光。
- 检查表格行、日志行、文件行和终端字符画布仍保持平直。
- 检查所有弹窗、菜单和侧栏无阴影裁切、内容裁切和透底缝隙。

视觉验收只有在所有 P0、P1、P2 问题修复后才通过；P3 仅记录为后续微调。最终交付需包含逐页新预览图和 UI-only 差异审计。

## 8. 完成标准

- 正常缩放下一眼可见明确的立体落差，不再是柔和光晕。
- 所有卡片、框体、工具栏、输入框、下拉框和按钮按语义使用更大圆角。
- 浅色与深色主题均保持层级、可读性和专业工具感。
- 每个页面均完成截图复核，无裁切、重叠、溢出和边缘错位。
- 生产代码差异仅包含主题令牌与样式文件，不包含功能文件。
- 编译、lint、相关单测和全量回归通过；已知依赖外部凭据或旧测试基线的问题需单独说明，不得混同为本次 UI 回归。
