# ShellPilot 极简 Skill 创建与 AI 任务中断设计

## 目标

本轮改造解决两个直接影响可用性的问题：

1. Skill 创建流程改为接近 Codex 的自然语言对话体验。
2. 普通 AI 对话和 Agent 任务运行后始终可以可靠停止。

改造保持现有 Skill 安全校验、SSH/SFTP 核心、Agent 工具网关和安全操作中心的数据兼容，不重写终端底座。

## 一、极简 Skill 创建

### 用户流程

1. 用户输入一句自然语言需求。
2. AI 生成禁用状态的 Skill 草稿。
3. 后台完成结构校验、权限检查和一次自动修复。
4. 主界面展示名称、用途、触发方式、能力摘要和安全状态。
5. 用户可以继续对话修改草稿。
6. 用户选择“保存草稿”或“保存并启用”。

默认界面不展示文件摘要、Digest、原始校验码和权限数组。上述内容保留在折叠的“详细信息”中，供高级用户审查。

### 界面结构

- 对话区：显示用户需求和 AI 的修改摘要。
- 输入区：继续用自然语言调整草稿。
- 结果卡：名称、用途、触发条件、能力和安全检查结果。
- 主操作：`保存草稿`、`保存并启用`。
- 次要操作：`详细信息`、`重新生成`。

### 生成与修复

- 模型必须生成受控 `SKILL.md` 和必要的附属文件。
- 本地校验器仍是最终权威，不接受模型自行声明“校验通过”。
- 首次校验失败后，控制器将经过脱敏的错误明细交给模型自动修正一次。
- 第二次仍失败时保留原草稿，显示中文可操作说明和“重新生成”按钮。
- 含脚本、高权限或高风险行为的 Skill 必须在启用前显示风险确认。

### 兼容策略

- 已有草稿、已启用 Skill、版本历史和回滚记录不迁移、不重写。
- 高级编辑器继续存在，仅从默认主流程移入“详细信息”。
- 仓库、校验器和启用时的 Digest 校验保持不变。

## 二、统一停止 AI 与 Agent

### 交互

- 任务运行时，输入框右侧的发送按钮固定切换为红色停止按钮。
- 停止入口不依附于某一条折叠的聊天记录。
- 点击后立即进入“正在停止”，防止重复点击。
- 结束后保留已生成文本、已完成步骤和工具输出，并显示“已由用户停止”。
- 用户可以继续对话或重新执行，不需要清空上下文。

### 停止范围

普通 AI 对话：

- 取消当前模型 HTTP 请求。
- 停止流式会话和轮询。
- 保留已经接收的内容。

Agent 任务：

- 取消模型请求和 Agent 循环。
- 取消等待、重试、确认弹窗、MCP、CLI 和尚未开始的工具步骤。
- 阻止后续计划步骤继续调度。
- 如果当前 SSH 命令由该 Agent 任务启动，则发送一次 `Ctrl+C`。
- 不向用户手动启动的命令发送中断信号，不断开 SSH 会话。

### 运行所有权

每次 AI 或 Agent 执行建立统一运行记录：

- `runId`
- `chatId`
- `mode`
- `status`
- `requestId`
- `streamSessionId`
- `agentTaskId`
- `terminalOperationId`
- `terminalOwnedByAgent`
- `cancelRequestedAt`

只有 `terminalOwnedByAgent` 为真且操作仍在运行时，停止流程才能发送 `Ctrl+C`。终端所有权由现有 Agent 工具网关在提交命令时登记，在命令结束、超时或断线后释放。

### 状态机

合法状态如下：

`idle -> running -> stopping -> cancelled`

正常完成为：

`running -> completed`

失败为：

`running -> failed`

停止请求具有幂等性。重复点击、窗口重绘或历史记录重新挂载不能重复发送 `Ctrl+C`，也不能把已完成任务重新标记为取消。

### 安全中心同步

- 停止请求立即写入任务记录。
- 工具和终端真正收口后，任务从“执行中”变为“已取消”。
- 已产生修改的步骤仍保留备份和回滚入口。
- “取消”不等于“回滚”，界面需要明确区分。
- 任务锁在最终状态落库后释放，允许立即开始下一项任务。

## 三、错误处理

- 网络层无法取消时，前端仍停止继续展示，并记录“远端请求可能仍在结束中”。
- `Ctrl+C` 发送失败时不关闭 SSH，记录失败原因并释放 Agent 调度锁。
- SSH 已断开时直接结束 Agent，状态记为“连接中断”。
- 模型流、Agent 和安全中心对同一 `runId` 记录日志，方便关联排查。
- 用户界面不显示本地绝对路径、原始堆栈或 API Key。

## 四、组件边界

- `SkillCreatorConversation`：极简对话和结果卡。
- `SkillCreatorDetails`：按需加载文件、权限、风险和校验信息。
- `AIExecutionController`：统一登记、查询和取消当前运行。
- `AIComposerStopButton`：固定停止入口和状态反馈。
- `AgentTerminalOwnership`：登记 Agent 启动的终端操作并提供幂等中断。
- 现有 Skill repository、validator、Agent gateway 和 transaction runner 继续作为底层能力。

## 五、测试与验收

### 自动测试

- Skill 一句话生成、自动修复、继续对话修改、保存草稿和启用。
- 普通 AI 流在首字前、流式中途和完成边界取消。
- Agent 在计划、确认、MCP、CLI、SSH 命令和等待阶段取消。
- 仅 Agent 自有命令收到一次 `Ctrl+C`。
- 用户手动终端命令不受影响。
- 安全中心最终状态和任务锁正确收口。
- 重复取消、组件卸载重挂和断线场景保持幂等。

### 界面回归

- 1366x768、1920x1080。
- Windows 100%、125%、150% 缩放。
- 日间和夜间主题。
- 中文输入法、长文本和窄 AI 侧栏。

### 完成标准

- 普通用户创建 Skill 时无需理解文件结构或校验器术语。
- 任意 AI/Agent 运行阶段都能从固定入口停止。
- 停止 Agent 不会中断用户手动终端任务或断开 SSH。
- 停止后 2 秒内界面进入终态；远程命令收口允许按现有超时策略异步完成。
- 所有新增测试、完整 Skill 测试、AI/Agent 回归和生产构建通过。

## 非目标

- 不允许模型绕过 Skill 校验或自动启用高风险 Skill。
- 不对所有历史聊天记录进行数据迁移。
- 不重写 SSH 终端、SFTP 或安全事务底座。
- 不将“停止任务”自动解释为“回滚修改”。
