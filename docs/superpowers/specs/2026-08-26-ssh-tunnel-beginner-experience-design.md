# ShellPilot SSH 隧道完整检测与新手使用体验设计

## 背景

现有 SSH 隧道管理器已经支持本地转发、远程转发和 SOCKS5 动态代理，但“运行状态”“连通性检测”和“怎么使用”之间没有形成完整闭环。

当前本地转发在本机监听端口建立后就进入运行状态。用户点击“测试”时，探测器只要连接上本机监听端口便返回成功；真正的 SSH `forwardOut` 和远端目标连接发生在随后阶段。因此服务器拒绝端口转发时，界面可能同时显示：

- `SSH_TUNNEL_FORWARDING_PROHIBITED`；
- “最近测试正常 · 1 ms”。

这两个结果分别描述了不同层级，但界面把本机监听成功错误地表达成整条隧道正常。另一方面，用户成功启动隧道后看不到明确的访问地址、数据库客户端参数或浏览器代理设置方法，新手很难完成最后一步。

本设计在不改写 SSH 协议实现、不自动修改服务器配置的前提下，补齐分层检测、准确状态、上下文使用说明和完整新手教程。

## 已确认的产品决策

1. 采用“运行卡片即时说明 + 完整帮助页”的分层方案。
2. 检测到 SSH 服务端策略禁止时，只显示诊断和可复制命令，不自动修改 `sshd_config`，不索取或代填 sudo 密码。
3. 覆盖本地转发、远程转发、SOCKS5，以及 HTTP、HTTPS、MySQL、PostgreSQL、Redis 常用模板。
4. 只有 SOCKS5 需要浏览器或应用配置代理。本地转发直接访问本机监听地址；远程转发从服务器侧或获准访问服务器监听端口的设备使用。
5. 不修改 Windows 全局代理。SOCKS5 仅提供 Firefox、Chrome/Edge 和通用应用的设置说明及可复制参数。
6. 无法自动证明的链路必须显示“未验证”或“等待实际流量”，不能显示整体正常。

## 目标

- 用户不用理解 SSH 专业术语也能在三种隧道类型中做出正确选择。
- 启动后的运行卡片直接回答“能不能用、从哪里访问、失败后怎么办”。
- 本地转发只有在本机监听、SSH 转发和目标连接均取得证据后才显示“可用”。
- SOCKS5 和远程转发如实区分“监听就绪”与“实际业务流量已验证”。
- 错误提示定位到具体检测层，并提供安全、可复制、不会自动执行的排查步骤。
- 旧书签与旧隧道定义无需迁移即可继续运行。

## 非目标

- 不自动编辑 `/etc/ssh/sshd_config`、`sshd_config.d` 或 `authorized_keys`。
- 不自动执行 sudo、远端 Shell、服务重载或防火墙修改。
- 不自动修改 Windows、浏览器或其他应用的全局代理设置。
- 不承诺一次 SOCKS5 探测能够证明所有网站均可访问。
- 不为远程转发自动开放 `GatewayPorts` 或防火墙。
- 不增加流量统计、限速、代理认证、PAC 文件或隧道共享。
- 不改变 SSH、SFTP、跳板机、终端输入和认证流程。

## 术语与界面语言

面向新手的主界面优先使用动作语言：

- “访问服务器上的网页或数据库”对应本地转发；
- “让浏览器流量经过服务器”对应 SOCKS5；
- “让服务器访问我电脑上的服务”对应远程转发。

“本地转发”“动态代理”“远程转发”等专业名称保留为副标题。界面必须解释 `127.0.0.1` 属于哪台机器，不能只显示“本地”和“远程”两个容易混淆的词。

## 用户体验

### 类型选择

现有三张类型卡片继续保留，并增加场景标题：

| 用户目标 | 类型 | 默认安全边界 |
| --- | --- | --- |
| 在本机访问服务器上的网页、数据库或内网服务 | 本地转发 | 本机只监听 `127.0.0.1` |
| 让浏览器或应用流量经过 SSH 服务器 | SOCKS5 动态代理 | 本机只监听 `127.0.0.1` |
| 让 SSH 服务器访问本机服务 | 远程转发 | 服务器只监听 `127.0.0.1` |

编辑区顶部增加“第一次使用？查看完整说明”入口。入口打开独立的新手帮助组件，不继续扩张现有表单组件。

### 启动后的运行卡片

运行卡片按以下顺序呈现：

1. 名称、隧道类型和准确的总体可用性；
2. 数据流向；
3. “现在这样使用”区域；
4. 分层检测结果；
5. 错误原因和修复入口；
6. 重新检测、复制、打开、完整说明、编辑和停止操作。

[在浏览器中打开] [复制地址]

### 使用说明生成

新增纯函数使用说明生成器，根据隧道类型、用途配置和规范化地址生成结构化结果，界面不自行拼接文案。

新建隧道选择模板时保存可选的 `usageProfile`：

- `http`
- `https`
- `mysql`
- `postgresql`
- `redis`
- `socks5`
- `generic`

`usageProfile` 只影响使用提示，不影响 SSH 转发行为。旧配置没有该字段时按以下规则保守处理：

- 动态转发固定识别为 SOCKS5；
- 本地转发名称与已知模板名称完全一致时可以推断对应用途；
- 其他配置显示通用 TCP 主机与端口，不猜测 HTTP/HTTPS，不显示“浏览器打开”。

本机监听地址为 `0.0.0.0` 或 `*` 时，访问地址转换为 `127.0.0.1`；监听地址为 `::` 或 `[::]` 时转换为 `[::1]`。只有 `http` 和 `https` 用途提供浏览器打开按钮，URL 由受控协议与规范化主机、端口生成，不能接受任意协议字符串。

各用途的即时说明：

| 用途 | 运行卡片显示 |
| --- | --- |
| HTTP | `http://<本机访问主机>:<本机端口>`、复制、浏览器打开、无需代理 |
| HTTPS | `https://<本机访问主机>:<本机端口>`、复制、浏览器打开、自签名证书说明 |
| MySQL | 客户端主机、本机端口、数据库用户名密码仍使用目标数据库凭据 |
| PostgreSQL | 客户端主机、本机端口、数据库名与认证说明 |
| Redis | 主机、本机端口、Redis 密码或 ACL 仍由目标服务提供 |
| SOCKS5 | `SOCKS5 <本机访问主机>:<本机端口>`、复制、浏览器设置入口、需要代理 |
| 远程转发 | 服务器监听地址与端口、访问范围、`GatewayPorts` 和防火墙边界 |
| 通用 TCP | 本机或服务器侧主机与端口，不猜测应用协议 |

浏览器打开必须由用户主动点击，检测通过也不能自动打开浏览器。

## 分层检测设计

### 状态模型

控制器生命周期与连通性结论分开保存：

- 生命周期继续表达 `starting`、`healthy`、`reconnecting`、`failed` 等运行时状态，保持内部兼容；
- `lastTest` 表达最近一次分层检测证据；
- UI 总体标签综合两者，不再把控制器已经监听等同于业务链路可用。

`lastTest` 使用以下结构：

```js
{
  verdict: 'passed' | 'limited' | 'failed' | 'unverified',
  summary: 'SSH 服务器禁止端口转发',
  checkedAt: 1787731200000,
  latencyMs: 24,
  stages: [
    {
      id: 'local-listener',
      status: 'passed',
      code: 'SSH_TUNNEL_LOCAL_LISTENER_READY',
      message: '本机监听正常',
      latencyMs: 1
    },
    {
      id: 'ssh-forwarding',
      status: 'limited',
      code: 'SSH_TUNNEL_FORWARDING_PROHIBITED',
      message: 'SSH 服务器禁止端口转发'
    },
    {
      id: 'target-service',
      status: 'unverified',
      code: 'SSH_TUNNEL_STAGE_NOT_REACHED',
      message: 'SSH 转发失败，尚未检测目标服务'
    }
  ]
}
```

阶段状态含义：

- `passed`：已经取得实际成功证据；
- `limited`：被服务器、权限或安全策略明确限制；
- `failed`：连接、协议或目标服务实际失败；
- `unverified`：当前检测无法自动证明，或前一阶段失败导致未执行。

只有该隧道类型规定的关键阶段全部 `passed` 时，总体结论才能是 `passed`。存在策略限制时为 `limited`，存在实际故障时为 `failed`，缺少必要证据时为 `unverified`。

### 本地转发

本地转发包含三个必要阶段：

1. 本机监听：确认当前控制器正在目标地址和端口监听；
2. SSH 转发：通过当前 SSH 连接发起与真实流量相同的 `forwardOut`；
3. 目标服务：只有 `forwardOut` 返回远端流后才通过，随后立即安全关闭探测流。

探测不能在本机 `net.connect` 的 `connect` 事件触发时返回成功。控制器提供受限的 `probe()` 能力，分别检查自身监听状态和 SSH 目标通道；运行时只消费结构化结果，不依赖下一条不相关的用户连接事件。

本地监听成功、SSH 策略禁止时，总体为 `limited`。SSH 通道建立但目标拒绝时，总体为 `failed`。这两种情况均不能保留旧的绿色测试结果。

### SOCKS5 动态代理

自动检测包含：

1. 本机监听；
2. SOCKS5 无认证协商是否得到正确响应；
3. 最近实际代理请求是否已经通过 SSH 获得远端流。

启动后尚无实际代理请求时，第三阶段为 `unverified`，总体显示“代理已就绪，等待实际网站流量验证”，不能承诺所有网站可访问。第一次成功的真实 SOCKS5 请求会记录不包含目标域名、URL或用户数据的成功证据；策略禁止、目标拒绝或网络错误会更新对应阶段。

“重新检测”只验证本机 SOCKS5 协议响应和当前已有证据，不默认连接公共网站，也不泄露用户拟访问的目标。

### 远程转发

远程转发包含：

1. SSH 服务器是否接受 `forwardIn` 远程监听；
2. 本机目标服务是否可连接；
3. 是否观察到一次真实的服务器侧进入连接并成功接到本机目标。

前两个阶段通过、但尚无实际进入连接时，总体显示“远程监听已就绪，等待远端访问验证”。只有观察到真实流量后才显示完整链路通过。

服务器监听在 `127.0.0.1` 时说明只能从服务器本机访问。监听在非回环地址时仍需 `GatewayPorts`、防火墙和服务认证共同允许；客户端不能仅凭 `forwardIn` 成功宣称外部设备一定可访问。

### 自动检测与结果失效

- 手动启动后异步进行检测，不阻塞 SSH 终端就绪；卡片显示“检测中”。
- 自动启动的隧道同样异步检测，单条失败不影响 SSH 会话和其他隧道。
- 用户点击“重新检测”时等待当前检测完成；同一隧道不能并发启动多次探测。
- 控制器出现新错误、SSH 重连、隧道重启或重新建立控制器时，旧 `passed` 结果立即失效。
- 重连成功后自动重新检测，不能直接恢复旧的绿色状态。
- 每个阶段设置明确超时；超时属于 `failed`，并显示发生层级。
- `lastTest` 只保存在当前会话，不写入书签。

## 错误诊断与可复制指导

诊断内容使用结构化目录，根据错误码返回标题、简短原因、检查步骤、安全命令和帮助章节标识。命令仅复制到剪贴板，永不自动发送到终端。

### 服务端禁止转发

覆盖：

- `AllowTcpForwarding`；
- `PermitOpen`；
- `DisableForwarding`；
- `Match User`、`Match Address` 等条件配置；
- `authorized_keys` 中的 `restrict`、`no-port-forwarding` 和 `permitopen=`；
- 堡垒机或安全设备策略。

帮助页先提供只读检查，再给最小授权示例。配置示例优先使用：

```sshconfig
Match User hik
    AllowTcpForwarding local
    PermitOpen 127.0.0.1:6060
```

示例明确说明用户名、目标地址和端口必须按实际情况替换；`DisableForwarding yes` 或密钥级限制仍可能覆盖授权。软件不提供“一键应用”。

### 目标拒绝连接

说明目标地址从 SSH 服务器视角解释。本地转发填写 `127.0.0.1:6060` 表示服务必须监听在 SSH 服务器自己的回环地址和 6060 端口。提供服务监听、容器端口映射和防火墙的只读检查顺序。

### 本机端口占用

保留现有可用端口建议，并说明更换的是本机监听端口，不是远端服务端口。Windows 检查命令和建议端口可以复制，不自动停止占用端口的程序。

### HTTPS 证书警告

说明 SSH 隧道只提供 TCP 加密转发，不替换目标网站证书。访问 `https://127.0.0.1:<端口>` 时，证书域名不匹配或自签名警告不等同于 SSH 隧道失败。软件不自动忽略证书错误。

### SOCKS5 使用问题

分别说明：

- 浏览器未配置代理时不会经过 SSH；
- Firefox 手动 SOCKS5 与“代理 DNS”选项；
- Chrome/Edge 使用独立启动参数或受信任代理扩展的方式；
- 通用应用应填写 SOCKS5 主机和端口；
- 软件不会修改 Windows 全局代理。

## 完整新手帮助页

新增独立帮助组件，支持从类型、用途和错误码深链到对应章节。页面顺序固定为：

1. 三秒选择正确类型；
2. 认识数据流和两端 `127.0.0.1`；
3. 本地转发逐字段示例；
4. 启动后如何访问 HTTP、HTTPS 和数据库；
5. SOCKS5 浏览器与应用设置；
6. 远程转发访问范围和安全边界；
7. 常见错误与只读排查命令；
8. 术语小字典与安全清单。

帮助页使用真实示例，不使用只有专业人员才能理解的抽象描述。每个示例都包含“适用场景、字段填写、数据流、启动后的访问方式、成功表现、失败时先检查什么”。

`apps/electerm-agent/docs/USER_GUIDE_ZH.md` 同步扩展为可离线阅读的完整章节，内容与界内帮助保持同一结构。界内说明偏操作，离线手册补充服务器管理员检查和安全背景。

## 组件与职责

建议边界如下：

- `src/app/server/ssh-tunnel.js`：控制器、真实 SSH 转发和控制器级探测能力；
- `src/app/server/ssh-tunnel-probe.js`：阶段、总体结论、超时和结构化探测结果；
- `src/app/server/ssh-tunnel-runtime.js`：生命周期、自动探测、结果失效、串行化；
- `src/client/components/ssh-tunnel/ssh-tunnel-usage.js`：用途识别、访问地址、客户端参数和说明模型；
- `src/client/components/ssh-tunnel/ssh-tunnel-diagnostics.js`：错误码到新手诊断、复制命令和帮助章节的映射；
- `src/client/components/ssh-tunnel/ssh-tunnel-guide-modal.jsx`：完整新手帮助页；
- `src/client/components/ssh-tunnel/ssh-tunnel-runtime-card.jsx`：运行卡片、访问操作和分层状态；
- `src/client/components/ssh-tunnel/ssh-tunnel-modal.jsx`：编辑、保存、列表和对话框编排，不继续承担说明生成和卡片细节；
- `docs/USER_GUIDE_ZH.md`：离线完整说明。

结构化模型由纯函数生成，便于单元测试。UI 只负责翻译键、渲染和调用既有复制/安全外链能力。

## 兼容性与降级

- `usageProfile` 为可选字段，旧书签不需要迁移。
- 稳定隧道 ID 继续由原有关键连接字段生成，新增用途字段不改变旧 ID。
- 旧服务端运行时若没有分层结果，UI 显示“运行中，未进行完整检测”，不能回退为“可用”。
- 完整帮助组件按需加载失败时使用现有错误边界并提供重试。
- 浏览器打开能力不可用时仍可复制地址。
- 单个探测或帮助模块失败不能关闭隧道、SSH 会话或终端。

## 测试策略

### 单元测试

- 本地监听成功但 `forwardOut` 尚未回调时，探测不得提前成功。
- `forwardOut` 返回策略禁止时，SSH 阶段为 `limited`、目标阶段为 `unverified`，总体不能为 `passed`。
- 目标拒绝、超时、SSH 断开和端口冲突映射到正确阶段及错误码。
- 旧的 `passed` 结果在控制器错误、重启和重连时失效。
- SOCKS5 协议握手通过但无实际代理流量时总体为 `unverified`。
- 远程监听和本机目标通过但无进入流量时总体为 `unverified`。
- HTTP、HTTPS、MySQL、PostgreSQL、Redis、SOCKS5、远程转发和通用 TCP 生成正确说明。
- 通配监听地址转换为安全的本机访问地址；IPv6 URL 使用方括号。
- 非网页用途和未知旧配置不生成浏览器打开动作。
- 诊断命令不包含密码、私钥、令牌或自动执行标记。

### 界面测试

- 运行卡片按总体结论显示“检测中、可用、受限、不可用、未验证”。
- 截图场景不能同时显示策略禁止和绿色整体正常。
- 网页模板显示复制与打开；数据库模板显示客户端参数；SOCKS5 显示代理设置入口。
- 新错误出现后旧绿色结果立即消失。
- 当前错误可以直达帮助页对应章节。
- 1366×768、1920×1080、Windows 125%/150% 缩放、日间和夜间主题均可操作。
- 所有新按钮具备可读名称、键盘焦点和足够的状态对比度。

### 真实服务器验收

- 允许转发的服务器上验证本地 HTTP/HTTPS 或 TCP 目标的完整链路。
- 真实关闭目标端口时验证 `SSH_TUNNEL_DESTINATION_REFUSED`。
- 专用或获准修改策略的环境中验证 `SSH_TUNNEL_FORWARDING_PROHIBITED`；不能为制造错误修改共享服务器策略。
- 验证远程转发监听、本机目标和一次真实进入连接。
- 验证 SOCKS5 握手及一次获准的真实代理连接，不记录目标内容。
- SSH 断开后监听和探测资源全部释放。

## 验收标准

1. 本地转发只有取得本机监听、SSH 通道和目标服务三层成功证据后才显示“可用”。
2. 服务器禁止转发时显示失败层级、准确错误码、只读检查命令和完整说明入口，不保留绿色测试结果。
3. 目标服务拒绝、端口占用、超时、SSH 断开和 HTTPS 证书警告均有互不混淆的新手说明。
4. HTTP/HTTPS 隧道启动后可以复制或主动打开正确本机 URL，并明确“不需要浏览器代理”。
5. MySQL、PostgreSQL 和 Redis 显示可直接填入客户端的主机与端口。
6. SOCKS5 明确要求应用配置代理，提供浏览器教程，并且不修改 Windows 全局代理。
7. 远程转发准确说明服务器本机、其他设备访问、`GatewayPorts` 和防火墙之间的边界。
8. 无法自动证明的 SOCKS5 或远程转发链路显示“未验证”或“等待实际流量”，不显示假正常。
9. 界内帮助和中文离线手册覆盖选择、填写、访问、代理、排错、安全和术语。
10. 旧书签可继续启动，SSH、SFTP、终端和其他隧道不受单条探测失败影响。
